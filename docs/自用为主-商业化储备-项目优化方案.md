## 一、定位分析与优先级原则

### 自用为主 vs 商业化的区别

| 维度 | 自用为主（现在） | 商业化（未来） |
|------|:---:|:---:|
| 用户数 | 1人 | 多人 |
| 认证 | API Key 即可 | Keycloak OAuth2 |
| 多语言 | 中文足够 | 英文必备 |
| 协作 | 不需要 | 核心卖点 |
| 成本控制 | 重要（自己掏钱） | 重要（用户付费） |
| 数据安全 | 局域网即可 | 必须防护 |
| 运维监控 | 看日志就行 | Grafana 看板 |
| 导出 | 自己用就行 | 用户要全格式 |

### 优先级原则

1. **先让自己用爽**：安全、稳定、成本可控、导出方便
2. **打好地基**：配置体系、数据库迁移、可观测性
3. **暂缓平台化**：多用户、协作、国际化、插件市场

## 二、已实施的优化（本次）

### 1. 配置体系强化

**文件**：`.env`、`.env.example`、`kunlun/config.py`

| 新增配置项 | 用途 | 自用价值 |
|-----------|------|----------|
| `OPENAI_API_KEYS_BACKUP` | 备用Key逗号分隔，自动轮换 | 一个Key限流了自动切另一个 |
| `LLM_MAX_TOKENS_PER_REQUEST` | 单次生成最大Token | 防止单次生成费用暴增 |
| `LLM_MAX_CALLS_PER_HOUR` | 每小时最大调用次数 | 防止脚本bug导致疯狂调用 |
| `LLM_DAILY_TOKEN_BUDGET` | 每日Token预算上限 | 日消费预算控制 |
| `RATE_LIMIT_PER_MINUTE` | 全局速率限制 | 防止误操作 |
| `RATE_LIMIT_GENERATE_PER_MINUTE` | 生成接口限制 | 防止并发过多 |
| `RATE_LIMIT_EXPORT_PER_MINUTE` | 导出接口限制 | 防止频繁导出 |
| `OTEL_ENABLED` | OpenTelemetry开关 | 商业化时一键启用 |
| `APP_HOST` 默认改为 `127.0.0.1` | 默认仅本地访问 | 安全性 |

**新增辅助方法**：
- `settings.get_all_api_keys()` — 获取主Key + 备用Key列表
- `settings.is_production()` / `is_development()` — 环境判断

### 2. API 安全加固

**文件**：`kunlun/api/main.py`、`requirements.txt`

- **slowapi 集成**：全局速率限制 + 429 友好错误提示
- **默认 APP_HOST=127.0.0.1**：防止局域网未授权访问
- **白名单路径**：`/health`、`/docs`、`/metrics` 等免认证
- **速率限制分层**：全局限制 + 生成接口独立限制

### 3. 前端导出功能完整化

**文件**：`frontend/src/views/ExportView.vue`

- **从 3 种格式扩展到 7 种**：TXT / HTML / Markdown / EPUB / MOBI / PDF / DOCX
- **新增投稿包功能**：一键生成 ZIP（正文 + 大纲 + 角色 + 快照）
- **新增选项**：HTML 排版风格（紧凑/标准/宽松）、全书导出范围（全部/仅已发布）
- **格式依赖提示**：EPUB/MOBI/PDF/DOCX 显示需要可选依赖的警告
- **结果弹窗**：导出完成后显示格式/字数/路径

### 4. 前端占位组件改造

**文件**：`frontend/src/components/AuditReport.vue`、`ChapterEditor.vue`、`KGBrowser.vue`、`OutlinePanel.vue`

- **之前**：4个占位组件仅显示"已迁移至 XX 页面"
- **现在**：改为 4 组快捷导航面板，每个面板包含 4 个快捷入口
  - **写作快捷操作**：创作中心、大纲管理、角色设定、世界观
  - **质量工具**：审计报告、知识图谱、全文搜索、版本快照
  - **工具中心**：AI对话、导出作品、偏好设置、自动守护
  - **系统信息**：系统设置、作品配置、Token用量、仪表盘

### 5. 可观测性基础

**文件**：`kunlun/observability.py`（新建）

- **生成耗时统计**：记录 Architect/Writer/Auditor/Polisher/KG Snapshot/Total 各步骤耗时
- **内存指标**：保留最近1000条记录，P95/Avg/Max
- **OpenTelemetry 集成**（可选）：通过 `OTEL_ENABLED=true` 一键启用
- **FastAPI 自动插桩**：HTTP 请求追踪
- **健康检查增强**：`/health` 端点返回生成统计

### 6. 数据库迁移系统

**文件**：`migrations/`（新建）

- **Alembic 配置**：管理 SQLite 数据库 schema 版本化
- **离线/在线模式**：支持生成 SQL 脚本或直接执行
- **模板脚本**：`script.py.mako` 自动生成迁移文件

### 7. 版本号统一

- `main.py` 中的硬编码版本号改为引用 `kunlun.__version__`
- 健康检查端点返回版本号

## 四、配置说明速查

### `.env` 关键配置项

```bash
# 安全（自用建议全开）
API_AUTH_ENABLED=true
API_AUTH_KEY=<python -c "import secrets; print(secrets.token_urlsafe(32))">
RATE_LIMIT_PER_MINUTE=30
RATE_LIMIT_GENERATE_PER_MINUTE=3
APP_HOST=127.0.0.1

# 成本控制
LLM_MAX_TOKENS_PER_REQUEST=4096
LLM_MAX_CALLS_PER_HOUR=60
LLM_DAILY_TOKEN_BUDGET=500000

# 备用 Key（逗号分隔）
OPENAI_API_KEYS_BACKUP=sk-backup1,sk-backup2

# 商业化时启用
OTEL_ENABLED=true
APP_HOST=0.0.0.0
```

### 启动命令

```bash
# 安装依赖
pip install -r requirements.txt

# 启动（数据库迁移自动执行）
python -m uvicorn kunlun.api.main:app --host 127.0.0.1 --port 8000

# 或直接
python kunlun/api/main.py
```

## 六、总结

### 核心改进

1. **安全性** — slowapi 限流 + API 认证 + 默认 localhost 绑定
2. **成本控制** — Token 预算 + 调用频率限制 + 备用 Key 轮换（已全链路生效）
3. **导出完整** — 7 种格式全暴露 + 投稿包
4. **可观测性** — 生成各步骤耗时统计 + OTel 预留
5. **数据库治理** — Alembic 自动迁移（启动时执行）
6. **Key 管理** — 多 Key 轮换 + 限流熔断冷却（60s）

### 不做的事（商业化时再说）

- 多用户认证（Keycloak）← Phase 2 剩余唯一 P1
- 实时协作（Yjs）
- 国际化（vue-i18n）
- 插件市场（pluggy）
- Grafana 仪表盘

### 定位升级路径

```
当前: 个人自用创作工具 (v0.1.0 → v0.2.0)
  ↓ Phase 2（1-2周）
安全可控的个人服务 (v0.5.0)
  ↓ Phase 3（2-4周）
小团队内网服务 (v1.0.0)
  ↓ Phase 4（4-8周）
多用户协作平台 (v2.0.0)
```

### 第三轮优化（2026-06-10 下午）— 降本增效·架构提质

| 文件 | 变更类型 | 说明 |
|------|:---:|------|
| `kunlun/gacha/engine.py` | 修改 | 模型池多模型混合（deepseek-chat+reasoner替代全reasoner）、climax/battle跳过廉价阶段、智能prompt压缩 |
| `kunlun/agents/writer.py` | 修改 | ContextBudgetAllocator实例缓存 + 修订prompt智能截断 + 异常类型化 |

**降本效果预估**：

| 优化项 | 节省量 |
|--------|:------:|
| 模型池多模型混合 | gacha_parallel_3 成本 -43%（同模型→混合模型） |
| climax/battle 跳过廉价 | cascade 模式 -2次LLM调用/章（按40%章节数） |
| Writer BudgetAllocator 缓存 | 每次生成 -1次对象创建 |
| 修订prompt智能截断 | 长章修订 -50% prompt token |

**增效效果预估**：

| 优化项 | 提速 |
|--------|:----:|
| 社会学串行→并行（3并发） | 8核心维度 ~3x 提速（8次/3≈2.7x） |
| 延迟导入缓存 | 每个热点端点 -1次 importlib 查找 |
| /chat 限流保护 | 防止API配额被单IP耗尽 |
| 智能prompt压缩 | 减少超大prompt导致的API超时 |
