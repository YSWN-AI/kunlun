## 二、通用设计模式提取（12大模式）

通过300个项目的交叉分析，提取以下12个对昆仑最有价值的通用设计模式：

### 模式1：声明式管线 (Declarative Pipeline)
**来源**: Haystack, Dify, LangChain(LCEL), ASP.NET Core, Prefect

**核心思想**：
- 用声明式描述(而非命令式代码)定义多步处理流程
- 支持DAG(有向无环图)而非纯线性流程
- 步骤之间通过类型化数据传递

**代码模板**：
```python
# 声明式管线定义（灵感：Haystack + ASP.NET Core）
class NovelPipeline:
    steps = [
        Step(SnapshotAgent, requires=[BookContext]),
        Step(ArchitectAgent, requires=[SnapshotOutput]),
        Step(SocietyAgent, requires=[ArchitectOutput], optional=True),
        Step(WriterAgent, requires=[ArchitectOutput, SocietyOutput]),
        Step(AuditAgent, requires=[WriterOutput], gate="8_gates"),
        Step(ReviseAgent, requires=[WriterOutput, AuditResult], 
             condition=lambda ctx: ctx.audit_score < 0.7),
    ]
```

**对昆仑的直接应用**：替换当前硬编码在 `makefile.py` 中的400行 `_run_chapter_pipeline_async()` 方法。

---

### 模式2：调谐循环 (Reconciliation Loop)
**来源**: Kubernetes Controllers, Spring Boot AutoConfiguration, Temporal Workflows

**核心思想**：
- 声明期望状态（Desired State）
- 控制器无限循环：观察(Observe) → 计算差异(Diff) → 调整(Act)
- 天然支持幂等、自愈、渐进收敛

**代码模板**：
```python
# 调谐循环（灵感：K8s Controller）
class AuditController:
    async def reconcile(self, chapter: Chapter) -> Chapter:
        """持续调谐直到章节通过所有门禁"""
        while True:
            current = await self.auditor.evaluate(chapter)
            if current.all_gates_passed():
                return chapter
            chapter = await self.reviser.revise(chapter, current.failed_gates)
```

**对昆仑的直接应用**：替换当前的固定3轮Audit→Revise循环，改为持续调谐直到达标。

---

### 模式3：中间件链/洋葱模型 (Middleware Chain / Onion)
**来源**: Django, Express.js, ASP.NET Core, Starlette, Envoy

**核心思想**：
- 核心业务逻辑被多层中间件包裹
- 每层处理一个横切关注点（日志/认证/限流/错误处理）
- 请求进入→逐层穿透→核心处理→逐层返回

**代码模板**：
```python
# 洋葱模型（灵感：Django + ASP.NET Core）
class PipelineMiddleware:
    """管线中间件基类"""
    async def process(self, context, next_handler):
        # 前置处理
        context = await self.before(context)
        # 调用下一个处理器
        result = await next_handler(context)
        # 后置处理
        return await self.after(result)

# 组合中间件
pipeline = Pipeline([
    AuthMiddleware(),      # 认证
    RateLimitMiddleware(), # 限流
    LoggingMiddleware(),   # 日志
    CoreAgentHandler(),    # 核心Agent
    ErrorRecoveryMiddleware(), # 错误恢复
])
```

**对昆仑的直接应用**：为管线添加统一的前置/后置处理层，解决当前裸异常捕获问题。

---

### 模式4：能力抽象/构建块 (Capability Abstraction / Building Blocks)
**来源**: Dapr, Semantic Kernel, LangChain Tools, Django Apps

**核心思想**：
- 将外部依赖抽象为标准化接口（存储/消息/模型/搜索）
- 每个接口有多个可替换的实现（Redis→SQLite, NATS→InProcess）
- 应用层不感知底层实现

**代码模板**：
```python
# 构建块抽象（灵感：Dapr + LangChain）
class StorageBlock(ABC):
    """存储构建块"""
    @abstractmethod
    async def save(self, key: str, data: dict) -> None: ...
    @abstractmethod
    async def load(self, key: str) -> dict: ...

class RedisStorage(StorageBlock): ...  # 生产环境
class SQLiteStorage(StorageBlock): ...  # 开发环境
class MemoryStorage(StorageBlock): ...  # 测试环境

# 组件注册
storage = config.get_storage()  # 根据环境自动选择实现
```

**对昆仑的直接应用**：统一Neo4j/NATS/Redis/Qdrant的抽象层，支持本地开发无需所有外部服务。

### 模式5：三层拦截架构 (Three-Layer Interception)
**来源**: NestJS (Guard → Interceptor → Pipe), ASP.NET Core, FastAPI Depends

**核心思想**：
- Guard层：认证/授权/权限检查（前置，可短路）
- Interceptor层：日志/度量/重试（环绕，不可短路但可修改）
- Pipe层：参数验证/类型转换（紧邻业务逻辑）

**代码模板**：
```python
# 三层拦截（灵感：NestJS）
class AgentExecutor:
    def __init__(self):
        self.guards: list[Guard] = [AuthGuard(), RateLimitGuard()]
        self.interceptors: list[Interceptor] = [LoggingInterceptor(), RetryInterceptor()]
        self.pipes: list[Pipe] = [ValidationPipe(), TransformationPipe()]
    
    async def execute(self, request: AgentRequest) -> AgentResult:
        # Guard: 认证/授权
        for guard in self.guards:
            if not await guard.can_activate(request):
                raise ForbiddenError()
        # Pipe: 参数验证
        for pipe in self.pipes:
            request = await pipe.transform(request)
        # Interceptor + Core
        return await self._with_interceptors(request)
```

**对昆仑的直接应用**：为Agent执行建立统一的安全/日志/验证框架。

```python
class ChapterCreate(BaseModel):
```

### 模式7：状态机 + 检查点 (State Machine + Checkpoint)
**来源**: Temporal, Prefect, Airflow, Kubernetes Operators

**核心思想**：
- 工作流定义为状态机，每步有明确的输入/输出/前置条件
- 每步完成后自动保存检查点（序列化中间状态）
- 失败时从最近检查点恢复，而非从头开始

**代码模板**：
```python
# 状态机+检查点（灵感：Temporal + Prefect）
@workflow
class ChapterCreationWorkflow:
    @step
    async def snapshot(self) -> SnapshotResult:
        return await self.agents.snapshot.capture(self.ctx.book)
    
    @step(requires=[snapshot])
    async def architect(self) -> ArchitectResult:
        return await self.agents.architect.plan(self.ctx)
    
    @step(requires=[architect], retry=3, timeout=300)
    async def write(self) -> WriterResult:
        return await self.agents.writer.generate(self.ctx)
    
    @step(requires=[write])
    async def audit(self) -> AuditResult:
        return await self.agents.auditor.evaluate(self.ctx.chapter)
```

**对昆仑的直接应用**：Makefile的17步管线改造为声明式工作流，每步自带检查点。

### 模式8：插件化扩展 (Plugin Architecture)
**来源**: pluggy, Litestar, Hocuspocus, Dify Plugin Marketplace, Tiptap Extensions

**核心思想**：
- 核心系统只定义扩展点(Extension Point / Hook)
- 插件实现具体功能，通过注册机制接入
- 支持动态发现(entry_points)、热加载、隔离

**代码模板**：
```python
# 插件架构（灵感：pluggy + Litestar）
class PipelinePlugin:
    """管线插件基类"""
    
    @hookspec
    def on_step_start(self, step_name: str, context: PipelineContext): ...
    
    @hookspec
    def on_step_complete(self, step_name: str, result: StepResult): ...
    
    @hookspec
    def on_pipeline_error(self, error: Exception, context: PipelineContext): ...

# 插件注册
class AuditPlugin(PipelinePlugin):
    """审计插件 - 为管线添加自动审计能力"""
    @hookimpl
    def on_step_start(self, step_name, context):
        if step_name == "writer":
            context.metadata["pre_audit_checksum"] = hash(context.chapter)

# 自动发现
plugin_manager = PluginManager("kunlun.pipeline")
plugin_manager.load_setuptools_entrypoints("kunlun.plugins")
```

**对昆仑的直接应用**：将21个扩展模块改为插件化注册，支持第三方扩展。

### 模式9：惰性求值与查询优化 (Lazy Evaluation)
**来源**: Polars, Vaex, Django QuerySet, Spark RDD

**核心思想**：
- 操作不立即执行，而是构建执行计划(Execution Plan)
- 最终执行时全局优化(谓词下推、列裁剪、算子融合)
- 中间结果不物化，减少内存占用

**代码模板**：
```python
# 惰性求值（灵感：Polars + Django QuerySet）
class LazyChapterQuery:
    """惰性章节查询"""
    def __init__(self):
        self._filters = []
        self._order_by = None
        self._limit = None
    
    def filter(self, condition) -> "LazyChapterQuery":
        self._filters.append(condition)
        return self
    
    def execute(self) -> list[Chapter]:
        # 构建优化后的执行计划
        plan = QueryOptimizer.optimize(self._filters, self._order_by, self._limit)
        return plan.execute()
```

**对昆仑的直接应用**：知识图谱查询改为惰性求值，减少Neo4j往返次数。

### 模式10：Saga/补偿事务 (Saga Pattern)
**来源**: Temporal, Axon Framework, NServiceBus, MassTransit

**核心思想**：
- 长事务拆分为多个局部事务
- 每个局部事务有对应的补偿操作(Compensating Action)
- 失败时逆序执行补偿，保证最终一致性

**代码模板**：
```python
# Saga模式（灵感：Temporal）
class ChapterPublishSaga:
    async def execute(self, chapter: Chapter):
        steps = []
        try:
            # Step 1: 格式化
            formatted = await self.formatter.format(chapter)
            steps.append(lambda: self.formatter.rollback(formatted.id))
            # Step 2: 上传
            uploaded = await self.uploader.upload(formatted)
            steps.append(lambda: self.uploader.delete(uploaded.url))
            # Step 3: 通知
            await self.notifier.notify(uploaded)
            steps.append(lambda: self.notifier.recall(uploaded.id))
        except Exception:
            # 逆序补偿
            for compensate in reversed(steps):
                await compensate()
            raise
```

**对昆仑的直接应用**：发布/导出管线中的多步操作保证原子性。

### 模式11：自适应降级 (Adaptive Degradation)
**来源**: Envoy Circuit Breaker, Resilience4j, Polly, Istio

**核心思想**：
- 检测下游服务健康状态（成功率/延迟/并发）
- 自动切换降级策略（减少调用/使用缓存/跳过非关键步骤）
- 半开状态探测恢复

**代码模板**：
```python
# 自适应降级（灵感：Resilience4j + Envoy）
class AdaptiveModelRouter:
    def __init__(self):
        self.circuit_breakers: dict[str, CircuitBreaker] = {}
    
    async def route(self, request: LLMRequest) -> LLMResponse:
        model = self._select_best_model(request)
        breaker = self.circuit_breakers.get(model)
        
        if breaker.is_open():
            # 熔断打开 → 降级到备用模型
            model = self._fallback_model(request)
        
        try:
            response = await self._call_model(model, request)
            breaker.on_success()
            return response
        except Exception as e:
            breaker.on_failure()
            if breaker.is_open():
                return await self._cached_or_default(request)
            raise
```

**对昆仑的直接应用**：LLM API调用的熔断降级，替代当前简单的60秒冷却。

### 模式12：事件溯源 + CQRS (Event Sourcing + CQRS)
**来源**: Axon Framework, EventStoreDB, Marten, Temporal

**核心思想**：
- 所有状态变更记录为不可变事件序列
- 当前状态 = 事件流折叠(reduce)
- 读写分离：写模型(Command)与读模型(Query)独立

**代码模板**：
```python
# 事件溯源（灵感：Axon + EventStoreDB）
class ChapterEventStore:
    async def append(self, chapter_id: str, event: ChapterEvent): ...
    async def read_stream(self, chapter_id: str) -> AsyncIterator[ChapterEvent]: ...

# 当前章节状态 = 事件折叠
chapter = await reduce(events, initial=EmptyChapter, reducer=apply_event)

# CQRS
class ChapterCommandHandler:  # 写模型
    async def handle(self, cmd: WriteChapter) -> ChapterId: ...

class ChapterQueryHandler:  # 读模型
    async def handle(self, query: GetChapter) -> ChapterView: ...
```

**对昆仑的直接应用**：章节修改历史不可变记录，支持完整审计和任意时间点回溯。

## 三、通用反模式警示（8大陷阱）

通过300个项目的源码审查和昆仑自身代码分析，提取以下反模式：

### 反模式1：上帝方法 (God Method)
**现象**: 单一方法超过200行，包含多个职责  
**昆仑现状**: `makefile.py` 中 `_run_chapter_pipeline_async()` 约400行  
**后果**: 无法测试、无法复用、修改风险高  
**解决方案**: 拆分为声明式管线（模式1），每步独立可测

---

### 反模式2：裸异常吞没 (Bare Exception Swallowing)
**现象**: `except Exception: pass` 或仅log不传播  
**昆仑现状**: 94处裸 `except Exception`，2处静默 `pass`  
**后果**: 生产错误不可见，数据不一致静默累积  
**解决方案**: 三层拦截（模式5）+ Saga补偿（模式10）

---

### 反模式3：全局可变状态 (Global Mutable State)
**现象**: 模块级可变单例、无锁共享字典  
**昆仑现状**: 8+ 模块级单例，3个无锁共享dict  
**后果**: 测试隔离困难、并发竞态、难以推理  
**解决方案**: 依赖注入容器 + 工厂模式替代模块级实例

---

### 反模式4：硬编码魔法数字 (Magic Numbers)
**现象**: 数值字面量散布各处，无命名无文档  
**昆仑现状**: 权重值、超时时间、重试次数散落各处  
**后果**: 调参困难、含义不明、容易遗漏  
**解决方案**: 集中常量文件 + Options模式（模式2的ASP.NET Core实现）

```python
# 改进点1：线程安全单例
import threading

class GachaEngine:
    _instance: Optional["GachaEngine"] = None
    _lock = threading.Lock()
    
    def __new__(cls, *args, **kwargs):
        if cls._instance is None:
            with cls._lock:
                if cls._instance is None:  # 双重检查
                    cls._instance = super().__new__(cls)
        return cls._instance

# 改进点2：滑动窗口熔断器
class SlidingWindowCircuitBreaker:
    """滑动窗口熔断器（对标 Resilience4j）"""
    def __init__(self, window_size: int = 60, failure_threshold: float = 0.5):
        self.window = deque(maxlen=window_size)
        self.threshold = failure_threshold
    
    def on_success(self): self.window.append(True)
    def on_failure(self): self.window.append(False)
    
    def is_open(self) -> bool:
        if len(self.window) < self.window.maxlen // 2:
            return False
        failure_rate = 1 - sum(self.window) / len(self.window)
        return failure_rate > self.threshold

# 改进点3：多级降级
class AdaptiveModelRouter:
    """自适应模型路由（对标 Istio Traffic）"""
    async def route(self, request: LLMRequest) -> LLMResponse:
        # Level 1: 主模型
        if not self.primary_breaker.is_open():
            try:
                return await self._call(self.primary_model, request)
            except Exception:
                self.primary_breaker.on_failure()
        
        # Level 2: 备用模型
        if not self.fallback_breaker.is_open():
            try:
                return await self._call(self.fallback_model, request)
            except Exception:
                self.fallback_breaker.on_failure()
        
        # Level 3: 缓存/默认值
        return self._get_cached_or_default(request)

# 改进点4：资源清理
async def cleanup(self):
    """资源清理（对标 Dragonfly 优雅关闭）"""
    if self._shared_http_client:
        await self._shared_http_client.aclose()
    for client in self._client_cache.values():
        await client.close()
```

### 6.4 `kunlun/core/extension_base.py` — 扩展系统

**当前问题**：

```python
# 改进点1：命名空间隔离
class BaseExtensionModule:
    _instances: dict[str, "BaseExtensionModule"] = {}
    _lock = threading.Lock()
    
    @classmethod
    def get_factory(cls, book_id: str = "") -> "BaseExtensionModule":
        key = f"{cls.__module__}.{cls.__name__}:{book_id}"  # 加命名空间
        if key not in cls._instances:
            with cls._lock:
                if key not in cls._instances:  # 双重检查
                    cls._instances[key] = cls(book_id)
        return cls._instances[key]

# 改进点2：插件注册
class ExtensionRegistry:
    """扩展注册中心（对标 pluggy PluginManager）"""
    def __init__(self):
        self._extensions: dict[str, type[BaseExtensionModule]] = {}
    
    def register(self, name: str, ext_class: type[BaseExtensionModule]):
        self._extensions[name] = ext_class
    
    def discover(self, entry_point_group: str = "kunlun.extensions"):
        """自动发现扩展（对标 setuptools entry_points）"""
        import importlib.metadata
        for ep in importlib.metadata.entry_points(group=entry_point_group):
            self.register(ep.name, ep.load())
```
