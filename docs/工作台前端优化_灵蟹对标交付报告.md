## 一、灵蟹创作对标分析总结

### 1.1 灵蟹创作核心定位

灵蟹创作是基于 VS Code 扩展架构的 AI 创意工作台，面向小说家、编剧、游戏叙事创作者。核心理念：**AI 放大创作力，而非替代创作者**。

### 1.2 UI 布局特点

| 区域 | 灵蟹创作设计 | 昆仑对标实现 |
|------|-------------|-------------|
| 活动栏 | 48px 宽，左侧最边，图标+tooltip，secondarySidebar 容器 | ✅ 48px 活动栏，9个导航项（含新增版本历史），图标+tooltip |
| 侧边栏 | Webview 驱动，可折叠切换，单视图聚焦 | ✅ 240px 可折叠侧边栏，拖拽调宽，视图切换 |
| 编辑器 | VS Code 原生编辑器，标签页多开 | ✅ 双编辑器分屏，标签页管理，欢迎页 |
| 底部面板 | 终端/输出面板，可收起 | ✅ AI对话/审校结果/输出日志三标签，可折叠拖拽 |
| 状态栏 | 字数/光标/模型/保存状态 | ✅ 书籍/章节/光标/字数/进度/质量/模型/保存 |
| 命令面板 | Ctrl+Shift+P，模糊搜索命令 | ✅ 命令面板，新增10+创作相关命令 |

### 1.3 核心功能面板对标

| 灵蟹功能 | 昆仑原状态 | 本次实现 |
|----------|-----------|---------|
| 人物卡管理 | 占位空面板 | ✅ 完整CRUD + 详情卡 + 关系列表 |
| 故事大纲/结构 | 占位空面板 | ✅ 章节树 + 伏笔管理 + 4种叙事模板 |
| 世界观/故事圣经 | 占位空面板 | ✅ 6板块（世界观/力量/地理/势力/时间线/备注） |
| 检查点/版本回退 | 无 | ✅ 检查点创建 + 版本列表 + 内容恢复 + diff对比 |
| AI 对话写作 | 已有 | ✅ 保留（总调度/Vibe写作双模式） |
| 叙事一致性 | 部分（记忆系统） | ✅ 保留记忆管理 + 人物/大纲联动 |
| 本地存储隐私优先 | 已有 | ✅ JSON文件本地存储，data/books/book_<id>/ |

### 1.4 交互模式与设计理念

- **VS Code 原生交互范式**：活动栏点击切换、侧边栏折叠、命令面板、快捷键驱动 — 昆仑已全面对标
- **AI 建议审阅制**：每条 AI 建议需用户确认后采纳 — 昆仑创作结果面板支持复制/插入/继续/调整
- **检查点探索机制**：灵蟹强调"使用检查点探索不同方向，需要时随时回退" — 昆仑新增版本/检查点面板
- **结构化素材组织**：人物/世界观/情节/弧线分离管理 — 昆仑4个新面板实现结构化管理

## 二、新增面板功能说明

### 2.1 人物卡管理 (Characters)

**位置**：活动栏 👤 图标 → 侧边栏人物卡面板

**功能清单**：
- **人物列表**（虚拟滚动）：显示姓名、角色定位，支持大量人物流畅滚动
- **人物详情卡**：姓名、角色定位、性格、外貌、背景、能力、动机、成长弧光、备注
- **人物关系**：JSON 格式定义关系（目标人物+关系类型），列表形式展示
- **完整 CRUD**：
  - 创建：模态表单，10个字段
  - 读取：列表摘要 + 点击查看完整详情
  - 更新：模态表单编辑所有字段
  - 删除：确认后删除
- **后端端点**：
  - `GET /api/v1/workstation/characters` — 人物列表
  - `GET /api/v1/workstation/characters/{id}` — 人物详情
  - `POST /api/v1/workstation/characters` — 创建
  - `PUT /api/v1/workstation/characters/{id}` — 更新
  - `DELETE /api/v1/workstation/characters/{id}` — 删除

**数据存储**：`data/books/book_default/characters.json`

### 2.2 大纲/故事结构 (Outline)

**位置**：活动栏 📋 图标 → 侧边栏大纲结构面板

**功能清单**：
- **三标签页设计**：
  - 📋 **章节树**：可折叠树状结构，支持卷/章/场景/弧线四种节点类型
  - 🔮 **伏笔管理**：伏笔列表，支持状态切换（活跃/已回收/废弃）、重要性标记
  - 📐 **叙事模板**：4种经典结构一键应用
    - 三幕式结构（8阶段）
    - 英雄之旅（12阶段）
    - 起承转合（4阶段）
    - 七点结构（7阶段）
- **树状节点**：支持父子层级、折叠展开、状态标记（草稿/写作中/完成）、排序
- **节点编辑**：标题、类型、父节点、摘要、情节点、目标字数、状态、排序
- **伏笔 CRUD**：标题、描述、埋设章节、回收章节、状态、重要性
- **后端端点**：
  - `GET /api/v1/workstation/outline` — 完整大纲（节点+伏笔）
  - `POST /api/v1/workstation/outline/nodes` — 创建节点
  - `PUT /api/v1/workstation/outline/nodes/{id}` — 更新节点
  - `DELETE /api/v1/workstation/outline/nodes/{id}` — 删除节点（含子节点递归）
  - `GET /api/v1/workstation/outline/foreshadows` — 伏笔列表
  - `POST /api/v1/workstation/outline/foreshadows` — 创建伏笔
  - `PUT /api/v1/workstation/outline/foreshadows/{id}` — 更新伏笔
  - `DELETE /api/v1/workstation/outline/foreshadows/{id}` — 删除伏笔

**数据存储**：`data/books/book_default/outline.json`

### 2.3 版本/检查点 (Versions)

**位置**：活动栏 🕐 图标 → 侧边栏版本历史面板

**功能清单**：
- **版本历史列表**（虚拟滚动）：按时间倒序，显示标签、章节、字数、创建时间、检查点标记
- **创建检查点**：捕获当前编辑器内容，自定义标签和章节名
- **版本详情**：标签、章节、字数、创建时间
- **查看内容**：模态弹窗预览版本完整内容
- **恢复版本**：确认后将版本内容写入当前编辑器（覆盖当前内容）
- **删除版本**：确认后删除
- **版本差异对比**（后端支持）：行级 diff，统计新增/删除/修改/相同行数
- **后端端点**：
  - `GET /api/v1/workstation/versions` — 版本列表（支持按章节筛选）
  - `GET /api/v1/workstation/versions/{id}` — 版本详情（含完整内容）
  - `POST /api/v1/workstation/versions/checkpoint` — 创建检查点
  - `POST /api/v1/workstation/versions/restore` — 恢复版本
  - `POST /api/v1/workstation/versions/diff` — 版本差异对比
  - `DELETE /api/v1/workstation/versions/{id}` — 删除版本

**数据存储**：`data/books/book_default/versions.json`

### 2.4 故事圣经 (Story Bible)

**位置**：活动栏 🌍 图标 → 侧边栏故事圣经面板（原世界观面板升级）

**功能清单**：
- **6大板块标签**：
  - 🌍 世界观 — 世界基本设定、规则、历史
  - ⚡ 力量体系 — 修炼/魔法/科技体系设定
  - 🗺️ 地理 — 地点、区域、地图描述
  - 🏛️ 势力 — 组织、门派、国家、阵营
  - 📅 时间线 — 重要事件、年代记
  - 📝 备注 — 其他设定笔记
- **条目管理**：每个板块下支持多条目，每条含标题、内容、标签
- **完整 CRUD**：创建、读取、更新、删除，支持板块间移动
- **后端端点**：
  - `GET /api/v1/workstation/bible` — 全部板块内容
  - `GET /api/v1/workstation/bible?section=xxx` — 指定板块
  - `POST /api/v1/workstation/bible/items` — 创建条目
  - `PUT /api/v1/workstation/bible/items/{id}` — 更新条目
  - `DELETE /api/v1/workstation/bible/items/{id}` — 删除条目

**数据存储**：`data/books/book_default/bible.json`

## 三、前端性能优化

### 3.1 面板懒加载

**实现机制**：
- 4个新面板（人物/大纲/版本/圣经）初始仅渲染占位加载器
- 用户首次点击活动栏切换到对应视图时，延迟 50ms 后调用 `ensureLoaded()` 创建完整 DOM 和绑定事件
- 已加载面板切换时不再重复初始化
- 通过 `initLazyLoading()` 包装 `IDE.switchView()` 实现透明集成

**性能收益**：
- 页面初始加载减少 4 个面板的 DOM 创建和事件绑定
- 首屏渲染时间显著降低
- 不使用的面板零开销

### 3.2 虚拟滚动

**实现机制**：
- 原生 JS 实现 `VirtualScroll` 类，无外部依赖
- 仅渲染可视区域内的元素（含上下 buffer 各5项）
- 滚动时动态计算可见范围，替换 DOM 内容
- 通过绝对定位模拟完整列表高度

**应用场景**：
- 人物列表（`char-virtual-list`，行高36px）
- 版本历史列表（`version-virtual-list`，行高44px）
- 章节树（现有，可扩展）
- 搜索结果（现有，可扩展）

**性能收益**：
- 1000+ 条人物/版本记录仍保持 60fps 滚动
- DOM 节点数从 O(n) 降至 O(可视高度/行高 + buffer)
