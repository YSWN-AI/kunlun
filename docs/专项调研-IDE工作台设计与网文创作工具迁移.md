# IDE 工作台设计理念调研：可迁移到 AI 网文创作工具的设计模式

> 调研对象：VS Code、JetBrains 系列（IntelliJ IDEA / PyCharm / WebStorm 等）、AI IDE（TRAE / Cursor / Windsurf / GitHub Copilot Workspace / 通义灵码 / 百度 Comate）、AI Agent 工作台
> 目标：提炼成熟 IDE 与 AI IDE 的工作台范式，为「昆仑创作引擎」的 AI 驱动写作工作台设计提供可落地的迁移清单。
> 日期：2026-09-04

## 一、VS Code 工作台设计分析

VS Code 的核心设计哲学是 **"以编辑器为中心、以命令为总线、以扩展为生态"**。它不是一个功能堆砌的 IDE，而是一个可被命令和插件重新定义的"工作台外壳"。

### 1.1 整体布局范式：五区结构

VS Code 采用经典的五区布局，从左到右、从上到下依次为：

| 区域 | 位置 | 职责 |
|------|------|------|
| **活动栏（Activity Bar）** | 最左侧窄条 | 视图切换器，图标即入口；点击切换侧边栏内容，再次点击可收起 |
| **主侧边栏（Primary Side Bar）** | 活动栏右侧 | 承载当前选中的视图（资源管理器/搜索/源代码管理/运行/扩展） |
| **编辑器区（Editor）** | 中央 | 核心工作区，支持多标签、多分屏、网格布局 |
| **面板（Panel）** | 底部 | 终端/问题/输出/调试控制台，多 Tab 切换，可收起 |
| **状态栏（Status Bar）** | 最底部 | 高密度信息条：行列号、编码、语言、Git 分支、错误警告数、缩进 |

此外还有 **二级侧边栏（Secondary Side Bar）**，位于编辑器右侧，默认承载 Chat 视图，可通过拖拽将主侧边栏的任意视图迁移过去，形成"左右双栏 + 中央编辑"的三栏工作流。

**设计精髓**：
- **活动栏是"视图遥控器"**，本身不占内容空间，只做切换；
- **侧边栏是"上下文容器"**，同一位置根据活动栏选择渲染不同视图，避免窗口碎片化；
- **面板可收起**，写作/编码时一键隐藏，需要时呼出，不干扰主区；
- **状态栏是"零交互信息层"**，只展示不操作（点击部分项可跳转），信息密度极高但不抢焦点。

### 1.2 命令面板（Command Palette）

`Ctrl+Shift+P`（或 F1）呼出命令面板，是 VS Code 最具标志性的设计。

**核心机制**：
- **模糊搜索**：输入任意字符片段即可匹配命令名，支持拼音/缩写/子串匹配；
- **命令分类与前缀**：命令按 `类别: 动作` 命名（如 `Preferences: Open Settings`、`Git: Commit`），类别天然形成分组；
- **快捷键提示**：每条命令右侧显示绑定的快捷键，用户在使用中自然学习键位；
- **最近使用排序**：高频命令自动上浮，降低重复操作成本；
- **`>` 前缀区分模式**：`Ctrl+P` 是文件快速打开，输入 `>` 后切换为命令模式，同一输入框承载两种语义。

**设计精髓**：命令面板是 **"功能的统一索引层"**。所有操作——无论来自内核还是扩展——都注册为一条命令，面板是唯一入口。这意味着：
- 用户不需要记住菜单层级；
- 扩展可以无缝融入，不需要新的 UI 范式；
- 键盘流用户可以完全脱离鼠标。

### 1.3 多编辑器 / 分屏

VS Code 的编辑器区支持极其灵活的多文档布局：

- **标签页（Tabs）**：每个打开的文件一个标签，支持拖拽排序、固定（Pin）、预览模式（单击预览，双击正式打开）；
- **左右分屏**：`Ctrl+\` 将当前编辑器拆分为左右两组；
- **上下分屏**：拖拽标签到上下边缘，或通过命令面板 `View: Split Editor Up/Down`；
- **网格布局**：支持 2x2、3x3 等任意网格，每个格子是一个独立的"编辑器组（Editor Group）"；
- **编辑器组独立导航**：每个组有自己的标签栈和光标历史，组间切换不互相干扰。

**设计精髓**：分屏的本质是 **"多上下文并行"**。开发者经常需要一边看定义一边写调用，一边看测试一边改实现。VS Code 把这种"多上下文"做成了一等公民，而不是弹窗或切换。

### 1.4 侧边栏设计：多视图切换

主侧边栏通过活动栏切换，默认包含五大视图：

| 视图 | 职责 | 写作工具映射 |
|------|------|-------------|
| **资源管理器（Explorer）** | 项目文件树，支持折叠、多选、拖拽、右键操作 | 书籍目录树（卷/章/节） |
| **搜索（Search）** | 全局搜索替换，支持正则、排除目录、结果分组 | 全文检索（人物名/伏笔/设定） |
| **源代码管理（SCM）** | Git 变更列表、暂存、提交、差异对比 | 版本管理/章节历史 |
| **运行（Run）** | 调试配置、断点、调用栈、变量 | 写作管线运行/任务状态 |
| **扩展（Extensions）** | 扩展市场、已安装列表、推荐 | 写作技能/模板市场 |

每个视图内部还可以有 **子视图（Views）**，例如资源管理器里有"打开的编辑器""大纲""时间线"等可折叠面板，用户可以拖拽重排、隐藏不需要的子视图。

**设计精髓**：侧边栏是 **"项目级上下文的容器"**，它展示的不是当前文件的信息，而是整个项目的结构和状态。多视图切换保证了"同一空间承载多种项目视角"。

### 1.5 底部面板：多 Tab 面板

底部面板默认包含四个 Tab：

- **终端（Terminal）**：集成 shell，支持多终端、分屏终端；
- **问题（Problems）**：当前文件/项目的错误和警告列表，点击跳转；
- **输出（Output）**：各扩展/语言服务的日志输出，可切换来源；
- **调试控制台（Debug Console）**：调试时的 REPL 和变量输出。

面板可以调整高度、最大化、收起（`Ctrl+J`），也可以移动到右侧（`View: Toggle Panel Position`）。

**设计精髓**：底部面板是 **"异步反馈的聚合层"**。终端输出、编译错误、扩展日志、调试信息——这些都是"用户操作后异步产生的反馈"，统一放在底部，不打断主编辑区的焦点。

### 1.6 快捷键体系

VS Code 的快捷键设计有几个关键特征：

- **键位映射文件（keybindings.json）**：所有快捷键可通过 JSON 完全自定义，支持 `when` 上下文条件（如 `editorTextFocus && !editorReadonly`）；
- **快捷键编辑器 UI**：图形化搜索、修改、冲突检测；
- **Chord 快捷键（双键序列）**：`Ctrl+K` 作为前缀，后续跟第二个组合键，如 `Ctrl+K Ctrl+S`（打开快捷键设置）、`Ctrl+K Ctrl+X`（裁剪尾随空格）。这极大扩展了快捷键命名空间，又不会与单键冲突；
- **上下文快捷键**：同一快捷键在不同上下文（编辑器、终端、侧边栏）触发不同命令；
- **命令面板即快捷键学习器**：每条命令显示快捷键，用户在搜索命令时被动学习。

### 1.7 状态栏信息密度

状态栏是 VS Code 信息密度最高的区域，典型内容包括：

- **左侧**：Git 分支名、同步状态（ ahead/behind 数）、错误数 × 警告数；
- **中央/右侧**：当前光标行列号（`Ln 12, Col 34`）、缩进（`Spaces: 4`）、编码（`UTF-8`）、换行符（`LF`）、语言模式（`Python`）、通知铃铛。

每一项都可点击跳转（如点击错误数打开问题面板，点击语言模式切换语言）。

**设计精髓**：状态栏是 **"全局状态的仪表盘"**，用极小的空间传递最关键的项目/文件状态，且每项都是可操作入口。

### 1.8 设置与配置

VS Code 的设置采用 **"UI + JSON 双轨制"**：

- **设置 UI**：`Ctrl+,` 打开图形化设置，分类浏览、搜索、下拉/复选框修改；
- **settings.json**：`Ctrl+Shift+P` → `Preferences: Open User Settings (JSON)`，直接编辑配置文件，支持注释、自动补全、悬停文档；
- **三层配置优先级**：默认值 < 用户设置 < 工作区设置（`.vscode/settings.json`），工作区设置可随项目共享；
- **配置即数据**：所有设置都是 JSON 键值对，扩展通过 `contributes.configuration` 声明自己的配置项，自动出现在设置 UI 和 JSON 补全中。

### 1.9 插件 / 扩展系统

VS Code 的扩展生态是其成功的核心支柱：

- **扩展市场（Marketplace）**：内置搜索、安装、评分、下载量；
- **扩展激活（Activation Events）**：扩展按需激活（如打开某语言文件时才激活），不拖慢启动；
- **扩展贡献点（Contribution Points）**：扩展通过声明式 JSON 贡献命令、视图、菜单项、配置、主题、语言支持等，内核提供统一的注册和渲染机制；
- **扩展隔离**：每个扩展运行在独立的 Extension Host 进程，崩溃不影响主界面。

### 1.10 快速打开（Quick Open）

`Ctrl+P` 呼出快速打开：

- **文件模糊跳转**：输入文件名片段（支持路径片段），实时匹配；
- **`@` 符号导航**：在文件内输入 `@` 后列出当前文件的符号（函数/类/变量），可模糊搜索跳转；
- **`:` 行号跳转**：输入 `:123` 直接跳到第 123 行；
- **`#` 全局符号**：输入 `#` 后搜索整个项目的符号；
- **`>` 切换命令模式**：同一输入框前缀切换语义。

**设计精髓**：快速打开是 **"导航的统一入口"**，文件、符号、行号、命令都在一个输入框里完成，靠前缀区分语义。

### 1.11 Peek 预览

Peek 是 VS Code 的内联预览机制：

- **Peek Definition（Alt+F12）**：在当前编辑器内联弹出一个小编辑器，显示定义位置，不离开当前上下文；
- **Peek References（Shift+F12）**：内联显示所有引用位置，左侧列表 + 右侧代码预览；
- **Peek Implementations**：内联显示接口实现；
- 内联编辑器可直接编辑，关闭后回到原位置。

**设计精髓**：Peek 是 **"零上下文切换的查阅"**。传统"跳转-查阅-返回"会丢失当前位置和阅读节奏，Peek 把查阅嵌入当前视图，保持心流。

### 1.12 Minimap 缩略图

编辑器右侧的代码缩略图：

- 显示整个文件的缩小版，高亮当前视口位置；
- 点击/拖拽快速跳转；
- 可显示差异标记（Git 增删改）、错误警告标记；
- 可关闭、可调整宽度、可渲染字符或色块。

**设计精髓**：Minimap 是 **"长文档的空间地图"**，让用户在数千行文件中保持方位感。

### 1.13 Zen Mode 专注模式

`Ctrl+K Z` 进入 Zen Mode：

- 隐藏活动栏、侧边栏、面板、状态栏；
- 编辑器居中、限宽（类似写作软件的专注模式）；
- 按 `Esc Esc` 退出；
- 可配置是否隐藏状态栏、是否居中。

**设计精髓**：Zen Mode 承认 **"工具界面本身是干扰"**，在需要深度专注时一键剥离所有 Chrome，只留内容。

### 1.14 主题与个性化

- **颜色主题（Color Theme）**：完整的 Token Color 定制，支持工作区/编辑器/UI 各部分颜色；
- **文件图标主题（File Icon Theme）**：根据文件类型显示不同图标；
- **产品图标主题（Product Icon Theme）**：UI 图标的替换；
- 主题通过扩展贡献，一键切换。

## 二、JetBrains 系列工作台设计分析

JetBrains IDE 的设计哲学是 **"以项目为中心、以智能分析为驱动、以工具窗口为组织单元"**。与 VS Code 的"轻量外壳 + 扩展"不同，JetBrains 是"重内核 + 深度集成"，对项目有完整的语义理解。

### 2.1 整体布局：工具窗口（Tool Windows）体系

JetBrains 没有 VS Code 那种固定的五区结构，而是采用 **"工具窗口（Tool Window）"** 的自由布局范式：

- 工具窗口可以附着在主窗口的 **左、右、下** 三个边缘；
- 每个工具窗口有一个 **工具窗口栏（Tool Window Bar）** 上的图标按钮，点击展开/收起；
- 工具窗口可以 **浮动（Floating）**、**窗口化（Windowed）** 为独立窗口（适合多显示器）；
- 支持 **分屏（Split）**：同一侧可以上下或左右排列多个工具窗口；
- 快捷键 `Alt+数字`（如 `Alt+1` 打开 Project 窗口）快速切换。

**设计精髓**：工具窗口是 **"可任意重组的功能面板"**。VS Code 的侧边栏是"一个位置切换多个视图"，JetBrains 是"多个窗口可以同时存在于多个位置"，更灵活但也更复杂。

### 2.2 Project 视图（项目视图）

`Alt+1` 打开 Project 工具窗口，是 JetBrains 最核心的项目导航：

- **多视角切换**：Project（目录结构）、Packages（包结构）、Project Files、Project Source Files、Scratches and Consoles 等；
- **范围视图（Scope Views）**：按预设范围（如仅测试文件、仅变更文件）过滤项目；
- **智能折叠**：包名可折叠为链式显示（`com.example.app` 折叠为一行）；
- **关联高亮**：当前编辑器打开的文件在 Project 视图中自动高亮定位（可配置自动滚动）；
- **右键上下文菜单**：New、Refactor、Git、Analyze 等操作直接在文件节点上执行。

**设计精髓**：Project 视图不是简单的文件树，而是 **"项目的多视角语义导航器"**。同一个项目可以从目录、包、范围等不同维度查看。

### 2.3 编辑器与分屏

JetBrains 编辑器支持：

- **标签页**：支持多行标签、固定标签、拆分标签；
- **分屏（Split）**：右键标签 → Split Right / Down，或拖拽标签到边缘；
- **智能分屏**：可选择"水平拆分"或"垂直拆分"，每个拆分独立导航；
- **无标签模式（Tabless）**：可配置隐藏标签栏，靠快捷键切换文件；
- **Distraction Free Mode**：类似 Zen Mode，居中限宽、隐藏所有工具窗口。

### 2.4 TODO 窗口

JetBrains 的 TODO 工具窗口是一个被广泛称赞的设计：

- **自动扫描**：持续扫描代码中匹配 TODO 模式（`TODO`、`FIXME` 等可自定义正则）的注释；
- **多 Tab 分类**：Project（全项目）、Current File（当前文件）、Scope（按范围）、Based on TODO Pattern（按模式）；
- **点击跳转**：点击 TODO 项直接定位到代码行；
- **自定义模式**：可在 Settings 中添加自定义 TODO 模式（如 `REVIEW:`、`OPTIMIZE:`），并指定颜色和图标；
- **过滤与排序**：按模块、包、文件、模式过滤。

**设计精髓**：TODO 窗口是 **"内嵌标记的全局追踪器"**。用户在正文中随手写的标记，自动聚合成可管理的任务列表，不需要额外的任务管理工具。

### 2.5 Database 工具

JetBrains Ultimate 版内置 Database 工具窗口：

- **数据源管理**：连接 MySQL/PostgreSQL/SQLite/Redis 等，显示表结构、视图、存储过程；
- **SQL 编辑器**：带语法高亮、补全、执行计划的 SQL 编辑器；
- **数据编辑器**：表数据可直接编辑、过滤、排序、导出；
- **图表**：表关系 ER 图；
- **与代码集成**：代码中的 SQL 字符串可识别并提供补全，JPA 实体可与表关联。

**设计精髓**：Database 工具体现了 JetBrains **"把开发涉及的所有数据源都纳入 IDE 语义层"** 的理念。

### 2.6 Run Dashboard / Services 窗口

- **Run Dashboard**（新版统一为 **Services 窗口**）：集中管理所有运行配置（应用、测试、数据库、Docker 等）；
- 显示每个服务的状态（运行中/已停止/调试中）、端口、日志；
- 支持批量启动/停止、服务间依赖拓扑图；
- 选中服务后在下方显示其日志和控制台。

**设计精髓**：Services 窗口是 **"多进程/多服务的统一控制面板"**，对于微服务/多组件项目尤其重要。

### 2.7 Local History（本地历史）

JetBrains 的 Local History 是一个杀手级功能：

- **自动版本快照**：无需 Git，IDE 自动记录文件的每次变更（保存、测试通过、重构等节点）；
- **按文件/目录/项目查看**：右键任意节点 → Local History → Show History；
- **差异对比**：时间线列表 + diff 查看器，可回滚到任意历史版本；
- **标签（Label）**：可在重要节点手动打标签（如"重构前"）；
- **保留期**：默认保留 5 天（可配置），不占用 Git 仓库空间。

**设计精髓**：Local History 是 **"零成本的安全网"**。用户不需要主动提交就能拥有版本回滚能力，对于"试错式创作"尤其有价值。

### 2.8 其他 JetBrains 特色

- **结构视图（Structure）**：`Alt+7`，当前文件的符号树（类/方法/字段），快速跳转；
- **查找操作（Find Action）**：`Ctrl+Shift+A`，类似 VS Code 命令面板，模糊搜索所有操作；
- **随处搜索（Search Everywhere）**：双击 `Shift`，统一搜索文件、类、符号、操作、设置；
- **智能补全（Code Completion）**：基本补全 `Ctrl+空格`、智能补全 `Ctrl+Shift+空格`（基于类型推断）、语句补全 `Ctrl+Shift+Enter`；
- **快速文档（Quick Documentation）**：`Ctrl+Q` 悬停显示文档；
- **快速定义（Quick Definition）**：`Ctrl+Shift+I` 内联预览定义（类似 Peek）；
- **重构菜单（Refactor This）**：`Ctrl+Alt+Shift+T`，上下文相关的重构操作列表；
- **VCS 集成**：`Alt+9` 打开 Git 工具窗口，包含 Log、Local Changes、Console、Shelf 等 Tab；
- **检查（Inspections）**：实时静态分析，问题高亮 + 快速修复（`Alt+Enter`）；
- **设置（Settings）**：`Ctrl+Alt+S`，统一的设置对话框，按类别树状导航，搜索框过滤。

## 三、AI IDE 与 Agent 工作台设计参考

传统 IDE（VS Code / JetBrains）解决的是"人写代码"的效率问题，而 AI IDE 解决的是 **"人与 AI 协作创作"** 的范式问题。AI IDE 在传统 IDE 布局基础上，新增了三个核心设计维度：**AI 对话作为一等公民、Agent 自主执行作为新工作模式、多 Agent 协作作为新组织单元**。这些设计对昆仑引擎的"AI 驱动网文创作"范式具有最直接的参考价值。

### 3.1 TRAE（字节跳动 AI IDE）— 重点分析

TRAE 基于 VS Code 架构（内核代号 TraeCode），是对昆仑引擎最有参考价值的 AI IDE——它同样是"中国团队打造的、AI 原生的、基于 VS Code 架构的创作工具"，其工作台布局和 AI 交互设计值得深入拆解。

#### 3.1.1 整体布局：左侧 VS Code + 右侧 AI 工作区常驻

TRAE 保留了 VS Code 的五区结构，但做了一个关键调整：**右侧 AI 面板默认常驻**，而不是像 VS Code 那样默认隐藏二级侧边栏。

```
┌──────────────────────────────────────────────────────┐
│ 顶部菜单栏（文件、编辑、选择、视图、前往、运行、帮助） │
├───────────┬──────────────────────────┬───────────────┤
│           │                          │               │
│ 左侧边栏  │    中央编辑区            │  右侧 AI 面板 │
│ • 文件    │  • 代码编辑器            │  • Chat 对话  │
│ • 搜索    │  • 多标签/分屏           │  • Builder    │
│ • 源代码  │                          │  • 任务列表    │
│ • 扩展    │                          │               │
├───────────┴──────────────────────────┴───────────────┤
│ 底部面板：终端 / 问题 / 输出 / AI 输出日志             │
├──────────────────────────────────────────────────────┤
│ 状态栏：分支 / 错误 / 行列 / 编码 / AI 模型状态        │
└──────────────────────────────────────────────────────┘
```

**设计精髓**：
- **AI 面板从"可选的二级侧边栏"升级为"默认常驻的一等区域"**，反映了 AI IDE 的核心范式转移：AI 不是辅助工具，而是协作伙伴；
- 左侧保留传统项目导航（文件/搜索/Git/扩展），中间是编辑器，右侧是 AI——形成 **"项目-创作-AI"三栏并行**；
- 右侧 AI 面板可通过 `Ctrl+U`（macOS: `Cmd+U`）一键收起，需要时呼出，不干扰纯写作场景；
- 这种"左中右"三栏布局比传统"左编辑+底面板"更适合 AI 协作，因为 AI 对话需要与正文并排对照，而不是挤在底部窄条里。

#### 3.1.2 AI 交互双模式：Chat 与 Builder

TRAE 右侧 AI 面板有两个核心模式，对应两种不同的协作深度：

**Chat 模式（默认）**：
- 侧边对话面板，适合较完整的任务沟通：解释代码仓库、生成代码片段、修复错误、规划实现方案；
- 支持 **行内对话（Inline Chat）**：在编辑器中选中代码后直接提问，结果在代码附近内联显示，不切换到侧边栏；
- 支持 **拖拽文件到对话输入框**，自动附加为上下文；
- 对话中可引用代码、文件、文件夹，AI 自动感知当前项目结构和打开的文件。

**Builder 模式**：
- **端到端项目生成**：通过自然语言描述需求（如"开发带用户登录的论坛系统"），自动完成环境配置、前后端代码生成、依赖管理及实时预览；
- 支持 **多模态输入**：Figma 设计稿、手绘草图可直接生成代码；
- Builder Agent 动态响应上下文，不再使用固定的预定义提案；
- 生成过程中可与终端交互、删除文件、调整方案，AI 不是"一次性生成"而是"迭代式构建"。

**对昆仑引擎的映射**：
- Chat 模式 → **AI 写作助手对话**（解释剧情、生成片段、修复逻辑、规划大纲、回答设定问题）；
- Builder 模式 → **整书/整卷生成模式**（自然语言描述"写一本玄幻爽文，主角重生复仇，开局被退婚"，AI 自动完成世界观设定、卷大纲、人物卡、首章正文，并实时预览）；
- 行内对话 → **选中段落后直接 AI 改写/润色/扩写**，结果在正文附近内联显示，不离开当前写作位置。

#### 3.1.3 SOLO 模式：AI 自主执行的三栏工作台

TRAE 的 SOLO 模式是 AI IDE 中最具颠覆性的设计。左上角模式切换按钮将 TraeCode 切换到 SOLO 模式后，整个界面变为三栏，传统的"左文件-中编辑-右AI"让位于 **"任务-对话-工具"** 的 Agent 工作台：

```
┌──────────────┬───────────────────┬──────────────┐
│              │                   │              │
│ 任务管理面板  │   AI 对话面板     │  工具面板     │
│              │                   │              │
│ • 任务列表    │ • 自然语言输入    │ • 编辑器      │
│ • 子任务拆解  │ • AI 思考过程     │ • 文档查看    │
│ • 执行状态    │ • 执行结果        │ • 浏览器      │
│ • 依赖关系    │ • 人工干预点      │ • 终端        │
│              │                   │              │
└──────────────┴───────────────────┴──────────────┘
```

**核心机制**：
- 用户通过 **自然语言描述、语音交互或上传本地文件** 输入需求；
- AI 自主拆解任务为子任务列表，显示在左侧任务管理面板；
- AI 按顺序执行子任务，每个任务的执行过程（思考、工具调用、结果）显示在中间对话面板；
- 右侧工具面板提供编辑器、文档、浏览器等工具，AI 可调用这些工具完成实际操作；
- 用户可在任意节点干预：修改任务、暂停执行、调整结果、插入新需求；
- 工具面板快捷键 `Ctrl+Alt+/`（macOS: `Option+Cmd+/`）展开/收起。

**设计精髓**：
- SOLO 模式把"AI 自主执行"从一个功能升级为 **一种完整的工作台范式**——不是"AI 在侧边栏回答问题"，而是"AI 在一个独立的三栏工作台里自主完成任务，人在旁边监督和干预"；
- **任务管理面板是"AI 工作的可观测层"**——用户能看到 AI 拆了什么任务、做到哪一步、下一步是什么、哪些任务有依赖，消除了"AI 黑箱"焦虑；
- **工具面板是"AI 能力的执行层"**——AI 不是只说话，而是能真正操作编辑器、浏览器、终端，完成实际工作，产出物直接在工具面板中可见；
- **对话面板是"人机协商层"**——用户可以随时插话、修改需求、纠正方向，AI 会根据新输入调整任务计划。

**对昆仑引擎的映射（核心参考）**：
- SOLO 模式 → **"AI 自主写作模式"**：用户说"帮我写完第一卷"，AI 自主拆解为"完善世界观→生成卷大纲→生成第1章大纲→写第1章正文→53维审计→修改→写第2章→..."，左侧显示任务进度和依赖，中间显示 AI 思考和生成过程，右侧工具面板显示正在写的正文/人物卡/大纲；
- 任务管理面板 → **"写作管线任务看板"**，每个子任务可暂停、修改、跳过、重跑，任务间依赖关系可视化（如"第2章大纲依赖第1章正文完成"）；
- 工具面板 → **"AI 可调用的写作工具集"**：正文编辑器、大纲编辑器、人物卡编辑器、世界观编辑器、审计工具、导出工具，AI 操作这些工具时用户可实时看到产出。

#### 3.1.4 上下文感知与多模态

- 拖拽文件到 AI 对话输入框，自动附加为上下文；
- 支持图片输入（设计稿、草图），AI 可理解视觉内容并生成代码；
- AI 自动感知当前打开的文件、选中的代码、项目结构，无需手动附加；
- 对话历史持久化，跨会话保持上下文。

### 3.2 Cursor — Composer、Agent 与 Tab 预测

Cursor 是 AI-Native IDE 的代表，基于 VS Code 架构，其核心创新在于 **"AI 不只是聊天，而是直接操作编辑器"**。

#### 3.2.1 三栏布局

Cursor 采用与 TRAE 类似的三栏布局：
- 左侧：文件资源管理器、搜索、Git、扩展（标准 VS Code）；
- 中间：代码编辑器；
- 右侧：AI Pane（Chat 或 Composer），`Cmd+L` 切换显示；
- 底部：终端 `Ctrl+``。

#### 3.2.2 三种 AI 交互模式

**Chat（`Cmd+L`）**：
- 侧边栏对话，适合快速提问、代码解释、调试；
- AI 理解整个代码库，可读取文件、回答问题、生成片段；
- 支持 `@文件`、`@代码` 引用，`@Recommended` 语义搜索推荐上下文。

**Composer（`Cmd+I`）**：
- 全屏/侧边栏的 AI 多文件编辑器；
- 与 Chat 的区别：Composer 可以直接编辑多个文件，而 Chat 主要是问答；
- **内联差异（Inline Diff）**：AI 修改的内容在编辑器中高亮显示差异，用户可逐段接受/拒绝；
- 支持 Agent 模式：Composer 中的 Agent 可以自行选择上下文、使用终端、执行命令。

**Agent（`Cmd+.`）**：
- 自主任务执行模式，AI 可以运行终端命令、编辑文件、完成多步骤任务；
- 每个动作可配置为需要人工批准或自动执行；
- 自动生成 Git 提交消息。

#### 3.2.3 Tab：下一步预测

Cursor 的 Tab 功能是 AI IDE 的独特创新：
- AI 预测用户接下来要做什么，主动建议变更；
- Tab 能看到当前任务、最近的变更、相关文件，做出上下文感知的建议；
- 用户按 Tab 接受建议，类似代码补全但粒度更大（可能是整段代码、整个函数）。

**对昆仑引擎的映射**：
- Tab → **"AI 续写预测"**：用户写到段落末尾，AI 主动在后台预测下一段内容，以灰色预览文字显示，按 Tab 接受；不是传统的"调用 AI 续写"，而是"AI 一直在后台预测，随时准备补全"；
- Composer 内联差异 → **"AI 改写的逐段接受/拒绝"**：AI 润色后，每处修改在正文中高亮显示（绿色=新增、红色=删除、黄色=修改），用户可逐段选择保留原文或采用 AI 版本，也可"全部接受""全部拒绝"；
- Agent 模式 → **"AI 自主执行写作任务"**（与 TRAE SOLO 类似）。

#### 3.2.4 多 Agent 并行：Tiled Layout

Cursor 3.0 引入了 Agents Window 的 Tiled Layout：
- 将当前视图拆分为多个窗格，同时运行和管理多个 Agent；
- 每个 Agent 在独立窗格中工作，可并行执行不同任务；
- 支持展开某个窗格聚焦、拖拽 Agent 到不同窗格、快捷键快速切换；
- 布局可保存。

**对昆仑引擎的映射**：
- Tiled Layout → **"多 AI 角色并行创作"**：一个窗格让"架构师 Agent"写大纲，另一个窗格让"写手 Agent"写正文，第三个窗格让"审计师 Agent"检查质量，用户可同时看到三个 Agent 的工作进度和产出，无需切换标签。

### 3.3 Windsurf — Cascade、Flow 状态与检查点

Windsurf（Codeium 团队）的核心理念是 **"不是你指挥 AI，而是 AI 与你并肩流动"**，其 Cascade Agent 是主要 AI 界面，而非附加在编辑器上的侧边栏聊天机器人。

#### 3.3.1 Cascade：融合多工具的 AI 协作系统

Cascade 不是简单的聊天框，而是融合了以下能力的统一 AI 协作流：
- **Code 模式**：AI 直接编辑代码；
- **Chat 模式**：对话问答；
- **工具调用（Tool Calling）**：AI 可调用终端、文件系统、浏览器等工具；
- **语音输入**：支持语音指令；
- **检查点（Checkpoints）**：AI 执行前后自动保存状态，可回滚；
- **实时感知（Real-time Awareness）**：AI 持续感知用户的编辑动作，理解用户意图；
- **Linter 集成**：AI 修改后自动运行 lint，确保代码质量。

#### 3.3.2 Flow 状态：Tab Tab Tab...Ship

Windsurf 强调"Flow"（心流）状态：
- AI 持续提供上下文感知的建议，用户通过连续按 Tab 接受建议；
- 目标是让用户保持在"输入-接受-输入"的流畅节奏中，不被打断；
- Cascade 能"思考 10 步 ahead"，预测用户的完整意图而非仅下一步。

#### 3.3.3 多 Cascade 并行会话

Windsurf Wave 13 引入了多 Cascade 并行：
- 可同时打开多个独立的 Cascade 会话；
- 每个会话处理不同任务（如一个修 bug、一个写新功能），互不干扰；
- 支持多面板/多标签布局。

**对昆仑引擎的映射**：
- Cascade 实时感知 → **"AI 持续感知写作上下文"**：AI 不是等用户调用才工作，而是持续理解用户正在写什么、刚改了什么、当前章节的目标是什么，主动提供建议和预警；
- Checkpoints → **"AI 操作前后自动保存检查点"**：每次 AI 续写/润色/改写前后自动保存版本，可一键回滚到 AI 操作前的状态，这是"AI 改坏了可以还原"的基础保障；
- Flow 状态 → **"写作心流模式"**：AI 预测续写 + Tab 接受，让作者保持"写-接受-写"的流畅节奏，不被"等 AI 生成"的等待打断；
- 多 Cascade 并行 → 同 Cursor Tiled，多 AI 角色并行。

### 3.4 GitHub Copilot Workspace — Spec 驱动的计划-审查-执行

Copilot Workspace 采用独特的 **"Spec 驱动"** 方法，与其他 AI IDE 的"对话驱动"不同，它强调"先规格、再计划、后执行"的结构化工作流。

#### 3.4.1 四阶段工作流

| 阶段 | 人类角色 | AI 角色 |
|------|---------|---------|
| **Issue（需求）** | 编写或审查需求描述 | 理解需求 |
| **Specification（规格）** | 审查和编辑规格文档 | 生成详细规格 |
| **Plan（计划）** | 审查和编辑计划 | 生成逐步执行计划（含涉及文件、命令、测试） |
| **Implementation（执行）** | 监控、可暂停 | 自主执行计划，每步可人工干预 |

#### 3.4.2 关键设计特征

- **规格先行**：不是直接让 AI 写代码，而是先让 AI 生成"完成后代码库应该是什么样"的规格文档，用户审查确认后再生成计划；
- **计划可编辑**：AI 生成的计划列出每个要创建/修改/删除的文件，以及每个文件中的操作步骤，用户可以修改任何部分（增删步骤、调整顺序、修改具体指令）；
- **差异可编辑**：最终生成的 diff 本身可以直接编辑；
- **人工监督每一步**：每个阶段都需要用户确认后才进入下一阶段，AI 不会"一路狂奔"。

#### 3.4.3 Copilot Chat 的 Agent 体系

Copilot Chat 内置多种 Agent：
- **Agent**：自主编码工作流，编辑代码、运行命令、执行任务；
- **Plan**：生成结构化的逐步实现计划；
- **Ask**：问答模式，解释代码库或技术概念；
- **@workspace**：引用整个工作区作为上下文；
- **Agents Panel**：轻量覆盖层，可从任何位置委派任务给 Agent，显示所有 Agent 的进度。

**对昆仑引擎的映射**：
- Spec 驱动 → **"大纲驱动的写作流程"**：不是直接让 AI 写正文，而是先让 AI 生成"本章完成后应该是什么样"的章节规格（场景列表、人物弧光、情绪曲线、伏笔点、字数目标），用户审查确认后再生成章大纲，章大纲确认后再写正文；
- 四阶段工作流 → **"需求→卷大纲→章大纲→正文"** 的结构化写作管线，每个阶段人工审查后才进入下一阶段，避免 AI"写偏了还一路写下去"；
- 计划可编辑 → AI 生成的章大纲可人工修改（增删场景、调整顺序）后再执行正文生成；
- Agents Panel → **"多 Agent 任务委派面板"**，可从任何位置委派任务给不同 Agent（写手/审计师/润色师/设定师），统一查看进度。

### 3.5 通义灵码（Lingma）与 Qoder — 克制的交互设计

通义灵码的交互设计以"克制"为特点，不追求大而全的 AI 面板，而是在用户最自然的操作点上提供 AI 能力。

#### 3.5.1 右键菜单集成

- 在编辑器中选中代码后右键，上下文菜单出现"通义灵码"子菜单；
- 包含代码解释、生成注释、优化建议、生成单测等核心功能；
- 这是最自然、最高频的使用方式，不需要切换面板或记住快捷键。

#### 3.5.2 侧边栏聊天窗口

- 右侧边栏展示灵码会话界面；
- 支持多轮对话、代码引用、文件上下文。

#### 3.5.3 Qoder 的 Editor / Quest 双模式

阿里 Qoder（通义灵码的独立 IDE 版）提供两种工作模式：
- **Editor 模式**：实时协作编程，一问一答，AI 辅助但不自主执行；
- **Quest 模式**：任务委派，自主执行，放手交付，AI 独立完成多步骤任务；
- Quest 任务状态：`Running`（执行中）、`Action Required`（等待操作）、`Ready`（已完成）、`Error`（执行错误）；
- 任务按最后交互时间排序。

**对昆仑引擎的映射**：
- 右键菜单 → **"选中文字后右键 AI 菜单"**：选中一段正文后右键，出现"AI 润色""AI 扩写""AI 改写""检查逻辑""生成对话""解释这段剧情"等选项，这是最高频最自然的交互方式，作者不需要切换面板；
- Editor/Quest 双模式 → **"协作模式/委派模式"**：协作模式是一问一答 AI 辅助（适合精雕细琢），委派模式是把整章/整卷交给 AI 自主完成（适合批量产出）。

### 3.6 百度 Comate — 多模态与元素级交互

Comate AI IDE（文心快码）的核心特色是多模态和元素级交互，在"所见即所得"方向上走得最远。

#### 3.6.1 F2C（设计稿转代码）

- 上传 Figma 设计稿或图片，AI 精准识别图层关系，生成 HTML/CSS 代码；
- 保留全部间距、色值、动效参数；
- 实时双向调试：在预览界面选中元素，说"把标题字号加大"，代码和设计稿同步更新。

#### 3.6.2 元素级点选与修改

- 在预览窗口中用鼠标点击任何 UI 组件或 HTML 元素，Comate 立即定位到对应源代码；
- 可以直接通过对话下达修改指令，实现"所见即所得"的编程；
- 这是 Comate 最具革命性的交互设计——用户不需要在代码中找到对应位置，直接在视觉结果上点选即可。

#### 3.6.3 Zulu 多智能体协同

- Comate 采用多智能体协同架构，不同 Agent 负责不同任务；
- 企业级安全、私域知识增强。

**对昆仑引擎的映射**：
- 元素级点选 → **"正文中的实体级交互"**：在正文中点击人名，立即弹出人物卡并可直接修改；点击地名，定位到世界观设定；点击伏笔标记，显示伏笔追踪状态和回收进度。实现"点哪改哪"的所见即所得写作，作者不需要在人物卡列表中翻找；
- F2C → **"参考图转设定"**：上传人物形象图/场景图/封面草图，AI 生成人物外貌描写/场景描写/封面文案；
- 多智能体 → 同前，多 Agent 协作。

### 3.7 AI Agent 工作台的通用设计模式

综合以上 AI IDE 和 Agent 平台（AgentsRoom、LangGraph Studio、OutSystems Agent Workbench、IronEngine、AgentWeaver 等），可以提炼出 AI Agent 工作台的通用设计模式：

#### 3.7.1 多 Agent 协作的四种架构

| 架构 | 协调方式 | 适用场景 | 对写作工具的映射 |
|------|---------|---------|----------------|
| **Supervisor（主管）** | 一个主管 Agent 分解任务、委派给专家 Agent、综合结果 | 开放式创作，需要统一协调 | 主编 Agent 协调架构师/写手/审计师/润色师 |
| **Handoff（交接）** | Agent 间动态委托，一次只有一个活跃 Agent | 任务中合适的专家自然浮现 | 写手写完后交接给审计师，审计后交接给润色师 |
| **Group Chat（群聊）** | 多 Agent 在共享线程中对话，聊天管理器控制顺序 | 头脑风暴、共识构建 | 多 Agent 讨论剧情走向，集体决策 |
| **Workflow（工作流）** | 预定义的步骤流程，Agent 按步骤执行 | 可重复的多步骤过程 | 固定的写作管线（大纲→正文→审计→润色） |

#### 3.7.2 Agent 状态展示

Agent 工作台必须展示每个 Agent 的实时状态，让"AI 在做什么"可观测：
- **状态标签**：Running（执行中）、Waiting（等待输入）、Done（已完成）、Error（出错）、Paused（已暂停）；
- **进度指示**：当前任务的完成百分比、已执行步骤数、预计剩余时间；
- **思考过程可视化**：可折叠的推理轨迹（Thinking blocks），显示 Agent 的分析过程和决策理由；
- **工具调用徽章**：显示 Agent 调用了什么工具、参数是什么、结果如何；
- **干预提示**：当 Agent 需要人工决策时，高亮提示"Action Required"，并闪烁对应 Agent 卡片。

#### 3.7.3 任务编排面板

- **DAG 视图**：有向无环图展示任务间的依赖关系，哪个任务依赖哪个任务的产出；
- **任务列表视图**：扁平化的待办列表，显示每个任务的负责 Agent、状态、优先级；
- **拖拽重排**：可拖拽调整任务顺序、依赖关系；
- **批量操作**：批量暂停/取消/重跑任务；
- **时间线视图**：按时间顺序展示任务执行历史。

#### 3.7.4 四区操作控制台（Operator Console）

部分 Agent 编排平台（如 AgentWeaver）采用四区控制台布局，其心智模型是：**"树选范围、图解释执行、会话看历史、输入发指令"**：

| 区域 | 职责 |
|------|------|
| **树（Tree）** | 选择作用范围（哪个项目、哪个任务、哪个 Agent） |
| **图（Graph）** | 解释执行过程（DAG 可视化，当前执行到哪个节点） |
| **会话（Session）** | 显示发生了什么（对话日志、工具调用、产出物） |
| **输入（Input）** | 一个输入框向协调器发消息，随时插入新指令 |

这种四区设计是 Agent 工作台的成熟范式，比单纯的"聊天框+日志"更适合复杂的多步骤 Agent 任务。

#### 3.7.5 检查点与回滚

- Agent 执行前后自动保存检查点（Checkpoint）；
- 可回滚到任意检查点；
- 可从检查点创建分支（并行探索不同方案）；
- 检查点可打标签（如"大纲确认后""审计通过后""定稿前"）。

#### 3.7.6 人工干预点（Human-in-the-loop）

- Agent 在关键决策点自动暂停，请求人工确认；
- 可配置"自动批准"的操作类型（如读取文件、搜索内容）和"需要批准"的操作类型（如删除章节、大规模改写正文、覆盖人物设定）；
- 干预界面显示：Agent 想做什么、为什么、可能的影响，用户选择批准/拒绝/修改指令。

## 四、可迁移到网文创作工作台的 IDE 设计模式清单

以下每条按 **"IDE 中的做法 → 迁移到写作工具的具体形态 → 价值"** 三段式呈现。优先级标注：★★★ 核心必做、★★ 强烈建议、★ 可选增强。

### 4.1 命令面板在写作工具中的应用 ★★★

**IDE 中的做法**：VS Code `Ctrl+Shift+P` / JetBrains `Ctrl+Shift+A`，所有操作注册为命令，模糊搜索 + 快捷键提示 + 最近使用排序。

**迁移到写作工具的具体形态**：
- 全局 `Ctrl+Shift+P` 呼出"创作命令面板"，所有功能统一入口：
  - `章节: 新建章节`、`章节: 写下一章`、`章节: 重命名`
  - `大纲: 生成卷大纲`、`大纲: 调整章节顺序`
  - `人物: 新建人物卡`、`人物: 查找人物`、`人物: 生成人物关系图`
  - `AI: 续写`、`AI: 润色当前段落`、`AI: 生成对话`、`AI: 审校本章`
  - `审计: 运行 53 维质量审计`、`审计: 查看连续性问题`
  - `视图: 切换专注模式`、`视图: 左右分屏`
  - `导出: 导出为 TXT`、`导出: 导出为 EPUB`
- 命令按 `类别: 动作` 命名，类别天然分组；
- 每条命令右侧显示快捷键，用户边用边学；
- 最近使用的命令自动上浮；
- 支持 `>` 前缀切换到"AI 指令模式"（直接输入自然语言指令，AI 解析后执行）。

**价值**：
- 写作工具功能越来越多（大纲/人物/世界观/AI/审计/导出），菜单层级会爆炸，命令面板是 **"功能的统一索引层"**，用户不需要记住菜单位置；
- 键盘流作者可以完全脱离鼠标，保持写作心流；
- 新增功能只需注册一条命令，不需要设计新的 UI 入口，扩展性极强。

### 4.2 分屏多文档：大纲 + 正文 + 人物卡同时编辑 ★★★

**IDE 中的做法**：VS Code `Ctrl+\` 左右分屏、拖拽上下分屏、2x2 网格、编辑器组独立导航；JetBrains Split Right/Down。

**迁移到写作工具的具体形态**：
- 中央编辑区支持任意分屏：
  - **经典三栏**：左侧大纲（章节列表/卷结构）+ 中间正文 + 右侧人物卡/世界观设定；
  - **双栏对照**：左侧上一章正文 + 右侧当前章正文（保持文风和上下文连贯）；
  - **三栏创作**：左侧本章大纲/情节卡 + 中间正文 + 右侧 AI 对话/参考资料；
  - **四宫格**：大纲 + 正文 + 人物关系图 + 时间线/伏笔追踪；
- 每个分屏是独立的"编辑器组"，有自己的标签栈和滚动位置；
- 拖拽标签到分屏边缘即可拆分，`Ctrl+\` 快速左右拆分；
- 支持"同步滚动"：两个正文编辑器可绑定滚动，对照上下章时保持行对齐；
- 分屏布局可保存为"工作区预设"（如"大纲模式""创作模式""审校模式"），一键切换。

**价值**：
- 网文创作的核心痛点是 **"多上下文切换"**：写正文时需要频繁查看大纲、人物设定、前文、伏笔。传统单编辑器 + 弹窗切换会不断打断心流；
- 分屏把所有需要的上下文同时铺在眼前，**"看一眼就够"**，不需要跳转；
- 这是 IDE 经过 20 年验证的"多上下文并行"范式，直接迁移即可。

### 4.3 底部面板：AI 对话 / 审校结果 ★★★

**IDE 中的做法**：VS Code 底部面板多 Tab（终端/问题/输出/调试控制台），可收起 `Ctrl+J`，异步反馈聚合层。

**迁移到写作工具的具体形态**：
- 底部面板默认包含以下 Tab：
  - **AI 对话**：与 AI 助手的对话窗口，支持选中正文后"问 AI"（如"这段对话是否符合人物性格"），结果显示在底部；
  - **审校结果**：53 维质量审计 + 8 门禁 + 连续性审计的结果列表，按严重程度分组（错误/警告/建议），点击跳转到正文对应位置；
  - **AI 输出**：AI 续写/润色/生成的原始输出日志，可对比多个版本（抽卡结果）；
  - **管线运行**：全管线自动写作的进度日志（架构→大纲→人物→正文→审计）；
  - **终端/命令**：高级用户的命令行入口（可选）；
- 面板可 `Ctrl+J` 一键收起/展开，写作时隐藏，需要时呼出；
- 审校结果支持"固定问题"：标记为"已确认"的问题不再重复提示；
- AI 对话支持"引用正文"：选中正文后提问，自动将选中文本作为上下文附加到对话中。

**价值**：
- AI 对话和审校结果是 **"异步反馈"**——用户发出请求后，结果在后台返回，不应该弹窗打断正文输入；
- 底部面板是"反馈的聚合层"，所有 AI 输出和审计结果统一管理，不会散落各处；
- 可收起设计保证了"写作时零干扰，需要时一键到达"。

### 4.4 状态栏：实时字数 / 质量分 ★★★

**IDE 中的做法**：VS Code 状态栏显示行列号、编码、语言、Git 分支、错误警告数，每项可点击跳转。

**迁移到写作工具的具体形态**：
- 底部状态栏从左到右显示：
  - **当前卷/章**：`第一卷 第12章`，点击打开章节导航；
  - **实时字数**：`本章 3,247 字 / 目标 3,000`，超出目标时变色提示；
  - **全书总字数**：`全书 128,540 字`；
  - **写作速度**：`今日 +2,340 字 / 12 字/分钟`（基于本次会话输入速率）；
  - **质量分**：`质量 87/100`，点击打开 53 维审计详情；低于阈值时变红；
  - **门禁状态**：`8/8 门禁通过` 或 `2 项未通过`，点击查看；
  - **AI 模型**：`DeepSeek-V3`，点击切换模型；
  - **保存状态**：`已保存` / `未保存的修改`；
  - **当前光标位置**：`第 12 段 / 第 34 句`（替代代码的行列号）。
- 每项可点击跳转到对应详情面板；
- 可配置显示/隐藏哪些项（右键状态栏自定义）。

**价值**：
- 状态栏是 **"零交互信息层"**，用极小空间传递最关键的创作状态，作者不需要打开任何面板就能知道"写了多少、质量如何、门禁过没过"；
- 实时字数和质量分是网文作者最关心的两个指标，放在状态栏形成 **"持续反馈闭环"**，激励写作；
- 可点击设计让每项信息都是"入口"，不是死数据。

### 4.5 活动栏 + 侧边栏：多视图切换 ★★★

**IDE 中的做法**：VS Code 活动栏（最左图标条）+ 主侧边栏（视图容器），点击图标切换侧边栏内容；二级侧边栏可放 Chat。

**迁移到写作工具的具体形态**：
- 最左侧活动栏图标（从上到下）：
  - 📚 **书籍/大纲**：卷章节树、大纲视图、情节卡；
  - 👤 **人物**：人物列表、人物卡、人物关系图；
  - 🌍 **世界观**：设定文档、地点、势力、物品、功法；
  - 🔍 **搜索**：全文检索、人物名/伏笔/设定搜索；
  - ✅ **版本/历史**：章节版本、Local History、回滚；
  - 🤖 **AI 技能**：写作技能/模板/扩展市场；
  - ⚙️ **设置**：项目设置、用户设置；
- 主侧边栏根据选中图标渲染对应视图；
- 右侧二级侧边栏默认放 **AI 对话** 或 **人物卡速览**，可拖拽其他视图过来；
- 每个视图内部有可折叠的子面板（如人物视图内有"人物列表""关系图""出场统计"），可拖拽重排。

**价值**：
- 网文创作涉及 **书籍/人物/世界观/大纲/伏笔** 等多个项目级维度，每个维度都需要独立的浏览空间；
- 活动栏 + 侧边栏的"一个位置切换多个视图"模式，避免了窗口碎片化，所有项目级上下文都在左侧统一管理；
- 二级侧边栏让 AI 对话常驻右侧，写正文时随时可问，不占主编辑区。

### 4.6 快速打开：章节/人物/设定快速跳转 ★★★

**IDE 中的做法**：VS Code `Ctrl+P` 文件模糊打开、`@` 符号导航、`:` 行号跳转、`#` 全局符号。

**迁移到写作工具的具体形态**：
- `Ctrl+P` 呼出"快速打开"：
  - 直接输入 → 模糊搜索章节标题（如输入"12"匹配"第12章"，输入"觉醒"匹配所有含"觉醒"的章节）；
  - `@` 前缀 → 当前章节内导航（场景/段落标记，如 `@场景3`、`@高潮`）；
  - `:` 前缀 → 跳转到段落号（如 `:45` 跳到第 45 段）；
  - `#` 前缀 → 全局搜索人物/设定/伏笔（如 `#叶凡` 跳转到人物卡，`#青铜仙殿` 跳转到设定文档）；
  - `>` 前缀 → 切换到命令面板模式；
- 搜索结果显示摘要（章节前 50 字 / 人物一句话描述），帮助识别；
- 最近打开的章节/人物自动上浮。

**价值**：
- 网文动辄数百章、数十个人物、上百条设定，**"找到目标"本身就是成本**；
- 快速开是"导航的统一入口"，章节、人物、设定、段落都在一个输入框里完成，靠前缀区分语义；
- 模糊搜索降低了记忆负担，作者不需要记住精确的章节号或人物全名。

### 4.7 Peek 预览：人物卡/设定/前文内联查阅 ★★

**IDE 中的做法**：VS Code Peek Definition / Peek References，内联弹出小编辑器，不离开当前上下文。

**迁移到写作工具的具体形态**：
- 在正文中选中或悬停人名 → `Alt+F12`（或点击悬浮卡片的"预览"）→ 内联弹出人物卡预览，显示姓名、性格、外貌、当前状态、与 POV 角色关系；
- 选中设定名词（如"青铜仙殿""源天师"）→ 内联弹出设定文档预览；
- 选中"前文提到的事件"→ 内联弹出前文章节片段预览（基于知识图谱的引用追踪）；
- 预览窗口可直接编辑人物卡/设定，关闭后回到正文原位置；
- 支持"Peek 引用"：选中人名后显示该人物在所有章节的出场片段列表，点击内联预览。

**价值**：
- 网文写作中最频繁的查阅是 **"这个人是谁、这个设定是什么、前文怎么写的"**；
- 传统"跳转-查阅-返回"会丢失当前写作位置和思路，Peek 把查阅嵌入当前视图，**保持心流不中断**；
- 可直接编辑的预览让"查阅时顺手修正"成为可能，减少了人物设定与正文不一致的问题。

### 4.8 TODO 窗口：伏笔/待办/修订标记全局追踪 ★★

**IDE 中的做法**：JetBrains TODO 窗口自动扫描 `TODO`/`FIXME` 注释，多 Tab 分类，点击跳转，自定义模式。

**迁移到写作工具的具体形态**：
- 在正文中用特殊标记语法（如 `{{伏笔:青铜仙殿的秘密}}`、`{{待修订:这段对话需要更符合人物性格}}`、`{{待查:此处历史时间线是否一致}}`）标记；
- 底部面板或侧边栏的"TODO/伏笔"窗口自动聚合所有标记：
  - **全项目**：所有标记按类型分组（伏笔/待修订/待查/已完成）；
  - **当前章节**：仅当前章的标记；

### 4.23 SOLO / AI 自主写作模式 ★★★

**IDE 中的做法**：TRAE SOLO 模式将界面变为"任务管理面板 + AI 对话面板 + 工具面板"三栏，AI 自主拆解任务、调用工具执行，人在旁监督干预。

**迁移到写作工具的具体形态**：
- 左上角模式切换："协作模式" ↔ "SOLO 自主模式"；
- SOLO 模式下界面变为三栏：
  - **左侧任务管理面板**：AI 拆解的写作子任务列表（完善世界观→生成卷大纲→写第1章→审计→修改→写第2章...），显示每个任务的状态、依赖、进度；
  - **中间 AI 对话面板**：AI 的思考过程、生成结果、与用户的协商，用户可随时插话修改需求；
  - **右侧工具面板**：AI 正在操作的工具（正文编辑器/大纲编辑器/人物卡编辑器/审计工具），产出物实时可见；
- 用户可暂停任意任务、修改任务内容、跳过某步、插入新需求；
- 关键节点（如大纲确认、正文定稿）自动暂停请求人工确认。

**价值**：
- SOLO 模式是"AI 批量产出"的核心范式——用户说"帮我写完第一卷"，AI 自主执行数十个子任务，用户只需在关键节点审查；
- 任务管理面板让"AI 在做什么、做到哪一步"完全可观测，消除黑箱焦虑；
- 工具面板让 AI 的产出物实时可见，用户可以"边看边改"，而不是等 AI 全部做完才看到结果。

### 4.24 行内对话与内联差异（Inline Diff）★★★

**IDE 中的做法**：Cursor Composer 支持行内对话（选中代码直接提问，结果在代码附近显示）和内联差异（AI 修改内容高亮，逐段接受/拒绝）。

**迁移到写作工具的具体形态**：
- **行内对话**：选中一段正文后，直接在正文附近弹出 AI 输入框（不切换到侧边栏），输入"这段对话太生硬，改得自然些"，AI 结果在选中段落下方内联显示；
- **内联差异**：AI 润色/改写后，正文中高亮显示每处修改——绿色=新增、红色=删除、黄色=改写；
- 每处修改旁有"接受/拒绝"按钮，也可"全部接受""全部拒绝""仅接受高亮处"；
- 支持多版本对比：AI 抽卡生成的多个版本以内联差异方式并排对比。

**价值**：
- 行内对话让"改这段"的操作零跳转——选中、提问、看到结果，都在同一个位置完成，不打断写作心流；
- 内联差异让 AI 改写"可审查、可选择"，作者不会被迫"要么全用要么全不用"，可以逐段决定；
- 这是 AI 改写从"黑箱替换"到"透明协作"的关键交互设计。

### 4.25 Tab 续写预测与 Flow 心流 ★★

**IDE 中的做法**：Cursor Tab 预测用户下一步操作，灰色预览，按 Tab 接受；Windsurf Flow 状态让用户保持"输入-接受-输入"的流畅节奏，AI 思考 10 步 ahead。

**迁移到写作工具的具体形态**：
- 用户写到段落末尾时，AI 在后台主动预测下一段内容，以灰色预览文字显示在光标后；
- 按 `Tab` 接受预测，按 `Esc` 拒绝，继续打字则自动覆盖；
- 预测基于当前章节大纲、前文风格、人物设定，不是随机生成；
- "Flow 模式"：开启后 AI 持续预测，作者保持"写- Tab -写- Tab"的流畅节奏，AI 像"副驾驶"一样持续补全；
- 可配置预测粒度（下一句/下一段/下一场景）。

**价值**：
- Tab 预测把"等 AI 生成"的等待时间消除——AI 在用户打字时就在后台预测，用户需要时按 Tab 即可；
- Flow 模式让 AI 从"按需调用"变为"持续协作"，大幅提升写作速度；
- 这是"AI 副驾驶"理念的核心体现——AI 不抢方向盘，但随时准备帮忙。

### 4.26 多 Agent 并行面板 ★★

**IDE 中的做法**：Cursor Tiled Layout / Windsurf 多 Cascade 并行，将视图拆分为多个窗格，每个窗格运行一个独立 Agent，并行执行不同任务。

**迁移到写作工具的具体形态**：
- "多 Agent 模式"下，编辑区可拆分为多个窗格，每个窗格运行一个独立 AI Agent：
  - 窗格 1：架构师 Agent 正在生成下一卷大纲；
  - 窗格 2：写手 Agent 正在写当前章正文；
  - 窗格 3：审计师 Agent 正在检查上一章的连续性问题；
  - 窗格 4：润色师 Agent 正在润色已完成的章节；
- 每个 Agent 窗格显示其状态（运行中/等待/完成）、当前任务、产出预览；
- 支持展开某个窗格聚焦、拖拽 Agent 到不同窗格、保存布局预设；
- Agent 间可通过"共享草稿板"传递产出（如架构师的大纲自动传递给写手）。

**价值**：
- 网文创作是多角色协作（架构/写作/审计/润色），多 Agent 并行让这些角色同时工作，而不是串行等待；
- 用户可以同时看到多个 Agent 的工作进度，像"编辑部主任"一样统筹全局；
- 这是从"单 AI 助手"到"AI 创作团队"的范式升级。

### 4.27 Spec / 大纲驱动的计划-审查-执行 ★★★

**IDE 中的做法**：GitHub Copilot Workspace 采用四阶段工作流（Issue→Specification→Plan→Implementation），每阶段人工审查后才进入下一阶段，计划可编辑，差异可编辑。

**迁移到写作工具的具体形态**：
- 写作管线采用"大纲驱动"的四阶段工作流：
  1. **需求（Issue）**：用户描述"写第 12 章，主角进入青铜仙殿，发现身世线索"；
  2. **规格（Specification）**：AI 生成本章规格——场景列表、人物弧光、情绪曲线、伏笔点、字数目标、与前后章的衔接，用户审查修改；
  3. **计划（Plan）**：AI 生成章大纲——逐场景的情节要点、对话要点、描写要点，用户审查修改（增删场景、调整顺序）；
  4. **执行（Implementation）**：AI 按大纲生成正文，用户监控、可暂停、可介入；
- 每个阶段必须用户确认后才进入下一阶段，AI 不会"跳过大纲直接写正文"；
- 规格和计划都是可编辑的文档，不是只读的 AI 输出。

**价值**：
- "先规格、再计划、后执行"避免了 AI"写偏了还一路写下去"的常见问题——每一步都有人工审查节点；
- 大纲驱动是网文创作的最佳实践（先有大纲再写正文），AI IDE 的 Spec 驱动模式与这一实践完美契合；
- 可编辑的规格/计划让"AI 辅助构思"成为可能，而不是"AI 替你决定一切"。

### 4.28 Agent 状态展示与任务编排面板 ★★

**IDE 中的做法**：AI Agent 工作台通用模式——展示每个 Agent 的实时状态（Running/Waiting/Done/Error）、进度、思考过程、工具调用；DAG 视图展示任务依赖。

**迁移到写作工具的具体形态**：
- "Agent 面板"（可放在侧边栏或底部）显示所有活跃 Agent 的状态卡片：
  - 每个卡片显示：Agent 名称（写手/审计师/润色师）、当前任务、状态标签、进度条、已用时间；
  - 点击卡片展开详情：思考过程（可折叠）、工具调用记录、产出物预览；
  - "Action Required"状态的卡片高亮闪烁，提示用户需要人工干预；
- "任务编排视图"：DAG 图展示写作管线中各任务的依赖关系（如"第2章正文依赖第2章大纲，第2章大纲依赖第1章正文"），当前执行到哪个节点高亮；
- 支持拖拽调整任务顺序、暂停/取消/重跑任务。

**价值**：
- Agent 状态展示让"AI 在做什么"完全透明，用户不会面对"AI 卡住了还是在思考"的困惑；
- DAG 任务编排让复杂的多步骤写作管线可视化，用户可以理解"为什么第 3 章还没开始写"（因为它依赖第 2 章的审计结果）；
- 这是从"AI 是黑箱"到"AI 是可观测的协作伙伴"的关键设计。

### 4.29 检查点与 AI 操作回滚 ★★

**IDE 中的做法**：Windsurf Cascade 在 AI 执行前后自动保存 Checkpoints，可回滚到任意检查点，可从检查点创建分支。

**迁移到写作工具的具体形态**：
- 每次 AI 操作（续写/润色/改写/批量生成）前后自动保存检查点；
- 检查点列表显示：操作类型、时间、AI 模型、字数变化、操作摘要；
- 一键回滚到任意检查点（"AI 润色前"状态）；
- 可从检查点创建"分支版本"——从某个历史版本出发，尝试不同的写作方向，不覆盖当前版本；
- 重要节点可手动打标签（如"大纲确认后""审计通过后""定稿前"）；
- 检查点与 Local History 互补：Local History 记录所有手动保存，检查点专门记录 AI 操作。

**价值**：
- AI 改写有风险——可能改坏了、可能改偏了、可能不如原版。检查点让"AI 操作可回滚"成为基础保障，作者可以放心让 AI 尝试；
- 分支版本让"并行探索不同写法"成为可能——从同一个检查点出发，让 AI 生成两个不同版本的高潮场景，对比后选择；
- 这是"AI 试错无成本"的基础设计。

### 4.30 右键上下文 AI 菜单 ★★★

**IDE 中的做法**：通义灵码将 AI 能力集成到右键菜单——选中代码后右键，出现"通义灵码"子菜单，包含解释、生成注释、优化等，这是最高频最自然的交互方式。

**迁移到写作工具的具体形态**：
- 选中一段正文后右键，上下文菜单出现"AI 创作"子菜单：
  - **AI 润色**：优化语言表达，保持原意；
  - **AI 扩写**：将简略描写扩展为详细描写；
  - **AI 改写**：换一种风格/视角重写；
  - **AI 续写**：基于选中内容继续写；
  - **检查逻辑**：检查这段是否有逻辑矛盾/设定冲突；
  - **生成对话**：将叙述改为对话形式；
  - **解释剧情**：AI 分析这段的剧情作用和人物弧光；
  - **翻译/文言文化**：风格转换；
- 菜单选项根据选中内容的类型智能变化（选中对话时优先显示"优化对话"，选中描写时优先显示"扩写描写"）。

**价值**：
- 右键菜单是"零学习成本"的 AI 入口——作者不需要记住快捷键或切换面板，选中文字后右键就能找到所有 AI 操作；
- 这是最高频的 AI 交互场景（"改这段"），放在右键菜单比放在侧边栏对话更直接；
- 智能变化的菜单选项让 AI 能力"在需要的地方出现"，而不是堆满整个界面。

### 4.31 实体级点选与修改 ★★

**IDE 中的做法**：百度 Comate 支持元素级点选——在预览窗口中点击任何 UI 元素，立即定位到对应源代码，可直接对话修改。

**迁移到写作工具的具体形态**：
- 正文中的"实体"（人名、地名、物品名、功法名、组织名）自动识别并可点击；
- 点击人名 → 弹出人物卡速览（性格、外貌、当前状态、与 POV 角色关系），可直接编辑；
- 点击地名 → 弹出世界观设定卡（位置、势力、历史、相关事件），可直接编辑；
- 点击伏笔标记 → 弹出伏笔追踪卡（埋设章节、计划回收章节、当前状态），可直接更新；
- 点击后可直接在弹出卡片中说"把这个人物的性格改成更腹黑"，AI 同步修改人物卡和正文中的相关描写；
- 实现"点哪改哪"的所见即所得写作。

**价值**：
- 网文涉及数十个人物、上百条设定，作者在正文中看到一个名字时，经常需要"这个人是谁来着"——实体级点选让查阅零跳转；
- "点选即修改"让设定维护与正文写作同步进行，不会出现"正文改了但人物卡没更新"的不一致；
- 这是知识图谱与正文编辑器深度集成的最佳交互方式。

### 4.32 四区操作控制台 ★

**IDE 中的做法**：AgentWeaver 等 Agent 编排平台采用四区控制台——树选范围、图解释执行、会话看历史、输入发指令。

**迁移到写作工具的具体形态**：
- "AI 创作控制台"模式（适合全管线自动写作场景）采用四区布局：
  - **左树（范围选择）**：书籍/卷/章/任务树，选择当前操作范围；
  - **上图（执行解释）**：DAG 图展示写作管线执行状态，当前节点高亮；
  - **右会话（历史记录）**：AI 对话日志、工具调用记录、产出物时间线；
  - **底输入（指令输入）**：一个输入框，随时向 AI 协调器发指令（如"暂停第 3 章""把第 2 章的风格改成更轻松"）；
- 四区可调整大小、可折叠，用户可根据需要聚焦某个区域。

**价值**：
- 四区控制台是复杂多步骤 Agent 任务的成熟范式，比"聊天框+日志"更适合全管线自动写作；
- "树选范围、图看执行、会话查历史、输入发指令"的心智模型清晰，用户随时知道"我在操作什么、AI 在做什么、发生过什么、我能说什么"；
- 适合"批量创作"场景——用户同时管理多本书、多卷的 AI 写作管线。

## 六、设计原则提炼

从传统 IDE（VS Code / JetBrains）和 AI IDE（TRAE / Cursor / Windsurf / Copilot Workspace 等）的设计中，可以提炼出适用于 AI 网文创作工作台的核心原则：

1. **以编辑器为中心**：所有 UI 都是为正文创作服务的，可隐藏、可收起、不抢焦点。
2. **以命令为总线**：所有操作注册为命令，命令面板是统一入口，功能再多也不迷路。
3. **多上下文并行**：分屏是一等公民，大纲/正文/人物/设定同时可见，减少跳转。
4. **异步反馈聚合**：AI 输出、审计结果、管线日志统一放底部面板，不打断写作。
5. **零交互信息层**：状态栏用极小空间传递关键状态，每项可点击成为入口。
6. **零成本安全网**：Local History 自动快照，AI 修改前后自动保存，试错无风险。
7. **可扩展的生态**：扩展/技能市场 + 贡献点机制，内核做基础，社区做垂直。
8. **键盘优先**：完整的快捷键体系 + Chord + 上下文快捷键，高频作者全键盘操作。
9. **心流保护**：专注模式 + Peek 预览 + 可收起面板，一切为了不打断写作节奏。
10. **配置即数据**：所有设置都是 JSON，UI 和 JSON 双轨，用户/工作区分层。
11. **AI 作为一等公民**：AI 对话面板默认常驻右侧，不是隐藏的辅助功能；AI 感知当前上下文，无需手动附加。
12. **AI 工作可观测**：任务拆解、执行进度、思考过程、工具调用全部可视化，消除"AI 黑箱"焦虑；Agent 状态实时展示。
13. **人工在环（Human-in-the-loop）**：关键决策点自动暂停请求确认，可配置自动批准/需批准的操作类型；AI 生成但人可控。
14. **多 Agent 协作**：不同角色 Agent（架构师/写手/审计师/润色师）可并行或串行工作，通过共享草稿板传递产出，从"单 AI 助手"升级为"AI 创作团队"。
15. **AI 操作可回滚**：每次 AI 操作前后自动保存检查点，可一键回滚、可分支探索，让"AI 试错无成本"。

这些原则不是 IDE 独有的，而是 **"面向长时间、高频、多上下文、多阶段、AI 协作的创造性工作"** 的通用工作台设计范式。AI 网文创作完全符合这一描述——它既有传统写作的"长时间高频输入"特征，又有 AI 协作的"多 Agent、多阶段、可观测"需求，因此传统 IDE 与 AI IDE 的设计模式都具有极高的迁移价值。
