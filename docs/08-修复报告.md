### A.2.1 InkOS — 架构最相似的标杆项目

**仓库**: `Narcooo/inkos` (6,700+ Stars) | **许可证**: MIT | **安装**: `npm i -g @actalk/inkos`

```
10 Agent 接力管线：
Radar → Planner → Composer → Architect → Writer
  → Observer → Reflector → Normalizer → Auditor → Reviser
```

**昆仑可直接借鉴的核心设计**:

| InkOS 特性 | 昆仑对应 | 差距分析 |
|-----------|---------|---------|
| **7 真相文件** + JSON Schema (Zod) 校验 | 7 truth files (仅JSON) | ❌ 昆仑无 schema 校验层，坏数据可能滚雪球 |
| **Observer + Reflector** 分离（提取事实→出JSON delta→代码层immutable写） | 直接写 truth files | ❌ 缺少提取-校验-写入的分离管线 |
| **11条写后验证规则**（零LLM，纯确定性） | 无 | ❌ 昆仑缺少确定性后写检查 |
| **SQLite 时序记忆** (Node 22+) 解决上下文膨胀 | 无（全量注入KG快照） | ❌ 长文瓶颈 |
| **输入治理控制面** (author_intent/current_focus/chapter_intent 分层) | EditorInChief 有相似概念 | ⚠️ 实现不完整 |
| **33维度审计** (temperature=0) | 33维 audit (同步调用) | ⚠️ 昆仑33维审计无temperature控制且阻塞事件循环 |
| **AI痕迹检测** (段落CV/套话密度/公式化转折/列表式) | G3门禁(仅连词密度) | ❌ 昆仑AI检测维度少 |
| **Composer Agent** (从全量真相文件中按相关性选上下文) | 无（Architect 直接RAG检索） | ⚠️ 缺少专门的上下文编排层 |
| **4种修订模式** (spot-fix/rewrite/polish/anti-detect) | 仅简单修订 | ❌ 修订策略单一 |

**InkOS 的糟粕（应避免）**:
- API 成本极高（每章大量 token 消耗）
- 学习曲线陡峭（初次配置需 30-60 分钟）
- `rewrite` 模式实测引入 6 倍 AI 标记
- 对免费/本地模型支持不佳

### A.2.2 SAGA — 知识图谱架构标杆

**仓库**: `Lanerra/saga` | **技术栈**: Python 3.12 + LangGraph + Neo4j 5.x

```
两层工作流：
Phase 1 (初始化): 角色表 → 全局大纲 → 幕大纲 → 提交到图谱 → 持久化文件
```

**昆仑可直接借鉴的核心设计**:

| SAGA 特性 | 价值 |

| **Cypher 注入防护** (白名单+正则+参数化) | 昆仑 routes.py 已有部分实现，但 kg/client.py SQLite 解析器无防护 |
| **idempotent MERGE** | 所有持久化使用 MERGE 语义，重跑章节确定性替换关系 |

**SAGA 的糟粕**:
- 非生产就绪（项目自述有已知严重问题）

- LangGraph checkpoint 机制复杂，调试困难

## A.6 关键教训（糟粕避让）

| 教训 | 来源 | 说明 |
|------|------|------|
| **rewrite > spot-fix** | InkOS 实测 | 全文重写引入 6x AI 标记，应默认 spot-fix |
| **全量上下文不可扩展** | InkOS 20章后 | 20章后全量注入导致 API 400 错误，必须用检索替代 |
| **Neo4j 强制依赖风险** | SAGA | 无降级方案导致部署门槛高。昆仑的 SQLite 降级是正确方向 |
| **Commons Clause 限制** | PlotPilot | 非商用许可证限制生态发展。昆仑应保持 MIT |
| **供应商锁定风险** | NovelForger (Gemini only) | 昆仑的多 provider 支持是正确的 |
| **单文件 JSON 膨胀** | Novel-OS | 长篇小说 JSON state 文件可能极大。应参考 SAGA 的 ContentRef 外部化 |
| **假流式无意义** | 昆仑 streaming.py | 完整响应后再切 chunk 失去流式 UX 价值 |
| **模型实例碎片化** | 昆仑 GachaEngine | 多实例导致 last_best_model 状态不一致。统一单例 |

```python
# WenShape select_engine.py 核心算法
# 昆仑 rag.py 应重写为此实现:

def hybrid_score(candidate, query, entity_names):
    """混合评分: BM25×0.4 + 词重叠×0.3 + 实体增强×0.3"""
    bm25 = compute_bm25(candidate, query)      # 标准BM25
    overlap = jaccard_overlap(candidate, query) # 词重叠Jaccard
    entity_boost = sum(1 for e in entity_names if e in candidate) / len(entity_names)
    
    return 0.4 * bm25 + 0.3 * overlap + 0.3 * entity_boost

def bm25_score(doc, query, avg_doc_len, k1=1.5, b=0.75):
    """标准BM25实现（修正昆仑rag.py的错误）"""
    score = 0.0
    doc_len = len(doc.split())
    for term in query.split():
        # 关键修正: tf = 词在文档d中的频率（不是查询中）
        tf = doc.split().count(term)
        idf = compute_idf(term)
        numerator = tf * (k1 + 1)
        denominator = tf + k1 * (1 - b + b * doc_len / avg_doc_len)
        score += idf * numerator / denominator
    return score
```

#### 2. 对数型距离衰减

```python
# WenShape distance_decay.py
# 昆仑应采纳: 在检索上下文时按章节距离衰减权重

def log_distance_decay(chapter_distance: int) -> float:
    """对数型衰减: 越接近当前章节权重越高"""
    if chapter_distance <= 0:
        return 1.0
    return 1.0 / (1 + math.log(1 + chapter_distance))
    # 距离1章: 0.59, 距离10章: 0.29, 距离50章: 0.20
    # 关键特性: 远章不会被直接丢弃，重要的世界观事实仍保留低权重

# 昆仑使用场景: kg_client.vector_search() + context_assembly
```
