## 1. AI文本检测工具原理深度解析

### 1.1 国际主流检测工具

| 工具名称 | 核心技术原理 | 检测维度 | 准确率（公开测评） | 成熟度 |
|---------|------------|---------|------------------|--------|
| **GPTZero** | Perplexity（困惑度）+ Burstiness（突发性）双指标模型 | 句子级困惑度变异、句长分布、词汇可预测性 | 英文约85%，中文约60% | ★★★★☆ |
| **Originality.ai** | 微调RoBERTa分类器 + 多模型集成 | 训练数据覆盖GPT-3/4/Claude/PaLM生成文本，n-gram分布、句法树特征 | 英文约94%，中文约55% | ★★★★★ |
| **Turnitin AI检测** | 自研分类器 + 学术语料微调 | 学术写作风格指纹、引用模式、段落结构、词汇多样性 | 英文学术约98%，误报率约5% | ★★★★★ |
| **Copyleaks** | 多语言模型集成 + 语义级分析 | 跨语言检测、语义相似度、写作风格一致性、AI生成概率 | 英文约91%，支持中文但准确率较低 | ★★★★☆ |
| **ZeroGPT** | 基于GPT-2的困惑度分析 + 关键词模式 | 高概率词序列检测、AI高频短语匹配、句长均匀度 | 英文约78%，中文约50%，误报率较高 | ★★★☆☆ |
| **Smodin** | 多模型投票 + 文本指纹 | 集成5+检测器结果投票，降低单一模型偏差 | 英文约85% | ★★★☆☆ |
| **Winston AI** | 深度学习分类器 + 写作风格分析 | 词汇选择模式、句法复杂度、标点使用习惯 | 英文约93% | ★★★★☆ |

**核心原理共性**：所有检测器本质上都是**逆向预测模型**——不做数据库比对，而是计算文本"属于最顺滑概率组合"的可能性。查重系统是"找证据"（非黑即白的事实认定），AI检测系统是"算概率"（统计特征匹配度）。["https://juejin.cn/post/7579628944035790857"]

### 1.3 检测维度全景分析

```
AI文本检测维度体系
├── 统计语言学维度
│   ├── Perplexity（困惑度）：文本可预测性，AI文本偏低（5-25），人类偏高（30-80+）
│   ├── Burstiness（突发性）：句子间困惑度变异系数，AI偏低（<0.3），人类偏高（0.35-0.60）
│   ├── 句长分布CV：AI句长均匀（CV<0.3），人类长短交错（CV>0.5）
│   ├── 词频分布：AI偏好高频词，人类使用更多低频词和意外组合
│   └── N-gram重复度：AI有固定词汇搭配模式，重复度偏高
│
├── 词汇语义维度
│   ├── AI高频词清单：仿佛、似乎、不由得、心中、微微、缓缓、紧紧等
│   ├── 连接词密度：AI过度使用"然而""因此""此外""综上所述"
│   ├── 功能词/实词比：AI功能词占比偏高（>0.40），人类偏低（<0.35）
│   ├── 抽象描述vs具体细节：AI偏好"莫名的""难以言喻的"，人类用具体感官
│   └── 弱动词使用：AI偏好"进行""做出""加以"，人类用具体动作动词
│
├── 句法结构维度
│   ├── 被字句过度：AI偏好被动语态，人类更多主动句
│   ├── 长定语堆叠：AI偏好"的的不休"，人类拆分短句
│   ├── 三段式列举：AI偏好"X、Y、Z"三项分组，人类更随机
│   ├── 排比过度：AI连续句子以相同结构开头
│   └── 双字句首：AI高频以"这就""那是""可以""但是"开头
│
├── 标点格式维度
│   ├── 逗号/分号偏好：AI偏好逗号连接长句，人类更多短句和句号
│   ├── 破折号过度：AI每100字超过1个破折号
│   ├── 感叹号/省略号：AI使用偏少，人类情绪表达时使用较多
│   ├── 冒号解释：AI文档风格过度使用冒号
│   └── 引号强调：AI频繁对普通词汇加引号（非对话）
│
├── 段落篇章维度
│   ├── 段落等长：AI段落长度高度一致（CV<0.25），人类长短不一
│   ├── 三段式结构：严格的引入→分析→总结，比例均匀（偏差<0.08）
│   ├── 模板化开头："在...中""随着...的发展""当...的时候"
│   ├── 模板化结尾："接下来""这一切才刚开始""真正的考验"
│   └── 事事交代：每件事都交代起因经过结果，缺乏留白
│
└── 对话叙事维度
    ├── 对话过于完整：AI对白过长（>100字），缺乏中断/省略
    ├── 缺语气词：AI对话缺"嗯/啊/哦/嘛/啦"等自然语气词
    ├── 完美对话标签：AI用"说道/问道/回答道"，人类用动作替代
    ├── 情感直白标签：AI用"生气地说""冷冷地"，人类通过内容展现
    └── 独白式说明：角色通过对话向另一角色解释已知信息（信息倾销）
```

### 1.4 检测技术的三代演进

| 代际 | 技术路线 | 代表工具 | 核心方法 | 局限性 |
|------|---------|---------|---------|--------|
| **第一代（2023）** | 统计特征法 | GPTZero、ZeroGPT | Perplexity + Burstiness 双指标 | 易被同义词替换和翻译绕过，中文准确率低 |
| **第二代（2023-2024）** | 监督分类法 | Originality.ai、Turnitin、Winston | 微调RoBERTa/BERT分类器，训练AI/Human文本对 | 依赖训练数据覆盖，新模型生成文本检测率下降 |
| **第三代（2024-2026）** | 零样本+水印+多模型集成 | Copyleaks、Fast-DetectGPT、Binoculars | 零样本似然比、生成式统计水印、多检测器投票 | 水印需生成端配合，零样本计算成本高 |

**关键洞察**：任何公开的检测规则都会成为AI学习规避的教程。Wikipedia志愿者花两年整理的24条AI写作特征指南，被Siqi Chen的Humanizer项目直接反向利用——"检测什么，就避免什么"，三天GitHub星标冲到1600+。这意味着检测与规避是永恒的军备竞赛，**降低AI率的核心不是"骗过检测器"，而是"真正写出人类风格的文本"**。["https://www.51cto.com/article/834937.html"]

### 2.2 技术路线分类

#### 路线A：基于规则的改写方法

**原理**：通过预定义的替换规则和结构变换，直接修改文本的表层特征。

**具体方法**：
1. **同义词替换**：AI高频词→人类常用词（如"展现"→"显出/露出/透出"）
2. **句式变换**：被字句→主动句、长定语→短句拆分、书面倒装→正常语序
3. **语序调整**：随机打乱句子内部成分顺序（保持语义不变）
4. **连接词替换**："然而"→"可/不过/但偏偏/谁知"，"因此"→"所以/于是乎/这下"
5. **标点替换**：逗号→句号（拆分长句）、破折号→逗号/句号

**优点**：零LLM成本、速度极快、可复现、不改变核心语义
**缺点**：只能处理表层特征、对深度AI模式无效、可能产生不自然表达
**适用场景**：快速后处理、批量降AI率的第一道工序

#### 路线B：基于LLM的人类化改写

**原理**：通过精心设计的Prompt策略，让LLM以人类风格重写文本。

**具体方法**：
1. **负向提示词（Negative Constraints）**：明确禁止使用AI高频词和句式
   ```
   禁止使用"综上所述""深入探讨""多面手"。
   禁止使用"首先、其次、最后"的列表结构。
   禁止在结尾升华主题。
   句子长度必须长短交替，方差要大。
   ```
2. **角色扮演（Roleplay）**：让LLM扮演特定身份的人类作者
   ```
   你是一个干了10年的老油条，性格直率，嘴有点损。
   你在给哥们写微信。用口语，多用反问句，夹杂点情绪。
   别跟我讲大道理。
   ```
3. **多轮渐进重写**：每轮专注不同维度（第1轮句式→第2轮词汇→第3轮对话）
4. **温度参数调整**：提高temperature（1.1-1.3）增加随机性，降低AI味
5. **特定Prompt模板**：如昆仑已实现的WEBNOVEL_HUMANIZE_SYSTEM_PROMPT

**优点**：效果最好、能处理深度语义层面的AI特征、可定制风格
**缺点**：LLM成本高、可能改变核心语义、结果不稳定、需要多次迭代
**适用场景**：黄金三章、关键章节、对AI率要求极高的场景

#### 路线C：统计特征驱动的改写

**原理**：先计算文本的统计指纹（perplexity/burstiness/句长CV等），然后针对性调整到人类区间。

**具体方法**：
1. **Perplexity提升**：强制插入低概率词、打破高频词序列、增加词汇意外性
2. **Burstiness提升**：合并短句+拆分长句，制造句长方差；调整段落边界打破均匀节奏
3. **句长CV优化**：目标CV=0.55，通过merge（<6字短句）和split（>50字长句）实现
4. **功能词比例调整**：降低"的/了/在/是"等功能词占比，增加具体实词
5. **N-gram去重**：打破重复的词汇搭配模式

**优点**：可量化、可验证、目标明确、与检测原理直接对应
**缺点**：纯统计调整可能产生不自然文本、需要与LLM改写配合
**适用场景**：改写后的验证和微调、批量文本的标准化处理

#### 路线D：翻译链（Translation Hack）

**原理**：通过跨语种翻译破坏文本的统计指纹。翻译过程会重新组织句子结构和词汇选择，从而改变perplexity/burstiness分布。

**具体方法**：
1. **标准3跳**：中文→英文→日文→中文（改变句式结构）
2. **激进4跳**：中文→英文→日文→芬兰语→中文（更彻底破坏统计指纹）
3. **最小2跳**：中文→英文→中文（保真度高，适合关键情节）
4. **小语种洗钱法**：中文→德语→西班牙语→中文（德语改句式，西语加啰嗦）

**优点**：统计指纹破坏彻底、对perplexity/burstiness改变显著
**缺点**：语义偏移风险大、需要多轮LLM调用（成本高）、可能产生翻译腔
**适用场景**：AI率极高的文本、需要彻底重置统计特征的场景

## 4. Perplexity/Burstiness优化技术

### 4.1 Perplexity（困惑度）深度解析

#### 定义与计算

Perplexity衡量语言模型对文本的"惊讶程度"——模型越能准确预测下一个词，困惑度越低。

**数学公式**：
```
PPL = exp(-1/N * Σ log2 P(w_i | w_1...w_{i-1}))
```

其中N为词数，P(w_i | context)为模型给定上下文后预测第i个词的概率。

**简化计算（字符级bigram，零模型依赖）**：
```python
# 昆仑fingerprint.py已实现的近似算法
def _calc_perplexity(text):
    chars = list(text)
    bigrams = Counter()
    for i in range(len(chars) - 1):
        bigrams[chars[i] + chars[i+1]] += 1
    total = sum(bigrams.values())
    entropy = 0.0
    for count in bigrams.values():
        prob = count / total
        entropy -= prob * math.log2(prob)
    perplexity = 2 ** entropy
    return min(perplexity, 80.0)
```

#### 中文文本Perplexity基准值

| 文本类型 | Perplexity范围 | 特征描述 |
|---------|--------------|---------|
| 纯AI生成（GPT-4/Claude） | 5-15 | 高度可预测，用词极其标准 |
| AI轻度润色 | 15-25 | 基本可预测，少量变化 |
| 人类学术写作 | 25-40 | 中等可预测，专业术语增加意外性 |
| 人类网文写作 | 30-60 | 较高意外性，口语化和个性化表达 |
| 人类创意写作 | 50-80+ | 高度意外性，大量低频词和创新表达 |

**关键阈值**：
- PPL < 20 → 强AI信号（检测器高度怀疑）
- PPL 20-30 → 中等AI信号
- PPL 30-50 → 人类区间（安全）
- PPL > 50 → 高人类度（但可能可读性下降）

#### 如何量化和调整Perplexity到人类区间

**方法1：低概率词注入**
- 识别文本中的高频词序列，用低频同义词替换
- 在关键位置插入"意外词"（不符合上下文概率分布的词）
- 目标：将PPL从15提升到35+

**方法2：打破高频bigram序列**
- 计算文本的bigram频率分布
- 对出现频率最高的top-10 bigram进行改写
- 通过语序调整、同义词替换、句式变换打破高频序列

**方法3：增加词汇多样性**
- 提高唯一词比例（目标>0.55）
- 避免短文本内同义词循环替换
- 使用更具体、更个性化的词汇代替通用词汇

**方法4：句法树重构**
- 不只是换词，而是改变句子的深层句法结构
- 主动句↔被动句、陈述句↔反问句、长句↔短句组合
- 目标：改变模型对下一个词的预测路径

### 4.2 Burstiness（突发性）深度解析

#### 定义与计算

Burstiness衡量句子间困惑度的变异程度——AI文本每句话的困惑度都很均匀（低突发性），人类文本有的句子很简单（低困惑度）有的句子很复杂（高困惑度），波动大（高突发性）。

**计算方法**：
```python
# 昆仑fingerprint.py已实现
def _calc_burstiness(sentences):
    per_sentence_pp = [calc_perplexity(sent) for sent in sentences if len(sent) > 3]
    mean_pp = sum(per_sentence_pp) / len(per_sentence_pp)
    std_pp = math.sqrt(sum((p - mean_pp)**2 for p in per_sentence_pp) / len(per_sentence_pp))
    burstiness = std_pp / mean_pp  # 变异系数
    return burstiness
```

**简化计算（句长变异系数替代）**：
```python
def _calc_sentence_cv(sentence_lengths):
    mean = sum(sentence_lengths) / len(sentence_lengths)
    variance = sum((l - mean)**2 for l in sentence_lengths) / len(sentence_lengths)
    cv = math.sqrt(variance) / mean
    return cv
```

#### Burstiness基准值

| 文本类型 | Burstiness范围 | 句长CV范围 | 特征描述 |
|---------|--------------|-----------|---------|
| 纯AI生成 | <0.20 | <0.25 | 每句话困惑度几乎相同，句长均匀 |
| AI轻度改写 | 0.20-0.35 | 0.25-0.40 | 少量变化，但整体仍偏均匀 |
| 人类普通写作 | 0.35-0.50 | 0.40-0.55 | 有明显的长短句交替 |
| 人类创意写作 | 0.50-0.70 | 0.55-0.80 | 大幅波动，节奏感强 |
| 极端人类风格 | >0.70 | >0.80 | 极度不规则，可能影响可读性 |

**关键阈值**：
- Burstiness < 0.30 → 强AI信号
- Burstiness 0.30-0.40 → 中等AI信号
- Burstiness 0.40-0.60 → 人类区间（安全）
- Burstiness > 0.60 → 高人类度（注意可读性）

#### Burstiness优化策略

**策略1：句子长度方差最大化**
- 合并过短句子（<6字）：将两个短句用逗号连接
- 拆分过长句子（>50字）：在逗号处拆分为独立句子
- 目标句长CV = 0.55（昆仑fingerprint.py的目标值）

**策略2：困惑度双峰分布**
- 刻意制造"简单句+复杂句"的交替模式
- 简单句：5-10字，主谓宾结构，高频率常用词
- 复杂句：30-50字，包含从句、修饰语、低频词
- 目标：相邻句子的困惑度差异>20

**策略3：段落边界随机化**
- 打破均匀的段落长度
- 随机在句子中间插入换行（模拟人类作者的不规则分段）
- 有的段落只有一句话，有的段落有5-8句话
- 目标段落长度CV > 0.40

**策略4：节奏模式设计**
- 设计固定的节奏模板，如"短-短-长-中-短-长"
- 在打斗场景使用"短-短-短"快节奏
- 在描写场景使用"长-中-长"慢节奏
- 在对话场景使用"中-短-中-短"交替节奏

## 5. 中文网文特有的AI率特征和规避方法

### 5.1 男频网文AI写作典型痕迹

#### 痕迹1：过度描写（环境/心理/动作堆砌）

**AI特征**：
- 环境描写过多，与主角行动脱节（"环境描写太多，和主角有关的东西太少"——网文编辑新酒）["https://china.qianlong.com/2025/0610/8502716.shtml"]
- 心理描写模板化："心中暗想""内心充满""不由得想到"
- 动作描写成语堆砌："快如闪电""势如破竹""雷霆万钧"
- 每段都有"只见+描写+仿佛+感受"的固定模板

**规避方法**：
- 环境描写不超过段落的30%，必须与主角行动直接相关
- 用行为和对话间接体现心理，避免直接陈述
- 用具体动作和感官细节替代成语（"他手腕一翻，刀光贴着对方脖颈划过"替代"快如闪电"）
- 打破"只见体"，直接进入动作

#### 痕迹2：套路化对话

**AI特征**：
- 对话过于完整正式，每句都有"说道/问道/回答道"标签
- 对话长度均匀，缺乏打断、沉默、重叠
- 缺乏语气词（嗯/啊/哦/嘛/啦）
- 角色通过对话向另一角色解释已知信息（信息倾销）
- 对话内容过于礼貌，缺乏冲突和个性

**规避方法**：
- 用动作替代对话标签（"他斜了对方一眼"替代"他冷冷地说道"）
- 在连续对话中插入动作打断、沉默、情绪反应
- 每3-4句对话至少有1个语气词或口语化表达
- 角色说话符合身份（老人用古语/方言，年轻人用网络用语/短句）
- 设计角色口头禅（如主角爱说"行吧"、反派爱说"有意思"）

#### 痕迹3：机械升级

**AI特征**：
- 升级描述千篇一律："一股强大的力量涌入体内""修为暴涨""突破瓶颈"
- 缺乏升级的具体感知和代价
- 升级节奏均匀（每N章升一级），缺乏意外和挫折
- 升级后立即展示力量，缺乏消化和适应过程

**规避方法**：
- 用具体感知描写代替抽象能量描述（"经脉里像有滚烫的岩浆在流，每一寸都在嘶嘶作响"）
- 每次升级都有代价（损伤、后遗症、资源消耗）
- 升级节奏不规则，有时连续突破，有时卡壳很久
- 升级后先出问题再展示力量（力量失控、需要适应）

#### 痕迹4：模板化装逼打脸

**AI特征**：
- "嘴角勾起一抹冷笑/笑意/弧度"
- "众人震惊/骇然/倒吸一口凉气/不敢置信/目瞪口呆"
- "不屑/轻蔑/鄙夷的目光/眼神"
- 打脸流程固定：被轻视→展示力量→众人震惊→反派后悔

**规避方法**：
- 设计独特的打脸方式（用智慧、用信息差、用反套路）
- 众人反应多样化（有人不信、有人嫉妒、有人趁机拉拢、有人沉默）
- 主角反应个性化（不屑解释、懒得理会、反而道歉、直接动手）
- 打破固定流程，有时打脸失败，有时不需要打脸

#### 痕迹5：逻辑硬伤和常识错误

**AI特征**：
- 时间线混乱（"在回家的公交车上坐了三天三夜"）["https://news.qq.com/rain/a/20250218A09IFL00"]
- 物理常识错误（力量、速度、距离不合理）
- 角色行为不符合人设（前期冷静的角色后期突然冲动）
- 伏笔遗忘（前期埋下的线索后期不再提及）
- 世界观不一致（前期设定的规则后期被打破）

**规避方法**：
- 三级大纲法：总纲（核心矛盾+主角成长线）→ 卷纲（每卷主题+关键事件）→ 章纲（每章场景+冲突+钩子）
- 知识图谱管理实体/关系/规则，每次写作前检索一致性
- 角色人设卡：每个角色有明确的行为模式、语言风格、决策逻辑
- 伏笔追踪表：记录每个伏笔的埋设位置、预期回收位置、实际回收位置

### 5.3 针对网文场景的人类化策略

#### 策略1：口语化表达注入

**具体方法**：
- 对话中使用口语化词汇（"啥""咋""呗""嘛""啦""啊"）
- 叙述中偶尔使用口语化表达（"说白了""讲真""你懂的"）
- 角色使用符合身份的方言或行业黑话
- 避免过于书面化的表达（"诸如""倘若""因此之故"）

#### 策略2：不规则句式设计

**具体方法**：
- 省略主语（"走了。"替代"他走了。"）
- 倒装句（"死了？这家伙居然死了？"）
- 断句（"他看着她。很久。没说话。"）
- 非完整句（"好一个……"）
- 重复强调（"不可能。不可能！这绝对不可能！"）

#### 策略3：个性化"语病"

**具体方法**：
- 角色说话时有特定的语法"错误"（如老人说话省略介词、小孩说话语序颠倒）
- 叙述中偶尔出现"不规范"但自然的表达
- 避免每句话都语法完美、逻辑严密
- 适度使用"啰嗦"和"跑题"（人类说话不会句句精准）

#### 策略4：角色口头禅和语言指纹

**具体方法**：
- 每个主要角色设计1-2个口头禅（如"行吧""有意思""你猜"）
- 角色有独特的语言节奏（急性子短句多、慢性子长句多）
- 角色有特定的词汇偏好（学者用术语、江湖人用黑话、贵族用敬语）
- 角色情绪变化时语言风格也变化（愤怒时短句、沉思时长句）

#### 策略5：叙事节奏控制

**具体方法**：
- 打斗场景：短句为主（3-10字），动作密集，少描写
- 日常场景：中长句交替，对话多，节奏舒缓
- 高潮场景：长短句剧烈交替，情绪爆发，感官轰炸
- 过渡场景：中等长度，信息密度高，节奏平稳
- 每500字至少有1个节奏变化点（从快到慢或从慢到快）

#### 策略6："不完美"写作

**具体方法**：
- 偶尔留悬念不解释（人类作者不会事事交代清楚）
- 适度使用"模糊"表达（"他好像说了什么，没听清"）
- 允许角色犯错和后悔（AI倾向于让角色永远正确）
- 允许情节有"冗余"和"跑题"（人类写作不是每句话都推进剧情）
- 允许结尾"不升华"（直接停在动作或对话上，不总结不展望）

### 7.3 具体增强方案

#### 增强1：Gacha抽卡时加入人类化评分维度

**修改文件**：`kunlun/gacha/engine.py`

**具体方案**：
1. **生成Prompt注入人类化指令**：
   - 在系统Prompt中追加负向约束："禁止使用'仿佛/似乎/不由得/心中/缓缓/紧紧'等AI高频词。禁止使用'然而/因此/此外/综上所述'等书面连接词。句子长度必须长短交替（短句3-5字，长句30-50字）。禁止在结尾升华主题。"
   - 对黄金三章使用更强的人类化Prompt（角色扮演："你是一位有10年经验的网文作者，写作风格凌厉、口语化、有个人特色"）

2. **多候选评分增加第10维"AI率预估分"**：
   - 当前gacha有9维评分，增加第10维`human_score`（人类度评分）
   - 使用`ai_features.calculate_ai_score()`快速计算每个候选文本的人类度
   - 评分权重：人类度占15%（与番茄算法的AI分权重一致）
   - 候选选择时，人类度低于阈值（<0.5）的候选直接淘汰

3. **temperature参数动态调整**：
   - 默认temperature从1.0提升到1.15（增加随机性，降低AI味）
   - 黄金三章使用1.25
   - 打斗场景使用1.2（快节奏需要更多变化）
   - 关键情节使用1.05（保持稳定性）

#### 增强2：Audit模块增加AI率检测门禁G9

**新建文件**：`kunlun/audit/gates/gate_g9_ai_rate.py`

**具体方案**：
1. **G9门禁：综合AI率检测**（在现有G3基础上增强）
   - G3是"AI味检测"（24+特征+段落CV），G9是"综合AI率检测"（统计指纹+模式检测+特征扫描+番茄AI分的综合判定）
   - G9输入：章节文本
   - G9输出：`ai_rate_score`（0-100，AI率百分比）+ `pass/fail`

2. **G9检测维度与权重**：
   | 维度 | 来源 | 权重 | 阈值 |
   |------|------|------|------|
   | 统计指纹AI可能性 | TextFingerprint.ai_likelihood | 30% | >0.5为异常 |
   | AI模式命中密度 | AIModeDetector.total_markers/千字 | 25% | >5处/千字为异常 |
   | 24+维AI特征人类度 | ai_features.calculate_ai_score | 25% | <0.6为异常 |
   | 番茄AI倾向分 | FanqieTrafficOptimizer | 20% | >50为异常 |

3. **G9判定规则**：
   - ai_rate_score < 15 → PASS（绿灯）
   - ai_rate_score 15-30 → WARN（黄灯，建议人工检查）
   - ai_rate_score > 30 → FAIL（红灯，必须重写）
   - 黄金三章标准更严：<10 PASS，10-20 WARN，>20 FAIL

4. **G9与G3的关系**：
   - G3保留为"AI味特征检测"（细粒度特征定位）
   - G9为"综合AI率判定"（量化AI率百分比，用于门禁和质量看板）
   - G3 FAIL → 触发G9检测 → G9 FAIL → 触发humanize自动改写

#### 增强3：Humanize模块增强

**修改文件**：`kunlun/humanize/` 下多个文件

**具体增强**：

1. **fingerprint.py增强**：
   - 增加真正的语言模型级困惑度计算（可选，使用本地小模型如GPT-2中文）
   - 增加Binoculars式双模型困惑度对比（observer vs performer）
   - 增加perplexity定向改写建议（定位低困惑度句子，给出改写方向）

2. **detector.py增强**：
   - 扩展AI模式库到50+种（当前约35种）
   - 增加网文特化模式：升级模板检测、装逼打脸模板检测、战斗描写模板检测
   - 增加角色语言指纹检测（不同角色的语言风格是否区分）
   - 增加n-gram模板匹配（预定义100+网文AI高频n-gram）

3. **rewriter.py增强**：
   - 增加"定向改写"模式：基于检测结果，只改写AI模式命中的句子（不改写全文，降低成本和语义偏移）
   - 增加"角色语言指纹注入"：为每个角色生成独特的语言风格参数（句长偏好、词汇偏好、口头禅、语气词密度），在改写时保持角色一致性
   - 增加"节奏模板重写"：预定义5种节奏模板（打斗快节奏/日常慢节奏/对话交替/高潮爆发/过渡平稳），根据章节类型应用
   - 增加"翻译链+保留"模式：翻译链只改写非关键句子（对话、核心情节、设定说明保留原文），降低语义偏移风险

4. **engine.py增强**：
   - 增加"渐进式处理"：先做规则后处理（零成本），检测不达标再做翻译链，再不达标才做LLM重写（成本递增，大部分文本在规则层就达标）
   - 增加"段落级处理"：只处理AI率超标的段落（不是全文处理），降低成本和对优质内容的破坏
   - 增加"人工审核队列"：处理后AI率仍>20%的文本，标记为"需人工审核"，写入质量看板

#### 增强4：Audit与Humanize的闭环集成

**修改文件**：`kunlun/audit/post_write_validator.py` 和 `kunlun/pipeline/` 相关文件

**具体方案**：
1. **后写验证器集成G9门禁**：
   - 每章生成后，post_write_validator自动运行G9检测
   - G9 FAIL → 自动调用humanize_engine.humanize()（auto_strategy=True）
   - humanize处理后再次运行G9 → 仍FAIL → 标记为"需人工审核"
   - 整个过程自动完成，无需人工干预

2. **Pipeline集成点**：
   - `GachaEngine.generate()` → 输出候选文本 → 快速AI率预估（AntiAIDetector）→ 选择人类度最高的候选
   - `StyleEngineer.execute()` → 润色后 → humanize_engine.humanize(strategy="minimal") → 规则后处理
   - `PostWriteValidator.validate()` → G9检测 → FAIL则自动humanize → 复检
   - `API端点 POST /humanize` → 手动触发人性化处理
   - `守护进程` → 每章生成后自动调用humanize

3. **质量看板集成**：
   - 每章记录：处理前AI率、处理后AI率、降低百分比、使用的策略、处理耗时
   - 全书统计：平均AI率、AI率趋势、各章节AI率热力图
   - 预警：连续3章AI率>20% → 警告（可能Prompt需要调整）
   - 黄金三章专项报告：AI率、番茄潜力分、改进建议

### 8.1 当前基线与目标

|------|----------------|------------------|------------------|
| 平均AI率（G9评分） | 30-50% | <25% | <15% |
| 黄金三章AI率 | 40-60% | <20% | <10% |
| 番茄AI倾向分 | 50-70 | <40 | <25 |
| G3门禁通过率 | 60-70% | >85% | >95% |
| G9门禁通过率 | 未实施 | >80% | >95% |
| 人工审核率 | 未知 | <15% | <5% |
| 单章处理耗时 | 未知 | <5秒（规则层） | <3秒（优化后） |
| 单章LLM成本 | 未知 | 降低30%（渐进式处理） | 降低50%（段落级处理） |

### 8.2 分阶段技术路径

#### 第一阶段：规则层强化（第1-2周，目标AI率<25%）

**核心思路**：零LLM成本，通过增强规则后处理和检测精度，将大部分文本的AI率降到25%以下。

**具体动作**：
1. **扩展AI高频词替换表到100+**（当前约60个）
   - 从网文平台热门作品中提取人类常用表达
   - 从AI生成文本中提取高频模式
   - 建立"AI词→人类词"的多对多映射（每个AI词有3-5个人类替换方案，随机选择）

2. **增强统计指纹优化算法**
   - 优化merge/split策略：不是简单按字数，而是按语义完整性（在语义边界处拆分/合并）
   - 增加段落级优化：段落长度CV目标>0.40
   - 增加节奏模板应用：根据章节类型自动应用对应节奏模板

3. **实现G9门禁**
   - 新建`gate_g9_ai_rate.py`
   - 集成4维检测（统计指纹+模式检测+特征扫描+番茄AI分）
   - 接入post_write_validator自动运行

4. **实现渐进式处理**
   - 修改engine.py：先规则后处理→检测→不达标再升级策略
   - 预计70%的文本在规则层达标，无需LLM成本

**预期效果**：
- 规则层处理后AI率平均降低40-50%
- 70%文本在规则层达标（AI率<25%）
- 零LLM成本，处理耗时<1秒/章

#### 第二阶段：LLM层优化（第3-4周，目标AI率<20%）

**核心思路**：对规则层不达标文本，使用精准的LLM重写（定向改写+段落级处理），将AI率降到20%以下。

**具体动作**：
1. **实现定向改写**
   - 基于检测结果，只改写AI模式命中的句子和低困惑度段落
   - 不改写对话、核心情节、设定说明（降低语义偏移风险）
   - 预计LLM调用量减少60%（只处理30-40%的文本）

2. **实现段落级处理**
   - 按段落检测AI率，只处理AI率超标的段落
   - 优质段落（AI率<15%）直接保留，不做任何处理
   - 预计处理量减少50%，同时保护优质内容不被破坏

3. **增强人类化Prompt库**
   - 建立5种章节类型的专用人类化Prompt（开头/打斗/日常/高潮/过渡）
   - 建立角色语言指纹参数（每个角色的句长偏好/词汇偏好/口头禅/语气词密度）
   - Prompt中注入角色语言指纹，保持角色一致性

4. **Gacha集成人类化评分**
   - 修改gacha/engine.py：生成Prompt注入人类化指令
   - 多候选评分增加第10维"人类度评分"
   - temperature动态调整（默认1.15，黄金三章1.25）

**预期效果**：
- LLM层处理后AI率平均再降低30-40%
- 90%文本AI率<20%
- LLM成本比全文处理降低50-60%

#### 第三阶段：闭环与持续优化（第5-12周，目标AI率<15%）

**核心思路**：建立检测→改写→复检→学习的完整闭环，通过数据驱动持续优化规则和Prompt，将AI率稳定在15%以下。

**具体动作**：
1. **建立AI率数据看板**
   - 每章记录：处理前AI率、处理后AI率、降低百分比、使用策略、处理耗时
   - 全书统计：平均AI率、AI率趋势、各章节AI率热力图
   - 预警系统：连续3章AI率>20%→警告；黄金三章AI率>15%→紧急预警

2. **实现反馈学习闭环**
   - 收集人工审核的修改案例（哪些改写被人工修改了、为什么）
   - 定期分析高频失败模式（哪些AI模式规则层处理不掉）
   - 基于失败案例更新规则库和Prompt库（每周迭代）

3. **增强检测精度**
   - 引入本地小模型（如GPT-2中文）计算真正的困惑度（替代字符bigram近似）
   - 实现Binoculars式双模型困惑度对比
   - 增加n-gram模板库（预定义200+网文AI高频n-gram）
   - 增加角色语言指纹检测（不同角色的语言风格是否区分）

4. **番茄平台专项优化**
   - 针对番茄AI率检测规则做专项优化（基于平台公开公告和治理数据）
   - 黄金三章使用最强处理（AGRESSIVE+人工审核）
   - 建立"番茄安全区"：AI率<15%+番茄AI倾向分<25+首300字合格+章尾钩子合格

5. **A/B测试框架**
   - 建立不同Prompt/规则/参数的A/B测试能力
   - 每周运行A/B测试，量化每种优化的效果
   - 基于数据选择最优配置

**预期效果**：
- 闭环优化后AI率稳定在15%以下
- 黄金三章AI率<10%
- 人工审核率<5%
- 处理耗时<3秒/章（规则层<1秒，LLM层<5秒但只处理10%文本）

### 8.3 关键技术指标与验证方法

| 验证维度 | 验证方法 | 通过标准 |
|---------|---------|---------|
| AI率降低效果 | G9门禁检测处理前后AI率 | 平均降低>50%，最终<15% |
| 语义保真度 | 人工抽查+核心情节一致性检测 | 核心情节不变率>95%，人工评分>4/5 |
| 可读性 | 句长分布+词汇多样性+人工评分 | 可读性评分>4/5，无明显不通顺 |
| 角色一致性 | 角色语言指纹检测+人工评分 | 角色语言风格保持率>90% |
| 处理效率 | 单章平均处理耗时 | 规则层<1秒，全流程<5秒 |
| 成本控制 | 单章平均LLM调用次数和Token数 | 比全文处理降低>50% |
| 番茄适配 | 番茄AI倾向分+潜力分 | AI倾向分<25，潜力分提升>10分 |

### 8.4 风险与应对

| 风险 | 可能性 | 影响 | 应对措施 |
|------|-------|------|---------|
| 规则层处理后文本不自然 | 中 | 可读性下降 | 增加语义边界检测，只在自然断点处拆分/合并；建立不自然表达黑名单 |
| LLM改写改变核心情节 | 中 | 剧情崩坏 | 定向改写只改表达方式不改语义；关键句子（对话/设定/转折）保留原文；改写后运行情节一致性检测 |
| 角色语言风格被破坏 | 中 | 角色崩坏 | 建立角色语言指纹参数，改写时保持角色偏好；角色对话不做翻译链处理 |
| 处理耗时过长 | 低 | 用户体验差 | 渐进式处理（70%文本在规则层<1秒完成）；段落级处理（只处理超标段落）；异步处理（生成后后台运行） |
| LLM成本过高 | 中 | 运营成本 | 渐进式+段落级+定向改写（预计降低50-60%成本）；规则层零成本；缓存相似文本的处理结果 |
| 番茄检测规则变化 | 高 | 检测失效 | 持续监控番茄平台公告和治理数据；每月更新检测规则和处理策略；建立"规则变化预警"机制 |
| 过度降AI导致内容质量下降 | 中 | 读者体验差 | 设定AI率下限（不低于5%，过低可能是文本质量问题）；保留优质内容不处理；人工审核兜底 |
