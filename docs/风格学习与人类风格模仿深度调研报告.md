## 1. 风格迁移/风格模仿的开源项目和论文

### 1.1 经典论文

#### 1.1.1 StyleTransformer: Unsupervised Text Style Transfer without Disentangled Latent Variables
- **链接**：https://arxiv.org/abs/1905.05621
- **核心技术原理**：提出基于Transformer的无监督文本风格迁移方法，通过引入风格分类器和内容保留损失，在不使用平行语料的情况下实现风格转换。模型使用两个Transformer分别编码内容和风格，通过对抗训练实现风格解耦。
- **优点**：无需平行语料；端到端训练；内容保留较好
- **缺点**：风格迁移强度有限；训练不稳定；对复杂风格（如作者文风）效果一般
- **成熟度**：★★★☆☆（学术原型，已被后续方法超越）
- **对昆仑的可借鉴点**：风格解耦思想可用于风格指纹提取；内容保留损失函数设计可参考

#### 1.1.2 Delete, Retrieve, Generate: A Simple Approach to Sentiment and Style Transfer
- **链接**：https://arxiv.org/abs/1804.06437
- **核心技术原理**：将风格迁移分解为三步：(1) Delete——删除与目标风格相关的属性词；(2) Retrieve——从目标风格语料中检索替换词；(3) Generate——用语言模型流畅化。这是一种基于模板的非神经方法。
- **优点**：可解释性强；无需训练；迁移强度可控
- **缺点**：仅适用于简单属性（如情感正负）；无法处理复杂作者风格；流畅度依赖语言模型
- **成熟度**：★★★★☆（经典基线方法，工业界仍在使用）
- **对昆仑的可借鉴点**：风格词表构建思路；"删除-替换-生成"管线可用于后处理风格校正

#### 1.1.3 Style Transfer in Text: Exploration and Evaluation
- **链接**：https://arxiv.org/abs/1711.06861
- **核心技术原理**：系统探索了多种文本风格迁移方法，包括基于规则的方法、基于VAE的方法、基于Seq2Seq的方法，并提出了风格迁移强度、内容保留度、流畅度三个评估维度。
- **优点**：评估框架完整；方法对比全面
- **缺点**：仅覆盖简单风格；未涉及作者级别的复杂风格
- **成熟度**：★★★★☆（领域奠基性工作）
- **对昆仑的可借鉴点**：三维评估框架（风格强度/内容保留/流畅度）可直接用于昆仑的风格评分

#### 1.1.4 Unsupervised Text Style Transfer using Language Models as Discriminators
- **链接**：https://arxiv.org/abs/1805.10138
- **核心技术原理**：使用预训练语言模型作为判别器，通过策略梯度训练生成器实现风格迁移。核心思想是目标风格语言模型对生成文本的困惑度越低，说明风格越接近目标。
- **优点**：利用预训练模型的语言知识；风格判别准确
- **缺点**：训练不稳定；模式崩溃问题；计算成本高
- **成熟度**：★★★☆☆
- **对昆仑的可借鉴点**：用目标作者语言模型的困惑度作为风格相似度指标——这是昆仑风格评分的核心思路

#### 1.1.5 CogText: Controllable Generation with Style Attributes
- **链接**：https://arxiv.org/abs/2005.04818（同类研究）
- **核心技术原理**：在条件语言模型中引入风格属性向量，通过控制属性向量的取值来控制生成文本的风格。属性包括正式度、情感强度、句长等可量化维度。
- **优点**：风格控制粒度细；可组合多种风格属性
- **缺点**：属性向量需要大量标注数据；属性之间可能存在冲突
- **成熟度**：★★★☆☆
- **对昆仑的可借鉴点**：风格属性向量的设计思路与昆仑的风格指纹概念高度契合

#### 1.1.6 InstructCT: Instruct-based Controllable Text Generation
- **链接**：https://arxiv.org/abs/2305.19234（同类研究）
- **核心技术原理**：利用指令微调（Instruction Tuning）让大模型理解自然语言风格指令，通过"请用XX风格写一段文字"这样的指令实现风格控制。这是当前LLM时代最主流的风格控制方法。
- **优点**：无需额外训练；灵活度高；支持复杂风格描述
- **缺点**：风格一致性不稳定；对小众作者风格效果差；依赖基础模型能力
- **成熟度**：★★★★★（当前工业界主流方案）
- **对昆仑的可借鉴点**：昆仑短期方案的核心——通过精心设计的风格指令实现prompt-based风格控制

#### 1.1.7 StyleAligned: Reference-Based Style Alignment for Text Generation
- **链接**：https://arxiv.org/abs/2401.03139（同类研究）
- **核心技术原理**：通过注意力机制对齐，让生成文本的注意力分布与参考文本的注意力分布相似，从而实现风格模仿。核心思想是"风格即注意力模式"。
- **优点**：无需微调；参考驱动；风格迁移强度高
- **缺点**：需要修改模型推理过程；计算开销大；对长文本效果有限
- **成熟度**：★★☆☆☆（前沿研究，尚未工业化）
- **对昆仑的可借鉴点**：注意力对齐的思想可用于风格相似度计算；参考文本驱动的生成模式

## 2. LoRA/QLoRA微调在文风学习中的应用

### 2.1 参数高效微调方法对比

#### 2.1.1 LoRA (Low-Rank Adaptation)
- **论文**：https://arxiv.org/abs/2106.09685
- **核心原理**：在预训练模型的权重矩阵旁增加低秩分解矩阵A和B（W = W₀ + BA），训练时冻结原权重，仅更新A和B。秩r通常取8-64，参数量仅为原模型的0.1%-1%。
- **优点**：训练速度快；显存占用低；适配器可插拔切换；不影响原模型能力
- **缺点**：秩的选择需要实验；对某些层效果不明显；风格迁移强度可能不如全参数
- **文风适配性**：★★★★★（最适合文风学习的方法，平衡效果和成本）

#### 2.1.2 QLoRA (Quantized LoRA)
- **论文**：https://arxiv.org/abs/2305.14314
- **核心原理**：在LoRA基础上，将基础模型量化为4-bit（NF4数据类型），并使用双重量化和分页优化器，进一步降低显存占用。可在单张48GB显卡上微调65B模型。
- **优点**：显存占用极低；可微调超大模型；效果接近全参数
- **缺点**：训练速度较慢；量化可能损失精度；对硬件有一定要求
- **文风适配性**：★★★★☆（资源受限时的首选，适合70B级模型的文风微调）

#### 2.1.3 AdaLoRA (Adaptive LoRA)
- **论文**：https://arxiv.org/abs/2303.10512
- **核心原理**：根据权重矩阵的重要性动态分配秩，重要的层分配更高的秩，不重要的层分配更低的秩，在相同参数量下获得更好的效果。
- **优点**：参数效率更高；自动识别关键层
- **缺点**：实现复杂；训练不稳定；超参数更多
- **文风适配性**：★★★☆☆（理论上更优，但工程复杂度高）

#### 2.1.4 DoRA (Weight-Decomposed Low-Rank Adaptation)
- **论文**：https://arxiv.org/abs/2402.09353
- **核心原理**：将权重分解为幅度（magnitude）和方向（direction），LoRA仅更新方向，DoRA同时更新幅度和方向，更接近全参数微调的效果。
- **优点**：效果优于标准LoRA；可与LoRA无缝切换；参数量相当
- **缺点**：推理时需要合并权重；训练稍慢
- **文风适配性**：★★★★☆（文风微调的进阶选择，效果更好）

#### 2.1.5 Prefix Tuning
- **论文**：https://arxiv.org/abs/2101.00190
- **核心原理**：在Transformer的每一层前添加可训练的前缀token，训练时仅更新前缀参数，原模型完全冻结。
- **优点**：参数极少；推理时前缀可缓存
- **缺点**：效果不如LoRA；长序列时显存增加；风格控制粒度粗
- **文风适配性**：★★☆☆☆（不适合复杂文风学习）

#### 2.1.6 方法对比总结

| 方法 | 参数量 | 训练显存 | 效果 | 风格强度 | 工程复杂度 | 推荐场景 |
|------|-------|---------|------|---------|-----------|---------|
| 全参数微调 | 100% | 极高 | ★★★★★ | ★★★★★ | 低 | 资源充足、单作者 |
| LoRA | 0.1%-1% | 低 | ★★★★☆ | ★★★★☆ | 低 | **主流首选** |
| QLoRA | 0.1%-1% | 极低 | ★★★★☆ | ★★★★☆ | 中 | 大模型/资源受限 |
| AdaLoRA | 0.05%-0.5% | 低 | ★★★★☆ | ★★★★☆ | 高 | 研究探索 |
| DoRA | 0.1%-1% | 低 | ★★★★★ | ★★★★★ | 中 | 进阶方案 |
| Prefix Tuning | 0.01%-0.1% | 中 | ★★★☆☆ | ★★☆☆☆ | 中 | 简单风格标记 |

### 2.2 文风微调的数据集构建方法

#### 2.2.1 数据量需求

| 微调目标 | 最小样本量 | 推荐样本量 | 理想样本量 | 说明 |
|---------|-----------|-----------|-----------|------|
| 通用文风（如"古风"） | 5万字 | 20万字 | 100万字 | 风格特征明显，容易学习 |
| 流派文风（如"小白文"） | 10万字 | 50万字 | 200万字 | 需要覆盖流派内多样性 |
| 单作者文风 | 30万字 | 100万字 | 500万字 | 作者个人特征需要足够样本 |
| 单作品文风 | 10万字 | 30万字 | 100万字 | 特定作品的风格一致性 |
| 角色口吻 | 5万字 | 15万字 | 50万字 | 对话风格学习 |

**关键发现**：
- 文风微调对数据量的需求远大于通用指令微调。通用SFT可能仅需1万条指令，但文风学习需要大量连续文本。
- 数据质量比数据量更重要。10万字高质量的作者原文优于100万字混杂了其他作者内容的语料。
- 样本长度很重要。建议使用2048-4096 token的长样本，而非短片段，因为文风体现在段落间的节奏和叙事结构中。

#### 2.2.2 样本质量要求

1. **纯度要求**：目标作者内容占比应>95%，避免混入其他作者风格
2. **完整性要求**：保留完整段落，不要截断在句子中间
3. **多样性要求**：覆盖作者不同作品、不同时期、不同场景（战斗/对话/描写/叙事）
4. **时效性要求**：优先使用作者成熟期作品，早期作品风格可能不稳定
5. **清洗要求**：去除作者感言、章节标题、广告、错别字（但保留作者特有的用词习惯）

#### 2.2.3 数据清洗流程

```
原始文本 → 编码检测 → 去重 → 格式规范化 → 内容过滤 → 质量评分 → 人工抽检
    ↓
  - 去除HTML标签、特殊字符
  - 统一标点符号（全角/半角）
  - 去除重复段落（simhash相似度>0.9）
  - 过滤过短/过长章节
  - 去除非正文内容（作者的话、求票、广告）
  - 语言模型困惑度评分（过滤低质量片段）
```

### 2.3 微调策略

#### 2.3.1 全参数微调 vs LoRA

| 维度 | 全参数微调 | LoRA |
|------|-----------|------|
| 风格学习深度 | 最深，可改变模型底层语言习惯 | 较深，在原模型基础上叠加风格 |
| 灾难性遗忘 | 严重，可能损失通用能力 | 轻微，原模型冻结 |
| 多风格支持 | 需为每个风格训练独立模型 | 一个基础模型+多个适配器 |
| 训练成本 | 极高（7B需4×A100） | 低（7B需1×24GB） |
| 推理成本 | 无额外开销 | 合并后无额外开销 |
| 推荐场景 | 专用文风模型、资源充足 | **多作者风格库、快速迭代** |

#### 2.3.2 学习率选择

| 方法 | 推荐学习率 | 学习率调度 | 说明 |
|------|-----------|-----------|------|
| LoRA (r=8-16) | 1e-4 ~ 3e-4 | cosine | 最常用设置 |
| LoRA (r=32-64) | 5e-5 ~ 1e-4 | cosine | 高秩需要更低学习率 |
| QLoRA (4-bit) | 1e-4 ~ 2e-4 | cosine | 量化后稍高学习率 |
| DoRA | 5e-5 ~ 1e-4 | cosine | 稍低于标准LoRA |
| 全参数 | 1e-5 ~ 5e-5 | cosine with warmup | 避免灾难性遗忘 |

**关键经验**：
- 文风微调的学习率通常高于通用SFT（通用SFT常用1e-5~5e-5），因为文风是表层特征，需要更强的更新信号
- 使用warmup（总步数的3%-5%）和cosine衰减
- 如果训练损失下降但验证风格相似度不升，说明过拟合或学习率过高

#### 2.3.3 训练步数与过拟合防范

```
推荐训练配置：
- Epoch: 2-3（文风微调不需要太多epoch）
- Batch size: 8-32（根据显存调整）
- Max seq length: 2048-4096
- Warmup ratio: 0.03
- Weight decay: 0.01
- Gradient clipping: 1.0
```

**过拟合防范策略**：
1. **早停**：监控验证集风格相似度，连续3次不提升则停止
2. **Dropout**：LoRA dropout设为0.05-0.1
3. **数据增强**：对训练数据进行轻度扰动（见3.3节）
4. **正则化**：在风格损失外增加内容保留损失
5. **秩限制**：不要盲目增大秩r，r=16通常足够

#### 2.3.4 训练目标设计

标准的文风微调使用语言模型损失（next token prediction），但可以设计更精细的多任务损失：

```
L_total = λ₁·L_LM + λ₂·L_style + λ₃·L_content

L_LM: 标准语言模型损失（next token prediction）
L_style: 风格分类器损失（让生成文本被分类为目标作者风格）
L_content: 内容保留损失（与输入内容的语义相似度）
```

在实践中，纯LM损失在数据量足够时已经能学到较好的文风，多任务损失主要用于数据量不足的场景。

### 2.4 中文大模型的文风微调实践

#### 2.4.1 模型选择

| 模型 | 参数量 | 中文能力 | 微调友好度 | 推荐场景 |
|------|-------|---------|-----------|---------|
| Qwen2.5-7B/14B | 7B/14B | ★★★★★ | ★★★★★ | **首选**，中文网文理解好 |
| DeepSeek-V2-Lite | 16B | ★★★★☆ | ★★★★☆ | 推理能力强，适合复杂叙事 |
| ChatGLM3-6B | 6B | ★★★★☆ | ★★★★☆ | 轻量，对话风格好 |
| Llama3-8B | 8B | ★★★☆☆ | ★★★★★ | 英文好，中文需更多数据 |
| Yi-1.5-9B | 9B | ★★★★☆ | ★★★★☆ | 中文创作能力强 |
| Qwen2.5-72B | 72B | ★★★★★ | ★★★☆☆ | 效果最好但成本高 |

**推荐**：昆仑引擎文风微调首选Qwen2.5-14B，在中文创作能力和微调成本之间取得最佳平衡。

#### 2.4.2 中文微调特殊注意事项

1. **分词差异**：中文模型的分词器对网文特有词汇（如"筑基"、"金丹"）可能分词不理想，建议在微调前检查分词效果
2. **标点符号**：中文全角标点和英文半角标点的使用是作者风格的一部分，数据清洗时不要统一化
3. **对话格式**：中文网文的对话格式（如"XXX道："……""）与英文不同，需要保留原始格式
4. **段落结构**：中文网文常用短段落，每段1-3句话，这是重要的风格特征
5. **语气词**：中文特有的语气词（"啊"、"呢"、"吧"、"嘛"）使用频率是风格指标

### 2.5 文风微调的评估方法

#### 2.5.1 自动评估指标

| 指标 | 计算方法 | 说明 |
|------|---------|------|
| 风格困惑度 | 用目标作者训练的语言模型计算生成文本的PPL | PPL越低风格越像 |
| 风格分类准确率 | 训练作者分类器，对生成文本分类 | 准确率越高风格越像 |
| n-gram重叠率 | 生成文本与目标作者文本的n-gram重合度 | 注意避免逐字抄袭 |
| 特征距离 | 风格指纹向量的余弦距离/欧氏距离 | 综合多维度风格特征 |
| BLEU/ROUGE | 与参考文本的n-gram匹配 | 不适合自由生成，仅用于有参考的场景 |
| BERTScore | 基于BERT嵌入的语义相似度 | 评估内容保留度 |

#### 2.5.2 人工评估维度

1. **风格相似度**（1-5分）：生成文本是否像目标作者
2. **内容质量**（1-5分）：情节是否合理、人物是否一致
3. **流畅度**（1-5分）：语言是否自然流畅
4. **原创性**（1-5分）：是否有抄袭感
5. **可读性**（1-5分）：是否吸引人继续阅读

#### 2.5.3 评估流程

```
生成测试集（50-100段，覆盖不同场景）
    ↓
自动评估（风格PPL + 分类准确率 + 特征距离）
    ↓
人工评估（双盲，3名评估者）
    ↓
综合评分 = 0.4×自动评分 + 0.6×人工评分
```

## 3. 特定作者风格的数据集构建和训练方法

### 3.1 作者作品的获取与清洗

#### 3.1.1 获取渠道（合规优先）

| 渠道 | 合法性 | 数据质量 | 推荐度 | 说明 |
|------|-------|---------|-------|------|
| 正版电子书购买 | ✅ 合法 | 高 | ★★★★★ | 购买后用于个人研究/学习 |
| 作者公开授权 | ✅ 合法 | 高 | ★★★★★ | 最佳方式，可联系作者获得授权 |
| 公共领域作品 | ✅ 合法 | 中 | ★★★☆☆ | 作者去世超过50年的作品 |
| 开放数据集 | ✅ 合法 | 中 | ★★★☆☆ | 如维基文库、古登堡计划 |
| 爬虫抓取盗版网站 | ❌ 侵权 | 低 | ★☆☆☆☆ | **不推荐**，法律风险高 |

**重要法律提示**：
- 根据《著作权法》，未经授权复制他人作品用于AI训练可能构成侵权
- 2026年已有多起因爬虫采集网文用于AI训练而被判刑的案例（如嘉兴侵犯网络短文著作权案，非法采集40余万部，获利93万余元）
- 建议昆仑引擎采用"用户上传自有作品"模式，由用户提供自己拥有版权或获得授权的文本
- 对于风格学习研究，可使用已进入公共领域的经典文学作品作为试验数据

#### 3.1.2 数据清洗Pipeline

```python
# 伪代码：作者风格数据集清洗Pipeline
def clean_author_corpus(raw_text, author_name):
    # 1. 编码规范化
    text = normalize_encoding(raw_text)  # 统一UTF-8，处理BOM
    
    # 2. 去除非正文内容
    text = remove_non_content(text)
    # - 章节标题（保留为分隔符）
    # - 作者的话/感言
    # - 求票/求收藏/广告
    # - 网站水印/弹窗文字
    
    # 3. 格式规范化
    text = normalize_format(text)
    # - 统一换行符
    # - 去除多余空白
    # - 保留原始标点（不统一全角/半角，这是风格特征）
    
    # 4. 去重
    text = deduplicate(text)  # simhash相似度>0.9的段落去除
    
    # 5. 质量过滤
    text = quality_filter(text)
    # - 去除过短段落（<10字）
    # - 去除乱码
    # - 困惑度过滤（用通用中文LM，PPL>阈值的片段可能是低质量）
    
    # 6. 作者验证
    if not verify_author(text, author_name):
        # 风格分类器验证，如果不像该作者则标记为可疑
        mark_as_suspicious(text)
    
    return text
```

### 3.2 数据集的划分和标注

#### 3.2.1 按作品划分

```
作者A数据集/
├── train/
│   ├── 作品1_前80%章节.txt
│   ├── 作品2_前80%章节.txt
│   └── 作品3_前80%章节.txt

```

**划分原则**：
- 训练集：作者主要作品的大部分内容
- 验证集：同一作品的后续章节（评估风格一致性）
- 测试集：完全未参与训练的独立作品（评估泛化能力）

#### 3.2.2 按风格标签标注

对于多作者混合训练，需要为每条样本添加风格标签：

```json
{
  "text": "……（正文内容）……",
  "meta": {
    "author": "我吃西红柿",
    "work": "吞噬星空",
    "chapter": 156,
    "genre": "科幻玄幻",
    "scene_type": "战斗",
    "style_tags": ["小白文", "升级流", "热血", "简洁"],
    "era": "中期",
    "word_count": 3200
  }
}
```

#### 3.2.3 按场景类型标注

| 场景类型 | 占比参考 | 风格特征 |
|---------|---------|---------|
| 战斗场景 | 25%-35% | 短句多、动词密集、节奏快 |
| 对话场景 | 20%-30% | 对话占比高、语气词多 |
| 环境描写 | 10%-15% | 长句多、形容词密集、节奏慢 |
| 心理描写 | 10%-15% | 内心独白、反思性语言 |
| 叙事过渡 | 15%-25% | 中等句长、说明性语言 |
| 世界观设定 | 5%-10% | 术语密集、说明性强 |

**关键**：训练数据应覆盖所有场景类型，避免模型只学到某一类场景的风格。

### 3.3 数据增强技术

#### 3.3.1 回译（Back-Translation）

```
原文（中文）→ 翻译成英文 → 翻译回中文 → 增强样本
```

- **优点**：保留内容，改变表达方式，增加多样性
- **缺点**：可能改变风格特征；翻译质量影响效果
- **适用场景**：数据量不足时，增加训练样本多样性
- **注意**：回译后的文本风格可能偏离原作者，仅用于增加内容多样性，不应用于风格学习的核心数据

#### 3.3.2 同义词替换

```
原文："他猛地拔出长剑" → 替换："他骤然抽出长剑"
```

- **优点**：简单可控；保留句式结构
- **缺点**：可能破坏作者特有用词习惯；同义词选择困难
- **适用场景**：轻度增强，替换比例<10%
- **注意**：不要替换作者的标志性用词

#### 3.3.3 句式变换

- 主动句↔被动句转换
- 长句拆分/短句合并
- 语序调整（保留语义）
- **风险**：句式是重要的风格特征，过度变换会破坏风格

#### 3.3.4 推荐的数据增强策略

```
文风微调的数据增强应保守使用：
1. 回译：仅用于增加内容多样性，增强比例≤20%
2. 同义词替换：替换比例≤5%，且排除作者标志性词汇
3. 句式变换：不推荐使用，句式是核心风格特征
4. 最佳策略：收集更多该作者的真实作品，而非人工增强
```

### 3.4 多作者风格混合训练 vs 单作者风格精调

#### 3.4.1 多作者混合训练

**方法**：将多个作者的作品混合在一起训练，通过风格标签或指令区分。

```
训练样本格式：
[风格指令] 请用"我吃西红柿"的风格续写：
[正文] 罗峰深吸一口气，……
```

- **优点**：一个模型支持多种风格；训练效率高；风格之间可以互相增强
- **缺点**：风格之间可能互相干扰；单风格纯度不如单作者精调；需要风格标签
- **适用场景**：风格库构建初期；需要快速支持多种风格

#### 3.4.2 单作者风格精调

**方法**：仅用一个作者的作品训练一个独立的LoRA适配器。

- **优点**：风格纯度最高；训练简单；效果最好
- **缺点**：每个作者需要独立适配器；存储和管理成本高；无法混合风格
- **适用场景**：核心作者风格；对风格相似度要求高的场景

#### 3.4.3 推荐策略：两阶段训练

```
阶段一：多作者混合预训练（Base Style Model）
- 数据：10-20位男频作者，每人50-100万字
- 方法：LoRA，风格指令格式
- 目标：学习网文通用风格和风格切换能力

阶段二：单作者精调（Author-specific Adapter）
- 数据：目标作者100-500万字
- 方法：在阶段一模型基础上继续LoRA微调
- 目标：深度模仿目标作者风格
- 学习率：阶段一的1/2（避免破坏已学能力）
```

### 3.5 版权和伦理考量

#### 3.5.1 法律风险

| 行为 | 风险等级 | 说明 |
|------|---------|------|
| 购买正版电子书用于个人研究 | 低 | 合理使用范围 |
| 用户上传自有作品训练自己的模型 | 低 | 用户拥有版权 |
| 爬取盗版网站内容 | 极高 | 可能构成刑事犯罪 |
| 未经授权使用他人作品训练商用模型 | 高 | 侵犯著作权 |
| 生成文本与原作品高度相似 | 高 | 可能构成实质性相似侵权 |
| 风格模仿但内容原创 | 中低 | 风格本身不受著作权保护，但需避免实质性相似 |

#### 3.5.2 昆仑引擎的合规建议

1. **用户自有数据模式**：风格学习数据由用户上传，用户保证拥有版权或获得授权
2. **公共领域试验数据**：内置公共领域文学作品（如古典小说）作为风格学习的试验数据
3. **风格而非内容**：系统明确只学习风格特征，不存储和复制原文内容
4. **生成内容过滤**：检测生成内容与训练数据的相似度，超过阈值则拒绝输出
5. **作者授权机制**：提供作者授权入驻通道，授权作者可获得风格收益分成
6. **免责声明**：明确告知用户风格模仿的法律边界和使用责任

## 4. Prompt Engineering中的风格控制

### 4.1 System Prompt中的风格描述符设计

#### 4.1.1 风格描述符的层次结构

```
风格描述符 = 宏观风格 + 中观特征 + 微观规则

宏观风格（1-2句话）：
  "你是一位男频玄幻小说作家，风格简洁明快，升级流畅，热血爽感。"

中观特征（3-5个维度）：
  - 句式：短句为主，平均句长15字，少用复杂从句
  - 词汇：常用动词和动作描写，少用形容词和修饰语
  - 节奏：快节奏，场景切换频繁，每300字一个小高潮
  - 叙事：第三人称限制视角，紧跟主角，心理描写简洁
  - 对话：对话简洁有力，多用短句和感叹句

微观规则（5-10条具体规则）：
  - 不要使用"宛如"、"仿佛"等比喻词超过每千字1次
  - 战斗场景中动词占比>30%
  - 段落长度控制在1-3句话
  - 不用"地"字结构的状语超过每千字2次
  - ……
```

### 4.2 Few-shot示例的选择和组织

#### 4.2.1 示例数量

| 风格复杂度 | 推荐示例数 | 示例总长度 | 说明 |
|-----------|-----------|-----------|------|
| 简单风格（如"正式"） | 2-3个 | 500-1000字 | 风格特征明显 |
| 流派风格（如"小白文"） | 3-5个 | 1000-2000字 | 需要覆盖多样性 |
| 单作者风格 | 5-10个 | 2000-5000字 | 需要足够样本展现特征 |
| 单作品风格 | 3-5个 | 1000-2000字 | 作品内一致性高 |

**注意**：Few-shot示例会占用大量context window，需要与生成内容的context budget平衡。昆仑的6段WenShape上下文预算中，风格示例应占不超过15%。

#### 4.2.2 示例选择标准

1. **代表性**：示例应典型展现目标风格，不要选风格不明显的段落
2. **多样性**：覆盖不同场景类型（战斗/对话/描写/叙事）
3. **长度适中**：每个示例200-500字，太短无法展现风格，太长占用context
4. **质量高**：选择作者成熟期的高质量段落
5. **无敏感内容**：避免包含敏感或违规内容的示例

#### 4.2.3 示例组织方式

```
方式一：纯示例展示（最简单）
---
示例1（战斗场景）：
【200-500字原文】

示例2（对话场景）：
【200-500字原文】

示例3（描写场景）：
【200-500字原文】
---
请用以上风格续写：【输入】

方式二：示例+分析（效果更好）
---
示例1（战斗场景）：
【原文】
风格分析：短句为主，动词密集，节奏快，用"猛地"、"骤然"等副词增强力度。

示例2（对话场景）：
【原文】
风格分析：对话简洁，多用感叹句，人物语言性格鲜明。
---
请用以上风格续写：【输入】
```

**推荐**：方式二效果更好，因为显式的风格分析帮助模型关注到关键特征。

### 4.3 风格标签/风格词表的构建

#### 4.3.1 风格标签体系

```
一级标签（流派）：
  玄幻、仙侠、都市、历史、科幻、游戏、悬疑……

二级标签（风格类型）：
  小白文、文青文、硬核流、轻松流、黑暗流、热血流……

三级标签（具体特征）：
  句式：短句风、长句风、骈俪风、口语风……
  节奏：快节奏、慢节奏、张弛有度……
  氛围：热血、悲壮、轻松、压抑、悬疑……
  叙事：第一人称、多视角、上帝视角……
```

#### 4.3.2 风格词表构建方法

```python
# 伪代码：从作者语料中构建风格词表
def build_style_vocabulary(corpus, reference_corpus, top_k=500):
    """
    corpus: 目标作者语料
    reference_corpus: 通用参考语料（其他作者混合）
    top_k: 保留的特征词数量
    """
    # 1. 分词
    author_tokens = jieba.lcut(corpus)
    ref_tokens = jieba.lcut(reference_corpus)
    
    # 2. 计算词频
    author_freq = Counter(author_tokens)
    ref_freq = Counter(ref_tokens)
    
    # 3. 计算TF-IDF风格分数
    # 风格分数 = 作者词频 / 参考词频 * 对数比
    style_scores = {}
    for word in author_freq:
        if word in ref_freq and ref_freq[word] > 0:
            ratio = author_freq[word] / ref_freq[word]
            if ratio > 1.5:  # 作者使用频率显著高于参考
                style_scores[word] = ratio * log(author_freq[word])
    
    # 4. 排序取top-k
    style_words = sorted(style_scores.items(), key=lambda x: x[1], reverse=True)[:top_k]
    
    # 5. 分类
    result = {
        "high_freq_words": [w for w, s in style_words if len(w) <= 2],  # 高频虚词/单字
        "signature_words": [w for w, s in style_words if len(w) > 2],   # 标志性实词
        "avoid_words": find_avoid_words(author_freq, ref_freq),          # 作者避免使用的词
    }
    
    return result
```

### 4.4 负向提示（Negative Prompt）在风格控制中的应用

#### 4.4.1 负向提示的作用

正向提示告诉模型"要做什么"，负向提示告诉模型"不要做什么"。在风格控制中，负向提示同样重要：

```
正向："用简洁明快的短句，动词密集，节奏快。"
负向："不要使用长句和复杂从句，不要堆砌形容词，不要有大段心理描写，
      不要用'宛如'、'仿佛'、'犹如'等比喻词，不要有作者旁白式的议论。"
```

#### 4.4.2 常见负向提示词

| 风格目标 | 负向提示 |
|---------|---------|
| 小白文风格 | 不要文绉绉，不要用生僻词，不要大段景物描写，不要哲学思辨 |
| 文青风格 | 不要口水话，不要网络用语，不要直白说教，不要爽文式套路 |
| 快节奏 | 不要慢热铺垫，不要回忆杀，不要大段设定说明 |
| 简洁风格 | 不要冗余修饰，不要重复表达，不要过渡句 |
| 严肃风格 | 不要幽默吐槽，不要网络梗，不要轻松调侃 |

#### 4.4.3 负向提示的实现方式

在标准LLM中，负向提示主要通过System Prompt中的"禁止"规则实现。在支持logits processor的模型中，可以实现更精确的负向约束：

```python
# 伪代码：负向词表的logits processor
def negative_words_logits_processor(input_ids, scores, negative_words):
    for word_id in negative_words:
        scores[:, word_id] = -float('inf')  # 完全禁止
    return scores
```

### 4.5 多轮对话中的风格一致性维持

#### 4.5.1 风格漂移问题

在长文本生成或多轮对话中，模型的风格会逐渐漂移，偏离初始设定的风格。原因包括：
1. Context window中风格提示的占比逐渐降低
2. 生成内容自身的"惯性"影响后续生成
3. 不同场景下模型自然切换表达方式

#### 4.5.2 风格一致性维持策略

| 策略 | 实现方式 | 效果 | 成本 |
|------|---------|------|------|
| 风格锚点重复 | 每N轮重新插入风格描述 | ★★★☆☆ | 低 |
| 风格示例常驻 | 将Few-shot示例放在System Prompt中常驻 | ★★★★☆ | 中（占用context） |
| 分段生成+校验 | 每段生成后做风格检查，不达标则重写 | ★★★★★ | 高 |
| 风格微调 | 用LoRA将风格内化到模型中 | ★★★★★ | 中（训练成本） |
| 风格后处理 | 生成后用规则或模型调整风格 | ★★★☆☆ | 中 |

#### 4.5.3 昆仑引擎的推荐方案

```
短期（Prompt-based）：
1. System Prompt中常驻风格描述符 + 2-3个Few-shot示例
2. 每生成1000字，自动插入风格提醒（"请保持XX风格"）
3. 每章结束后做风格一致性检查（见7.4节）

中期（混合方案）：
1. 轻量风格LoRA适配器（可选）
2. Prompt风格描述符作为补充控制
3. 风格检查+自动重写

长期（微调方案）：
1. 作者风格LoRA适配器作为主要风格控制手段
2. Prompt仅用于场景级别的微调
3. 跨章节风格漂移检测与校正
```

### 4.6 结构化风格描述

完整的风格描述应覆盖四个层面：

#### 4.6.1 句法特征
- 平均句长、句长标准差、句长分布
- 简单句/复合句/复杂句比例
- 倒装句、省略句、疑问句的使用频率
- 标志性句式（如"XX之道，在于……"）

#### 4.6.2 词汇特征
- 高频词表（top 100）
- 作者专属词（显著高于通用语料的词）
- 生僻词比例、文言词比例
- 虚词使用偏好（"的/地/得"、"了/着/过"）
- 避免使用的词

#### 4.6.3 修辞特征
- 比喻频率、比喻类型（明喻/暗喻/借喻）
- 夸张、拟人、排比、对偶的使用频率
- 用典频率、引用频率
- 通感、反讽等高级修辞的使用

#### 4.6.4 叙事特征
- 叙事视角（第一/第三人称，全知/限制）
- 对话比例、对话格式
- 描写比例（环境/心理/动作/外貌）
- 叙事节奏（场景切换频率、高潮密度）
- 时间线处理（顺叙/倒叙/插叙）
- 段落长度分布

```python
def sentence_length_stats(text):
    """
    计算句长分布统计
    返回：平均句长、标准差、最大/最小句长、分布直方图
    """
    # 中文分句：按。！？；分句
    sentences = re.split(r'[。！？；]', text)
    sentences = [s.strip() for s in sentences if len(s.strip()) > 0]
    
    # 计算每句字数（含标点）
    lengths = [len(s) for s in sentences]
    
    stats = {
        "mean": np.mean(lengths),
        "std": np.std(lengths),
        "max": np.max(lengths),
        "min": np.min(lengths),
        "median": np.median(lengths),
        "percentiles": {
            "p25": np.percentile(lengths, 25),
            "p75": np.percentile(lengths, 75),
            "p90": np.percentile(lengths, 90),
        },
        "distribution": np.histogram(lengths, bins=[0,10,20,30,40,50,100,200])[0].tolist(),
        "short_ratio": sum(1 for l in lengths if l <= 15) / len(lengths),  # 短句比例
        "long_ratio": sum(1 for l in lengths if l >= 40) / len(lengths),   # 长句比例
    }
    return stats
```

def vocabulary_profile(text, reference_text=None):
    """
    分析用词偏好
    """
    words = jieba.lcut(text)
    word_freq = Counter(words)
    
    # 过滤停用词
    stopwords = load_stopwords()
    content_words = {w: c for w, c in word_freq.items() 
                     if w not in stopwords and len(w) > 1}
    
    result = {
        "top_n_words": word_freq.most_common(100),  # 高频词
        "vocabulary_richness": len(set(words)) / len(words),  # 词汇丰富度
        "hapax_legomena": sum(1 for w, c in word_freq.items() if c == 1) / len(word_freq),  # 一次词比例
        "average_word_length": np.mean([len(w) for w in words]),  # 平均词长
    }
    
    if reference_text:
        # 计算作者专属词（显著高于参考语料）
        ref_words = jieba.lcut(reference_text)
        ref_freq = Counter(ref_words)
        signature_words = {}
        for w, c in content_words.items():
            ref_c = ref_freq.get(w, 0)
            if ref_c > 0:
                ratio = (c / len(words)) / (ref_c / len(ref_words))
                if ratio > 2.0 and c > 5:
                    signature_words[w] = ratio
        result["signature_words"] = sorted(signature_words.items(), key=lambda x: x[1], reverse=True)[:50]
    
    return result
```

def rare_word_ratio(text):
    """
    计算生僻词比例
    生僻词定义：不在通用常用词表中的词
    """
    common_words = load_common_vocabulary()  # 通用常用词表（如现代汉语常用词表）

    content_words = [w for w in words if len(w) > 1 and not w.isdigit()]

def punctuation_profile(text):
    """
    标点使用偏好
    """
    punctuations = {
        "。": "period", "！": "exclamation", "？": "question",
        "，": "comma", "；": "semicolon", "：": "colon",

    }
    
    result = {}
    total_chars = len(text)
    for punct, name in punctuations.items():
        count = text.count(punct)
        result[name] = {
            "count": count,
            "per_1k": count / (total_chars / 1000),

    # 特殊指标

    return result

def style_similarity(text1, text2):
    """
    计算两段文本的风格相似度
    基于多维度风格特征的加权距离
    """
    features1 = extract_all_style_features(text1)
    features2 = extract_all_style_features(text2)
    
    # 归一化各维度到[0,1]
    weights = {
        "sentence_length": 0.15,
        "vocabulary": 0.20,
        "rhetoric": 0.10,
        "dialogue_ratio": 0.10,
        "description_ratio": 0.15,
        "paragraph_length": 0.10,
        "punctuation": 0.10,
        "perspective": 0.10,
    }
    
    total_distance = 0
    for feature, weight in weights.items():
        d = feature_distance(features1[feature], features2[feature])
        total_distance += weight * d
    
    similarity = 1 - total_distance  # 转换为相似度
    return max(0, similarity)
```

    # 修辞特征
    metaphor_per_1k: float = Field(description="每千字比喻次数")
    exaggeration_per_1k: float = Field(description="每千字夸张次数")
    parallelism_per_1k: float = Field(description="每千字排比次数")
    four_character_per_1k: float = Field(description="每千字四字格次数")
    
    # 叙事特征
    dialogue_ratio: float = Field(description="对话占比")
    action_desc_ratio: float = Field(description="动作描写占比")
    env_desc_ratio: float = Field(description="环境描写占比")
    psych_desc_ratio: float = Field(description="心理描写占比")
    perspective: str = Field(description="叙事视角")
    
    # 段落特征
    paragraph_mean_chars: float = Field(description="平均段落字数")
    paragraph_mean_sentences: float = Field(description="平均段落句数")
    single_sentence_para_ratio: float = Field(description="单句成段比例")
    
    # 标点特征
    exclamation_ratio: float = Field(description="感叹号/句号比")
    question_ratio: float = Field(description="问号/句号比")
    ellipsis_per_1k: float = Field(description="每千字省略号次数")
    
    # 向量表示（用于相似度计算）
    feature_vector: List[float] = Field(description="归一化后的特征向量，用于相似度计算")
    
    # 文本描述（用于Prompt生成）
    text_description: str = Field(description="自然语言风格描述，用于System Prompt")
    
    def similarity(self, other: "StyleFingerprint") -> float:
        """计算与另一个风格指纹的相似度"""
        import numpy as np
        v1 = np.array(self.feature_vector)
        v2 = np.array(other.feature_vector)
        cosine_sim = np.dot(v1, v2) / (np.linalg.norm(v1) * np.linalg.norm(v2))
        return float(cosine_sim)
    
    def to_prompt(self) -> str:
        """将风格指纹转换为Prompt描述"""
        return self.text_description
```

# kunlun/style/library.py

class StyleLibrary:
    """风格库 - 管理多作者风格的存储和切换"""
    
    def __init__(self, library_path: str):
        self.library_path = library_path
        self.fingerprints: Dict[str, StyleFingerprint] = {}  # style_id -> fingerprint
        self.adapters: Dict[str, StyleAdapter] = {}          # style_id -> LoRA适配器信息
        self.prompts: Dict[str, StylePrompt] = {}            # style_id -> Prompt模板
        
    def add_style(self, fingerprint: StyleFingerprint, 
                  adapter: Optional[StyleAdapter] = None,
                  prompt: Optional[StylePrompt] = None):
        """添加一个风格到库中"""
        style_id = fingerprint.author_id
        self.fingerprints[style_id] = fingerprint
        if adapter:
            self.adapters[style_id] = adapter
        if prompt:
            self.prompts[style_id] = prompt
        self._save()
    
    def get_style(self, style_id: str) -> StyleProfile:
        """获取一个风格的完整配置"""
        return StyleProfile(
            fingerprint=self.fingerprints[style_id],
            adapter=self.adapters.get(style_id),
            prompt=self.prompts.get(style_id),
        )
    
    def list_styles(self) -> List[Dict]:
        """列出所有可用风格"""
        return [
            {
                "style_id": fp.author_id,
                "author_name": fp.author_name,
                "style_name": fp.style_name,
                "has_adapter": fp.author_id in self.adapters,
                "sample_size": fp.sample_size,
            }
            for fp in self.fingerprints.values()
        ]
    
    def find_similar_style(self, text: str, top_k: int = 5) -> List[Tuple[str, float]]:
        """根据输入文本找到最相似的风格"""
        extractor = StyleFingerprintExtractor()
        text_fp = extractor.extract(text, "unknown", "input")
        
        similarities = []
        for style_id, fp in self.fingerprints.items():
            sim = text_fp.similarity(fp)
            similarities.append((style_id, sim))
        
        return sorted(similarities, key=lambda x: x[1], reverse=True)[:top_k]

# kunlun/gacha/scorer.py

class StyleScorer:
    """风格评分器 - gacha第10个评分维度"""
    
    def __init__(self, style_library: StyleLibrary):
        self.style_library = style_library
        self.extractor = StyleFingerprintExtractor()
    
    def score(self, text: str, style_id: str) -> float:
        """
        计算生成文本与目标风格的匹配度
        返回0.0-1.0的分数
        """
        # 1. 提取生成文本的风格特征
        text_features = self.extractor.extract_quick(text)
        
        # 2. 获取目标风格指纹
        target_fp = self.style_library.fingerprints[style_id]
        
        # 3. 计算多维度相似度
        dimensions = {
            "sentence": self._sentence_similarity(text_features, target_fp),
            "vocabulary": self._vocabulary_similarity(text_features, target_fp),
            "rhetoric": self._rhetoric_similarity(text_features, target_fp),
            "narrative": self._narrative_similarity(text_features, target_fp),
            "punctuation": self._punctuation_similarity(text_features, target_fp),
        }
        
        # 4. 加权平均
        weights = {
            "sentence": 0.25,
            "vocabulary": 0.30,
            "rhetoric": 0.10,
            "narrative": 0.25,
            "punctuation": 0.10,
        }
        total = sum(dimensions[k] * weights[k] for k in dimensions)
        return total
```

#### 7.5.1 漂移检测算法

```python
# kunlun/style/drift_detector.py

class StyleDriftDetector:
    """跨章节风格漂移检测器"""
    
    def __init__(self, style_library: StyleLibrary, threshold: float = 0.15):
        self.style_library = style_library
        self.extractor = StyleFingerprintExtractor()
        self.threshold = threshold  # 漂移阈值
        self.chapter_features = {}  # chapter_id -> feature_vector
    
    def check(self, chapter_id: str, text: str, target_style_id: str) -> DriftReport:
        """
        检查章节的风格漂移
        """
        # 1. 提取当前章节风格特征
        current_features = self.extractor.extract_quick(text)
        
        # 2. 获取目标风格
        target_fp = self.style_library.fingerprints[target_style_id]
        
        # 3. 计算与目标风格的距离
        distance_to_target = self._distance(current_features, target_fp.feature_vector)
        
        # 4. 计算与历史章节的漂移
        drift_from_history = 0
        if self.chapter_features:
            avg_history = np.mean(list(self.chapter_features.values()), axis=0)
            drift_from_history = self._distance(current_features, avg_history)
        
        # 5. 逐维度分析偏差
        dimension_drift = self._analyze_dimension_drift(current_features, target_fp)
        
        # 6. 生成报告
        report = DriftReport(
            chapter_id=chapter_id,
            target_style=target_style_id,
            distance_to_target=distance_to_target,
            drift_from_history=drift_from_history,
            is_drifted=distance_to_target > self.threshold,
            dimension_drift=dimension_drift,
            suggestion=self._generate_suggestion(dimension_drift),
        )
        
        # 7. 记录
        self.chapter_features[chapter_id] = current_features
        
        return report
    
    def _analyze_dimension_drift(self, current, target) -> Dict[str, float]:
        """分析每个维度的偏差"""
        return {
            "sentence_length": abs(current["sentence_mean"] - target.sentence_mean) / target.sentence_mean,
            "dialogue_ratio": abs(current["dialogue_ratio"] - target.dialogue_ratio),
            "vocabulary_richness": abs(current["vocabulary_richness"] - target.vocabulary_richness),
            "metaphor_frequency": abs(current["metaphor_per_1k"] - target.metaphor_per_1k),
            # ... 更多维度
        }
```

class DriftCorrector:
    """风格漂移校正器"""
    
    def correct(self, text: str, drift_report: DriftReport) -> str:
        """
        根据漂移报告校正文本风格
        """
        corrected = text
        
        # 句长漂移：拆分长句或合并短句
        if drift_report.dimension_drift.get("sentence_length", 0) > 0.2:
            corrected = self._adjust_sentence_length(corrected, drift_report)
        
        # 对话比例漂移：增加或减少对话
        if drift_report.dimension_drift.get("dialogue_ratio", 0) > 0.1:
            corrected = self._adjust_dialogue(corrected, drift_report)
        
        # 词汇漂移：替换标志性词汇
        if drift_report.dimension_drift.get("vocabulary", 0) > 0.2:
            corrected = self._adjust_vocabulary(corrected, drift_report)
        
        return corrected

## 10. 英文技术的中文适配方法

### 10.1 文本风格迁移技术的中文适配

| 英文技术 | 中文适配要点 | 适配难度 |
|---------|------------|---------|
| 基于平行语料的Seq2Seq迁移 | 中文平行语料稀缺，需构建或使用无监督方法 | ★★★★☆ |
| 基于VAE的风格解耦 | 中文分词影响latent space，需使用字级或BPE | ★★★☆☆ |
| 基于对抗训练的迁移 | 中文风格分类器需要单独训练 | ★★★☆☆ |
| Delete-Retrieve-Generate | 中文风格词表需要重新构建 | ★★☆☆☆ |
| 基于LLM的Prompt迁移 | 中文LLM能力足够，直接可用 | ★☆☆☆☆ |
| 风格分类器评估 | 需要中文风格分类数据集 | ★★★☆☆ |

### 10.2 计算风格学的中文适配

#### 10.2.1 分词问题
- 英文按空格分词，中文需要jieba等分词工具
- 分词准确性影响词汇特征计算
- 建议：同时计算字级和词级特征，字级特征更稳健

#### 10.2.2 句法分析
- 英文有成熟的句法分析器（Stanford Parser、spaCy）
- 中文句法分析工具较少且准确率较低
- 建议：使用基于规则的句长/标点特征，减少对深层句法分析的依赖
- 可选：使用LTP（哈工大语言技术平台）或HanLP进行中文句法分析

#### 10.2.3 修辞识别
- 英文修辞识别研究较多，中文修辞识别研究较少
- 建议：基于标志词的启发式方法 + 人工标注训练中文修辞识别模型

#### 10.2.4 作者识别
- 英文作者识别（如Federalist Papers）有经典研究
- 中文作者识别需要考虑文言/白话差异、繁简差异
- 建议：使用n-gram特征（字级n-gram对中文特别有效）+ 词汇特征

### 10.3 LoRA微调的中文适配

| 方面 | 英文模型 | 中文模型 | 适配要点 |
|------|---------|---------|---------|
| 基础模型 | Llama、Mistral | Qwen、DeepSeek、ChatGLM、Yi | 选择中文能力强的基础模型 |
| 分词器 | BPE（英文友好） | BPE/SentencePiece（中文优化） | 检查网文词汇的分词效果 |
| 数据格式 | 英文标点、段落 | 中文全角标点、短段落 | 保留原始格式，不要"规范化" |
| 训练文本 | 英文句子平均较长 | 中文句子较短 | max_seq_length可适当减小 |
| 评估指标 | BLEU、ROUGE | 中文BLEU（需分词）、BERTScore(中文) | 使用中文预训练模型计算BERTScore |

### 10.4 Prompt Engineering的中文适配

1. **风格描述语言**：用中文描述风格特征，比英文更精准（中文有丰富的风格评论词汇）
2. **Few-shot示例**：使用中文原文示例，不要翻译英文示例
3. **指令格式**：中文LLM对中文指令的遵循能力强于翻译后的英文指令
4. **负向提示**：中文负向提示需要考虑中文表达习惯（如"不要"比"avoid"更直接）
5. **文化语境**：中文网文有独特的文化语境（修仙、江湖、朝堂等），需要在Prompt中体现

## 11. 总结与实施路线图

### 11.1 核心发现

1. **Prompt-based是短期最优解**：当前LLM的指令跟随能力已经能实现基本的风格控制，无需训练即可上线
2. **LoRA是中长期核心技术**：在风格纯度和一致性上显著优于Prompt，且成本可控
3. **风格量化是基础**：无论Prompt还是微调，都需要量化的风格特征作为评估和控制依据
4. **数据是最大瓶颈**：高质量、合规的作者作品数据是风格学习的关键前提
5. **男频作者风格差异显著**：5位代表作者在句长、词汇、修辞、叙事等维度有明显可量化的差异
6. **中文适配需要针对性工作**：分词、句法分析、修辞识别等都需要中文特化处理
