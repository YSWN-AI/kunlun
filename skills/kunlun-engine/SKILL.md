# 昆仑创作引擎 (Kunlun Novel Writer)

> 基于10个专业AI Agent协作的智能网文创作系统

## 核心能力

本技能提供完整的网文创作解决方案，涵盖从灵感构思到大纲生成，从章节撰写到审计发布的全流程。

### 1. 写作引擎

**触发场景**：
- 用户要求"写一章小说"
- 用户提供写作意图，如"写主角觉醒异能的都市文"
- 用户需要续写现有章节

**执行流程**：

#### 步骤1：理解写作意图

1. 解析用户提供的写作需求
2. 识别故事类型（都市、玄幻、仙侠、科幻等）
3. 识别核心元素（主角、场景、情绪基调）

**示例输入**：
```
写作意图：写一章玄幻小说，主角在昆仑山巅觉醒异能，与妖兽激战
```

#### 步骤2：调用13步创作管线

当用户触发写作任务时，按以下流程执行：

```
KG快照 → Architect蓝图 → Society社会推演 → Writer抽卡生成
  → Auditor审计 → ICU质量检查 → StyleEngineer润色
  → KG更新 → 发布 → 状态机追踪
```

**管线说明**：

| 阶段 | 功能 | 输出 |
|------|------|------|
| Architect蓝图 | 生成章节结构、场景排布、情绪曲线 | 章节蓝图 |
| Writer生成 | 多模型抽卡生成正文 | 章节初稿 |
| Auditor审计 | 8道门禁+33维审计 | 审计报告 |
| StyleEngineer润色 | 去AI味+文风优化 | 润色稿件 |
| Publisher发布 | 落盘+格式导出 | 成品章节 |

#### 步骤3：输出章节内容

**输出格式**：
```markdown
# 第X章：章节标题

正文内容...

---

**字数**：X,XXX
**审计**：通过 (33/33)
**建议**：如有优化建议在此列出
```

### 2. 知识图谱管理

**触发场景**：
- 用户询问"角色关系"
- 用户需要"构建世界观"
- 用户要求"查看伏笔"

**核心功能**：

#### 2.1 实体管理

| 实体类型 | 说明 | 示例 |
|----------|------|------|
| 人物 | 角色信息 | 叶青云、主角、昆仑派弟子 |
| 地点 | 场景位置 | 昆仑山巅、长安城 |
| 物品 | 关键道具 | 昆仑镜、太清诀 |
| 事件 | 重要情节 | 觉醒、秘境探险 |
| 关系 | 实体连接 | 师徒、敌对、恋人 |

#### 2.2 查询指令

**示例**：
```
查询所有主角相关的实体
查看第一章的伏笔有哪些
列出昆仑派所有人物
```

#### 2.3 伏笔追踪

- 自动记录埋下的伏笔
- 标记伏笔回收节点
- 超期伏笔预警

### 3. 审计系统

**触发场景**：
- 用户需要"检查章节质量"
- 用户要求"审计报告"
- 用户想知道"有哪些问题"

**8道门禁 (G1-G8)**：

| 门禁 | 检查项 |
|------|--------|
| G1 弧线门禁 | 角色成长弧线是否完整 |
| G2 信息门禁 | 信息释放是否合理 |
| G3 去AI门禁 | 是否消除AI写作痕迹 |
| G4 爽点门禁 | 爽点间隔是否合适 |
| G5 多样性门禁 | 词汇/句式是否丰富 |
| G6 情绪门禁 | 情绪节奏是否合理 |
| G7 对话门禁 | 对话是否自然 |
| G8 战斗门禁 | 战斗描写是否精彩 |

**33维审计**：
- 角色一致性（6维）
- 情节连贯性（6维）
- 信息准确性（5维）
- 逻辑严密性（6维）
- 情感表达（5维）
- AI痕迹检测（5维）

---

### 4. 文风优化

**触发场景**：
- 用户需要"去AI味"
- 用户要求"优化文风"
- 用户想要"风格润色"

**核心能力**：

#### 4.1 去AI味规则

- 识别并替换AI常用句式
- 消除过度规范的标点使用
- 打破模板化段落结构

#### 4.2 文风指纹

- 建立作品独特的文风特征
- 保持多章节风格一致性
- 注入作者个人写作特色

#### 4.3 爽点引擎

- 识别12种爽点类型
- 分析爽点密度
- 提供疲劳度预警

---

### 5. 辅助功能

#### 5.1 大纲管理

- 章节大纲生成
- 故事线梳理
- 支线任务管理

#### 5.2 导出功能

支持导出格式：
- TXT（纯文本）
- Markdown（.md）
- EPUB（电子书）
- HTML（网页）
- PDF（打印版）

#### 5.3 写作统计

| 指标 | 说明 |
|------|------|
| 总字数 | 作品总字数 |
| 日均字数 | 每日写作产出 |
| 审计通过率 | 33维审计通过比例 |
| 完本率 | 预计完成度 |

## API接口

### 核心端点

| 方法 | 路径 | 功能 |
|------|------|------|
| POST | `/api/v1/books/{id}/chapters/{n}/generate` | 生成章节 |
| POST | `/api/v1/audit/run` | 执行审计 |
| GET | `/api/v1/kg/query` | 知识图谱查询 |
| GET | `/api/v1/search` | 全文搜索 |
| GET | `/api/v1/books/{id}/stats` | 获取统计 |

### 请求示例

**章节生成请求**：
```json
{
  "book_id": "昆仑变",
  "chapter": 1,
  "intent": "主角在昆仑山巅觉醒异能",
  "genre": "玄幻",
  "target_words": 3000
}
```

**审计请求**：
```json
{
  "chapter_content": "章节正文内容...",
  "check_levels": ["gates", "dimensions33"]
}
```

## 错误处理

### 常见错误

| 错误类型 | 原因 | 解决方案 |
|----------|------|----------|
| 后端未连接 | Python服务未启动 | 检查端口8000是否开启 |
| API Key缺失 | 环境变量未配置 | 配置DeepSeek/OpenAI Key |
| 知识图谱不可用 | Neo4j服务未启动 | 使用SQLite降级模式 |
| 模型超时 | API调用超时 | 重试或更换模型 |

### 重试机制

- 自动重试：最多3次，间隔2秒
- 降级策略：多模型并行 → 单模型 → 本地缓存

## 使用示例

### 示例1：生成章节

**用户输入**：
```
帮我写一章玄幻小说，主角在昆仑山巅遭遇妖兽袭击，觉醒异能将其击败
```

**Skill执行**：

2. 加载相关角色和世界观
3. 执行13步管线
4. 输出章节和审计报告

```
查看昆仑派有哪些角色，他们之间的关系是什么
```

**Skill执行**：
1. 查询昆仑派相关实体
2. 获取关系网络
3. 输出角色关系图

### 示例3：章节审计

**用户输入**：
```
审计一下第三章，看看有什么问题
```

**Skill执行**：
1. 执行8道门禁检查
2. 执行33维审计
3. 输出问题清单和修复建议

## 限制与注意事项

1. **字数限制**：单次生成建议3000-5000字，超长章节建议分段生成
2. **API依赖**：需要配置有效的LLM API Key
3. **存储要求**：建议预留5GB以上空间用于知识图谱和版本管理
4. **网络要求**：需要访问DeepSeek/OpenAI API（国内用户推荐DeepSeek）
5. **上下文窗口**：建议单次对话不超过10轮，超出建议开启新对话
