# 长篇网文项目协作规则

本文件适用于本目录及全部子目录，只负责启动顺序、资料路由、权威边界、记忆分层和更新权限。具体题材审美、剧情事实与正文施工细节由对应项目文件负责。

## 一、每次开始工作

1. 先读本文件。
2. 读取 项目档案/项目配置.md 与 项目档案/项目状态.md，确认项目阶段、当前任务和仍待确认的问题。
3. 除“初始化新小说项目”外，完整读取 项目档案/作者长期偏好.md 与 项目档案/本书创作原则.md。
4. 从 项目档案/创作日志.md 中只读取最近1—3条与本次任务相关的定稿记录；追查旧决定时再按索引读取归档。
5. 按 项目档案/资料索引.md 路由，只读取本次任务真正涉及的大纲、人物、设定、摘要或正文资料。
6. 写大纲、导演卡、正文或人物前，核对姓名、时间、地点、资源、能力、物品、关系、知情边界、已发生事件和未回收伏笔。
7. 不凭聊天上下文直接续写。项目文件是跨会话权威记忆，当前对话中的候选方案不是既定事实。

## 二、初始化例外

当用户第一次说“初始化新小说项目”或同义表达时：

1. 读取 项目档案/新项目初始化向导.md。
2. 盘点目录中已有材料，不假定用户已经完成任何设定。
3. 按向导分阶段交流；每一阶段经用户确认后，才写入相应权威文件。
4. 未确认创意、推断和备选方向只进入 项目档案/候选推断与待确认事项.md。
5. 初始化完成前，不直接生成正式正文。

## 三、资料权威顺序

- 作者跨项目的稳定偏好：项目档案/作者长期偏好.md。
- 当前小说的阅读体验、风格和禁区：项目档案/本书创作原则.md。
- 主题、高概念、故事发动机与长线：核心创作纲领.md。
- 人物事实：人物/ 下对应人物专属档案。
- 世界规则、力量或系统边界：设定/世界观与核心规则.md。
- 时间、地点、资源、物品、关系和知情边界：设定/连续性台账.md。
- 已发生或已规划事件：最新阶段大纲；正文造成的明确变更必须同步回权威大纲。
- 当前有效进度与入口：项目档案/项目状态.md。
- 下一章精确衔接：项目档案/正文进度.md 中最新衔接卡。
- 远期常规回顾：剧情摘要/ 下对应区间摘要。
- 已落地变更历史：近期创作日志及其冷归档。

文件冲突时不得静默综合，也不得自行创造第三种解释。先把冲突登记进 项目档案/候选推断与待确认事项.md 和 项目状态.md 的待确认区，说明冲突来源与影响，等待用户确认后再统一。

## 四、三级项目记忆

### 1. 远期宏观记忆

- 剧情摘要/ 按 项目配置.md 中的摘要区间建立，默认每50章一个不重叠区间。
- 摘要保存区间主因果、区间结束硬状态、人物变化、伏笔坐标、阶段设计逻辑、权威来源和正文覆盖状态。
- 跨越远期区间时默认读摘要，不逐章重读全部正文或旧章纲。
- 修改旧章、精确回收伏笔或核查冲突时，才回到对应权威原文件。

### 2. 当前正文衔接

- 项目档案/正文进度.md 只保存正文总进度、当前工作章和最新一章衔接卡。
- 准备紧邻下一章时默认读取最新衔接卡，不回读上一章全文。
- 最新衔接卡只记录会影响下一章的硬状态，不保存修辞和普通对白。

### 3. 冷历史

- 项目档案/历史正文衔接卡归档/ 保存旧章完整衔接卡。
- 项目档案/创作日志归档/ 保存较早的定稿变更。
- 冷归档不参与日常续写，只有核查旧决定、旧章站位、章末原句或冲突时才精准读取。

## 五、大纲与人物流程

- 讨论全书定位、核心矛盾、故事发动机或长期结构时，读取核心创作纲领及相关设定。
- 讨论阶段剧情时，读取全书结构、上一阶段结束状态、当前阶段大纲、相关人物档案与连续性台账。
- 阶段大纲必须说明阶段目标、开头与结尾硬状态、核心冲突、人物变化、伏笔、逐章推进及不得提前发生的内容。
- 涉及具名人物时先检索 人物/。正式出现并承担持续剧情功能的人物，应建立专属档案。
- 新人物方向、隐藏动机和未来路线若只是AI推断，先进入候选区，不得直接写入人物档案。

## 六、正文专属流程

用户说“准备第X章”“开始第X章”、要求导演卡、分场口述、整理、合并或定稿时，必须读取：

- 项目档案/正文协作流程.md
- 项目档案/正文进度.md
- 目标章最新阶段大纲
- 相关人物档案、设定与连续性条目

正文固定采用：

章纲 → 导演卡 → 用户分场口述 → AI忠实整理 → 计划场景完成后自动确认 → 用户要求整章合并 → 合并检查并直接定稿。

不从章纲直接自由扩写正式正文。每章只使用一份 正文工作区/第XXX章工作稿.md。

## 七、事实与推断

### 可以自动记录的明确事实

- 正式正文中明确发生的事件、行动、台词和结果。
- 明确的时间、地点、物品、资源、伤势、身份、关系和知情状态变化。
- 会直接影响下一章的现场状态和未解决问题。

这些内容可自动进入最新衔接卡；影响后文的硬事实可同步连续性台账、项目状态及相应权威资料。

### 不得自动升级的推断

- 性格趋势、隐藏动机、象征意义、伏笔解释。
- 未明说的关系结论、能力上限和未来选择。
- 仅凭一次动作或一句台词推测出的长期人物方向。

以上只进入候选推断区，用户确认后才可写入权威档案。

## 八、更新与日志

- 只有用户已确认或明确授权执行、且决定已经落入权威文件时，才追加创作日志。
- 脑暴、候选方案、未确认推断和无变化占位不写入日志。
- 项目状态只保存当前有效事实；日志保存已经落地的变化历史。
- 正文定稿后必须执行资料同步矩阵，不能只保存正文。
- 任何更新都只修改真正受影响的文件，避免把相同信息复制到所有资料中。
- 新项目初始化时生成项目代号，将各Markdown权威文件元数据中的 project_id、date_created、date_updated 和 status 更新为实际值；结构模板仍保留 template 状态。
- 后续修改带元数据的文件时同步更新 date_updated，不虚构过去日期。

## 九、当前入口

当前项目状态、下一步和待确认事项以 项目档案/项目状态.md 为准。本节不重复项目事实，避免入口规则随剧情频繁改写。
