# 把小说当成一个项目：Agent 长篇网文写作模板使用说明

这不是一组“让AI帮我写小说”的提示词，而是一套把长篇小说当成长期项目来管理的创作模板。

你仍然可以像平时一样和AI聊天、讨论人物、修改剧情、口述正文，但人物、设定、大纲、正文进度和长期伏笔不再只存在于聊天记录里。Agent会按照项目规则判断本次应该读取哪些资料、哪些已确认内容应该保存到哪里，以及正文定稿后需要同步哪些状态。

它最适合以下情况：

- 准备长期连载一部长篇网文。
- 经常和AI讨论创意，但不想自己反复整理资料。
- 人物、设定和大纲会在写作过程中不断调整。
- 希望降低AI遗忘前文、人物写偏和设定冲突的概率。
- 希望保留自己的剧情控制权和表达习惯，而不是把整章完全交给AI代写。

## 一、普通AI写作和Agent写作有什么区别

### 1. 普通提示词写作：核心仍然是一场对话

传统AI写作通常是这样的：

1. 把提示词发给AI。
2. 把人物资料、大纲或上一章粘贴进聊天框。
3. 让AI扩写、续写或修改。
4. 自己把结果复制出来保存。

这种方式并不是不能用。写短文、写单章、临时改稿时，它很方便。

但长篇小说越写越长以后，问题会逐渐出现：

- 重要设定散落在不同聊天记录里。
- 每次都要自己判断应该把哪些资料重新发给AI。
- 人物修改以后，大纲、后续剧情和设定文件不一定同步。
- AI可能把讨论中的候选方案误当成已经确认的事实。
- 为了让AI记住前文，只能不断塞入更多材料，最后上下文越来越臃肿。
- 聊天结束后，很多灵感没有进入可长期使用的资料体系。

它的基本工作单位是“这一轮对话”。

### 2. Agent写作：核心变成了一个持续维护的项目

Agent写作的变化，不只是模型变聪明了，而是工作方式变了。

小说不再只是聊天框里的一段上下文，而是一个包含人物、设定、大纲、进度、正文和历史记录的完整项目。Agent除了回答当前问题，还会根据规则完成三件事：

- 判断本次任务需要读取哪些资料。
- 判断新确认的信息应该写入哪个权威文件。
- 判断一次修改会影响哪些后续资料，并进行同步或提出冲突。

例如，用户确认某个人物从“遇事冲动”调整为“表面冲动，关键选择时非常克制”。

普通聊天可能只在当前回复里记住这个变化。换一个会话后，如果没有重新提供资料，AI可能又写回旧性格。

在项目式写作中，Agent会先判断：

- 这是已经确认的人物事实，还是仍在讨论的候选方向？
- 应该修改哪一份人物档案？
- 尚未写出的阶段大纲里，是否有依赖旧性格的行动？
- 连续性台账或项目状态是否受到影响？
- 已经定稿的旧章节是否真的冲突？

如果只是影响未来，Agent可以更新人物档案和未写大纲；如果和已定稿正文发生硬冲突，它不会悄悄重写历史，而是把冲突列出来交给用户决定。

所以这里的“自动”，不是让AI不受控制地修改一切，而是让它按照明确规则维护受影响的资料。

### 3. 两种方式的核心差异

| 对比项 | 普通提示词写作 | Agent项目写作 |
| --- | --- | --- |
| 基本单位 | 一次聊天或一个提示词 | 一整部持续维护的小说项目 |
| 长期记忆 | 依赖聊天记录和人工粘贴 | 依赖结构化项目文件 |
| 资料读取 | 用户判断该发什么 | Agent按规则自动路由 |
| 创意保存 | 用户自己复制和分类 | 确认后进入对应权威资料 |
| 修改影响 | 容易只改当前回答 | 检查人物、大纲、设定和进度的关联 |
| 长篇续写 | 上下文越来越大 | 近期、远期和冷历史分层读取 |
| 用户角色 | 提示词提供者和结果筛选者 | 主笔、导演和最终决策者 |
| AI角色 | 临时生成文本 | 项目助理、剧情顾问、连续性检查者和文字编辑 |

## 二、这套模板真正的核心：AGENTS.md

项目根目录中的 AGENTS.md，可以理解为整个小说项目的“总路由”和“工作章程”。

它通常不保存某个角色的具体年龄，也不保存某一章发生了什么。它负责告诉Agent：

- 每次开始工作先读什么。
- 不同任务应该去哪里找资料。
- 哪份文件对哪类信息拥有最高权威。
- 什么内容可以自动更新。
- 什么内容必须等待用户确认。
- 发生冲突时应该怎样处理。
- 正文定稿以后需要同步哪些资料。

整个工作过程可以理解为：

~~~text
用户正常聊天或发出任务
        ↓
Agent先读取 AGENTS.md
        ↓
读取项目状态与项目配置
        ↓
判断本次属于创意、人物、大纲、设定还是正文任务
        ↓
只读取真正相关的资料
        ↓
完成讨论、整理或写作
        ↓
把已确认内容更新到对应权威文件
        ↓
同步进度、衔接、日志或待确认事项
~~~

这就是为什么使用者不需要每次自己记住：

“这次应该让AI读人物档案，还是先读第三阶段大纲？”

只要项目规则已经建立，Agent会自行判断。

不过有一个前提：你使用的AI环境必须具备读取和修改项目文件的能力，并且能够识别项目级指令文件。普通网页聊天如果无法访问这些文件，就只能把本模板当作人工资料结构使用，无法实现完整的自动路由和回写。

## 三、为什么要把资料拆成一棵树

长篇小说最怕的不是资料少，而是所有资料都混在一起。

人物性格、世界设定、阶段剧情、正文细节、历史废案和作者偏好如果全部堆进一个大文档，AI每次都要读很多无关内容，也很难判断哪句话仍然有效。

这套模板把资料拆成不同职责：

~~~text
小说项目
├─ AGENTS.md                  项目总路由与工作规则
├─ 核心创作纲领.md            这本书为什么成立、如何长期推进
├─ 项目档案/
│  ├─ 项目配置.md             书名、篇幅、章节和记忆参数
│  ├─ 作者长期偏好.md         跨作品保持稳定的个人审美
│  ├─ 本书创作原则.md         当前小说的风格、节奏和禁区
│  ├─ 项目状态.md             当前写到哪里、下一步是什么
│  ├─ 资料索引.md             不同任务应该读取哪些文件
│  ├─ 正文协作流程.md         导演卡、口述、整理和定稿规则
│  ├─ 正文进度.md             最新正文状态和上一章衔接
│  ├─ 创作日志.md             最近已经落地的修改历史
│  └─ 候选推断与待确认事项.md  未确认创意、AI推断和资料冲突
├─ 设定/                      世界规则与连续性硬状态
├─ 人物/                      每个持续人物的权威档案
├─ 故事大纲/                  全书结构和各阶段详细大纲
├─ 剧情摘要/                  跨几十章使用的远期压缩记忆
├─ 正文工作区/                导演卡与分场口述整理稿
└─ 正文/                      已经正式定稿的章节
~~~

这种分类不是为了显得专业，而是为了让每份资料只回答一种问题。

### 作者长期偏好和本书原则为什么要分开

作者可能在多部作品里都不喜欢说教、喜欢强冲突、偏好克制的情感表达。这些属于作者长期偏好，可以随着新项目继续使用。

但某一本书可能要求轻松、快节奏；另一本书可能要求压抑、悬疑和慢热。这些只属于当前小说，应该进入本书创作原则。

如果混在一起，上一部书的写法很容易限制下一部书。

### 项目状态和创作日志为什么要分开

项目状态只保存“现在什么是真的”。

创作日志保存“我们曾经改过什么、为什么改、替代了哪个旧决定”。

需要续写时看状态，需要追查历史时才看日志。这样AI不会把已经废弃的旧方案重新捡回来。

### 人物档案和阶段大纲为什么要分开

人物档案回答“这个人是谁”。

阶段大纲回答“这个阶段他做了什么”。

人物事实以人物档案为准，事件安排以最新阶段大纲为准。两者冲突时必须提出，不能让AI自己拼出第三个版本。

### 候选推断为什么单独保存

正文中一个人物沉默了，不一定代表他“从此变得冷漠”；一次保护别人，也不一定足以证明他“本性善良”。

Agent可以发现这些可能性，但不能把推测直接升级成人物事实。因此模板专门设置候选区：

- 正文明说的事实，可以自动记录。
- AI分析出的性格趋势、隐藏动机和伏笔解释，先等待用户确认。

这可以显著减少人物被AI越分析越偏的问题。

## 四、长篇小说怎样解决“记不住前文”

很多人使用AI写长篇时，会尝试把前几十章甚至全部正文重新发给AI。

这种方式成本很高，而且信息越多不代表判断越准。真正需要的是让不同距离的剧情使用不同精度的记忆。

本模板采用三级记忆。

### 第一层：最新正文衔接卡

只服务紧邻下一章。

它记录上一章结束时：

- 时间和地点。
- 人物站位与状态。
- 关系和知情边界。
- 资源、能力和关键物品。
- 尚未解决的问题。
- 章末画面或关键台词。

准备下一章时，通常读这张卡就够了，不需要重新读取上一章全文。

### 第二层：远期剧情摘要

默认每50章建立一个高精摘要，区间可以在项目配置中修改。

它不逐章复述，而是压缩：

- 这一阶段的主因果。
- 区间结束硬状态。
- 核心人物变化。
- 长线伏笔及回收位置。
- 后续不能丢的设计逻辑。

写到第51章以后，需要回顾前50章时，优先读取摘要，而不是重新读取50章正文。

### 第三层：冷历史归档

旧衔接卡和较早的创作日志都会进入冷归档。

它们平时不参与写作。只有需要核查某一章的站位、旧决定、原句或冲突时，Agent才精准调取。

这样既保留了历史，也不会让历史资料一直占用当前上下文。

## 五、第一次使用：怎样建立一本新书

### 第一步：复制整个模板

不要只复制 AGENTS.md，也不要只复制 README。

请复制完整的 通用小说创作模板 文件夹，把副本改成你的小说名。每一部小说使用一份独立副本，不要让多本书共用同一套项目状态和人物资料。

### 第二步：把已有材料放进去

你可以放入：

- 零散创意。
- 旧版大纲。
- 已有正文。
- 人物卡。
- 世界观笔记。
- 参考作品分析。
- 语音转写或聊天记录。

没有任何材料也没关系。

### 第三步：在这个目录中开启Agent任务

然后说：

> 初始化新小说项目

Agent会先盘点材料，不会一上来要求你填写一张很长的表格。

### 第四步：完成六个初始化阶段

初始化按以下顺序进行：

1. 材料盘点：区分有效资料、旧方案、候选和冲突。
2. 作品定位：确认题材、读者、核心卖点、阅读体验和篇幅。
3. 故事发动机：确认主角为什么不断行动，剧情为什么可以持续写长。
4. 人物与世界：建立主角、首阶段核心人物和必要规则。
5. 长线与第一阶段：确定全书大方向和第一阶段可执行大纲。
6. 开篇施工准备：把项目推进到可以制作第一章导演卡的状态。

每一阶段确认后才会进入权威文件。你不需要在第一天就把几百万字的内容全部想清楚。

## 六、日常怎么和它一起创作

### 1. 正常聊天和头脑风暴

你可以像平时一样说：

> 我想让主角下一阶段遇到一个看起来无解的问题，你先帮我想几个方向。

这时内容默认仍是讨论方案，不会自动变成正式设定。

如果你选定了一个方向，可以明确说：

> 这个方向确定，更新进当前阶段大纲，并同步相关人物和项目状态。

Agent会判断应该更新哪些文件，而不需要你逐个指定路径。

### 2. 修改人物或设定

可以直接说：

> 确定把这个人物调整为表面嘴硬，但真正遇到责任时不会逃。请检查这项修改会影响哪些未写剧情。

Agent应当：

- 更新对应人物档案。
- 检查未写阶段大纲。
- 检查连续性和知情边界。
- 遇到与已定稿正文的冲突时先报告，不私自重写。
- 完成更新后记录必要的创作日志。

### 3. 规划阶段剧情

可以说：

> 从第21章的结束状态继续规划第22—30章。

Agent会读取：

- 当前项目状态。
- 上一阶段结束状态。
- 相关人物档案。
- 世界规则和连续性台账。
- 当前阶段真正需要的历史摘要。

它不会默认把全书正文全部重新读一遍。

### 4. 准备一章正文

当你说：

> 准备第12章。

Agent不会直接写出一整章，而是先制作导演卡，并写入这一章唯一的工作稿。

导演卡会提前想清楚：

- 本章唯一核心任务。
- 开头和结尾必须处于什么状态。
- 本章拆成哪几个场景。
- 每场有哪些人物。
- 双方各自想得到什么。
- 冲突焦点是什么。
- 对话或行动结束后局面怎样变化。
- 哪些细节必须出现。
- 哪些剧情绝对不能提前写。
- 用户口述每一场时需要回答什么。

### 5. 分场口述

接下来可以说：

> 开始第12章第一场。

Agent会先给出这一场的口述提示。你不需要说得像正式小说，可以重复、停顿、只讲大概，也可以直接说关键台词。

口述时可以使用这些指令：

- “这句话尽量原样保留。”
- “这个意思帮我说顺。”
- “这里补一点动作。”
- “这里不要展开。”
- “这里不要煽情。”
- “这部分我没想好，先给我几个选择。”

口述结束后说：

> 整理这一场。

Agent会删除口头重复、调整句序、补少量动作和环境，让内容成为可阅读的小说文字，并保存进工作稿。

### 6. 整章合并和定稿

所有计划场景完成后，说：

> 整合这一章。

这句话代表：

- 按已经确认的顺序合并全部场景。
- 统一人物声音、称谓、视角和时态。
- 检查连续性、剧情结果和章末钩子。
- 保存正式正文。
- 更新最新衔接卡。
- 把旧衔接信息追加到冷归档。
- 同步正文明确产生的硬事实。
- 把AI推断单独放入候选区。

如果只想先看全文、不希望进入正式正文，请说：

> 只合并预览，先不要定稿。

## 七、为什么采用“导演卡＋分场口述”

### 1. 导演卡解决“不知道这一场该写什么”

很多人不是没有故事，而是一进入正文就容易漏信息、跑题或把高潮提前写掉。

导演卡先把每场的任务、冲突、进入方式和退出状态拆清楚。用户不需要同时考虑整章所有问题，只需要完成眼前这一场。

### 2. 口述能减少明显的AI味

完全让AI根据大纲自由扩写，文字很容易出现：

- 角色说话过于完整。
- 情绪被旁白总结。
- 每一段都像标准范文。
- 人物声音越来越相似。
- AI为了把情节写满而擅自补充剧情。

口述把人物态度、关键台词、停顿方式和情绪尺度留在作者手里。AI主要负责把口语整理成顺畅文本，因此更容易保留作者自己的表达习惯。

### 3. 作者仍然控制内容

用户决定：

- 人物到底怎么选。
- 哪句话必须保留。
- 这场戏要不要煽情。
- 冲突最后落在哪里。
- 哪个信息现在不能说。

AI负责：

- 提醒漏掉的必要信息。
- 检查前后连续性。
- 整理语言和动作。
- 控制信息密度。
- 发现可能的冲突。

这不是把写作完全外包，而是把AI放在剧情顾问、场记和文字编辑的位置。

### 4. 写作能力能够积累

如果每一章都让AI直接生成，作者积累的往往只是“判断这段好不好”。

通过导演卡和口述，作者仍然需要思考人物目的、场景冲突、关键台词和情绪变化。写得越多，对场景和人物的判断会越来越清楚。

最终得到的不只是一本书，也是一套会随着创作不断完善的个人写作方法。

## 八、Agent会自动做什么，不会自动做什么

### 会自动做

- 按任务判断需要读取哪些资料。
- 把用户明确确认的创意写入对应权威文件。
- 正文定稿后记录下一章需要的硬状态。
- 同步明确的时间、地点、资源、关系和人物状态变化。
- 检查人物、大纲、设定和正文之间的冲突。
- 维护当前状态、远期摘要和冷历史。
- 把值得讨论但尚未确认的推断放入候选区。

### 不会擅自做

- 不把头脑风暴自动当成定稿。
- 不把AI对人物的理解直接当成人物事实。
- 不因修改未来设定就悄悄重写已定稿章节。
- 不在用户口述之外新增重要事件、秘密人物或新支线。
- 不为了让资料显得完整而提前锁死所有后期内容。
- 不遇到资料冲突时自行拼出一个折中版本。

## 九、推荐使用口令

### 初始化与状态

- “初始化新小说项目。”
- “检查当前项目还缺哪些建档内容。”
- “汇报当前大纲、正文和待确认事项。”
- “检查项目资料是否存在冲突。”

### 创意与大纲

- “这个只是候选方向，先不要写入正式设定。”
- “这个方案确定，更新到对应权威资料。”
- “继续完善全书结构。”
- “规划第X—X章。”
- “检查这个阶段是否符合本书创作原则。”

### 人物与设定

- “建立某某的人物档案。”
- “检查这个人物当前有哪些已确认事实。”
- “这个性格调整确定，请检查受影响的未写剧情。”
- “把这条推断放入候选区，暂时不要定稿。”

### 正文

- “准备第X章。”
- “开始第X章第一场。”
- “整理这一场。”
- “整合这一章。”
- “只合并预览，先不要定稿。”

## 十、使用时最重要的几个习惯

### 1. 明确区分讨论和确认

推荐主动使用这些词：

- “先讨论。”
- “这是候选。”
- “这个确定。”
- “用新方案替代旧方案。”
- “这个方向废弃，以后不要恢复。”

这样Agent更容易准确判断哪些内容可以进入权威文件。

### 2. 不必每次指定要读哪个文件

只要AGENTS.md、资料索引和项目状态维护正常，你可以直接说要做什么。Agent应该先判断任务类型，再读取对应资料。

只有当你明确希望它核对某份旧材料时，才需要点名文件。

### 3. 定期让Agent检查项目健康

写完一个阶段或进行较大修改后，可以说：

> 检查当前人物、设定、大纲、正文和长期摘要是否一致。

这适合发现：

- 人物年龄或身份变化没有同步。
- 时间线和资源数量对不上。
- 已废弃方案仍残留在旧大纲。
- 正文新增事实没有进入后续资料。
- 伏笔已经移动，但摘要仍保留旧坐标。

### 4. 分享时必须分享整个目录

README只是说明书，AGENTS.md只是路由。真正让系统运行的是完整目录和各文件之间的分工。

如果只分享一段提示词，项目记忆、自动路由和定稿回写都会失效。

### 5. 保留备份

Agent项目会持续修改文件。建议使用版本管理、云盘历史版本或定期备份，尤其是在大规模重排大纲、替换人物路线和批量同步资料之前。

## 十一、常见问题

### 这套模板只能写系统爽文吗？

不是。模板只规定项目管理和协作流程，不绑定题材。系统、力量体系、行业机制和对话比例都属于可选配置。

### 可以把已经写了一部分的旧书放进去吗？

可以。初始化时先进行材料盘点，区分正式正文、有效大纲、旧方案和互相冲突的资料，再逐步建立项目状态和长期摘要。

### 每次打开新会话都要把资料重新上传吗？

如果Agent始终在同一个项目目录中工作，并拥有读取文件的权限，通常不需要。它会从AGENTS.md和项目状态开始恢复工作。

### Agent真的能永久记住整本书吗？

严格来说，不是模型永久记住，而是项目文件替它保存记忆。每次工作时，Agent根据规则读取当前需要的部分。可靠性来自可检查的文件，而不是依赖聊天记忆。

### 为什么不让AI直接根据大纲写完整正文？

可以做到，但这套模板有意选择用户口述主导。目标是保留作者的剧情控制、人物语气和思考过程，同时让AI承担整理、补缝和检查工作。

### 文件这么多，会不会更麻烦？

这些文件主要是给Agent路由和维护的。使用者日常仍然可以直接聊天，不需要每次手工打开全部文件。分类越清楚，长篇写到后期反而越省事。

## 十二、最后理解这套工具的一句话

普通AI写作，是你每次把资料交给AI，请它完成当前这一段。

Agent项目写作，是你和AI共同维护一部持续成长的小说：你负责创意、判断和表达，Agent负责把这些决定放到正确的位置，并在下一次创作时重新找到它们。

AI不再只是临时帮你写几段文字。

它开始参与管理整本书。
