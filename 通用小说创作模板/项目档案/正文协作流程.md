# 正文协作流程

## 一、触发方式

当用户说“准备第X章”“开始第X章”“做第X章导演卡”或意思相同时，启动本流程，不从章纲直接自由扩写正式正文。

## 二、协作角色

- 用户是主笔和导演，决定剧情原意、人物态度、关键台词、情绪尺度和最终取舍。
- AI是剧情顾问、场景拆解者、连续性检查者和文字编辑，不擅自发展重要剧情。
- 阶段大纲规定本章必须发生什么。
- 单章导演卡规定本章怎样分场。
- 用户口述决定场景实际内容。
- AI负责忠实整理、有限补缝和一致性检查。

## 三、章节状态

章节依次进入：

未规划 → 已有章纲 → 导演卡就绪 → 分场口述中 → 场景完成 → 仅合并预览 / 已正式定稿

各状态含义：

1. 未规划：尚无已确认章纲。
2. 已有章纲：本章事件已在阶段大纲中确认，但没有施工导演卡。
3. 导演卡就绪：导演卡已写入唯一工作稿，等待口述。
4. 分场口述中：至少一场正在口述或整理。
5. 场景完成：全部计划场景已口述整理，内容自动视为已确认，等待用户要求合并。
6. 仅合并预览：用户明确要求只看整章，不进入正式正文。
7. 已正式定稿：整章已保存到正文目录并完成资料同步。

导演卡、口述整理稿和预览稿均不是正式正文事实。

## 四、开始一章前的读取顺序

1. 根目录 AGENTS.md。
2. 项目配置、项目状态、作者长期偏好和本书创作原则。
3. 最近1—3条与目标章相关的创作日志。
4. 本文件与 正文进度.md 最新衔接卡。
5. 目标章对应的最新阶段大纲。
6. 相关人物档案、世界规则和连续性条目。
7. 跨越远期区间时，再读取对应剧情摘要和目标章前近期大纲。
8. 核对姓名、时间、地点、资源、能力、物品、关系、知情边界、前章钩子和本章结束状态。

默认不读取全部历史正文或全部冷归档。

只有以下情况才回读相关正式正文片段：

- 与上一章属于同一场景的无缝续接，衔接卡不足以确认动作或站位。
- 需要逐字回扣旧台词、物件描写或章末原句。
- 衔接卡、台账和正文疑似冲突。
- 用户明确要求核对或模仿某段正文。

## 五、制作单章导演卡

AI将导演卡直接写入 正文工作区/第XXX章工作稿.md。聊天默认只汇报章名、核心任务、场景数量、主要风险和工作稿路径。

导演卡至少包含：

- 本章唯一核心任务。
- 主要阅读回报：爽点、情绪、信息、反转或悬念。
- 开头硬状态与结尾硬状态。
- 三至五个核心场景及篇幅权重。
- 每场地点、人物、进入方式和退出方式。
- 每场核心对话或交锋双方。
- 双方各自目的、冲突焦点和谈完后的局面变化。
- 必须出现的动作、道具、环境与可见细节。
- 必须保留的台词、情绪动作和伏笔。
- 不能提前透露、不能改变和容易写坏的内容。
- 针对每场的明确口述问题。

用户直接开始第一场口述，即视为接受当前导演卡。用户可在口述前或口述过程中修改导演卡。

## 六、建立唯一工作稿

每章只使用一份工作稿：

正文工作区/第XXX章工作稿.md

工作稿依次保存：

- 已确认导演卡。
- 每场用户原意与锁定要求。
- 每场口述整理正文。
- 编辑说明与必要问题。
- 整章预览或定稿合并稿。
- 整章检查结果。
- 定稿与资料同步记录。

工作稿定稿后仍保留，用于追溯用户口述与编辑过程。

## 七、用户分场口述

默认一次只处理一个场景。AI先提示本场必须解决的事情，再等待用户口述。

用户口述可以重复、停顿或只说大意。下列表达视为明确编辑指令：

- “这句话尽量原样保留。”
- “这个意思帮我说顺。”
- “这里可以补一点动作或环境。”
- “这里不要展开。”
- “这里不要煽情。”
- “这里我没想好，先给我选择。”

每场口述后：

1. AI整理并写入当前章节工作稿。
2. 记录保留了什么、补了什么、是否仍有必要问题。
3. 聊天只汇报简要进度和下一场重点，除非用户要求查看全文。
4. 不要求用户逐场回复“确认”。

全部计划场景完成后自动进入“场景完成”，但不得自动合并整章。

只有出现硬冲突、缺少必要场景、无法判断用户原意或必须超出默认编辑权限时，才暂停提问。

## 八、AI默认编辑权限

### 可以直接处理

- 删除口述中的重复、停顿和无效绕话。
- 调整句序，使叙述和对话自然连贯。
- 区分人物语气和说话习惯。
- 补少量动作、表情、站位、环境、道具和感官细节。
- 补必要的场景过渡与因果连接。
- 用已经存在的内容加强节奏、冲突和章末钩子。
- 检查题材要求、连续性、人物状态和现实边界。
- 按项目配置控制单场信息密度和章节长度。

### 未经用户同意不得处理

- 改变剧情结果、人物选择、关键态度或场景顺序。
- 新增重要事件、具名人物、人物秘密或新支线。
- 改变世界规则、系统任务、资源属性、时间或地点状态。
- 擅自补写新的动机、主题总结或作者说教。
- 把克制情感扩写成长篇煽情。
- 提前揭露、回收或改变既有伏笔。
- 为追求文采而改变用户表达的基本风格与原意。

超出权限的内容只能作为候选建议提出，不能静默写入正文。

## 九、长度与信息密度

- 单场口述整理目标以项目配置为准，默认约1000个中文字符。
- 信息正常或较多时，优先删除重复、无效铺陈和过量描写。
- 信息较少时自然成篇，不为凑字数新增空洞心理、无关景物或未经口述的剧情。
- 信息明显超出单场容量时，优先保留关键事件、人物态度、有效交锋和必要动作。
- 连续性、用户原意和有效推进优先于机械字数。

## 十、整章合并即定稿

全部计划场景已经口述整理后，用户说“整合这一章”或明确同义表达，即同时授权整章合并与正式定稿。

AI执行：

1. 完整读取目标章工作稿，不依赖聊天记忆拼接。
2. 按已确认顺序合并全部场景。
3. 统一人物声音、称谓、视角、时态、场景过渡和章内节奏。
4. 检查核心任务、阅读回报、连续性、规则边界、人物选择和章末钩子。
5. 检查是否混入未经用户确认的重要扩写。
6. 把整章定稿写回工作稿。
7. 保存到 正文/第XXX章 章名.md。
8. 执行下方资料同步矩阵。

以下情况必须暂停：

- 仍有计划场景缺失。
- 场景之间存在无法自行消解的硬冲突。
- 为形成完整章节必须新增重要事件或改变剧情结果。
- 用户明确说“只合并预览”“先看全文，不要定稿”。

称谓、过渡、重复、句序和已确认内容之间的普通衔接问题，由AI直接处理。

## 十一、定稿资料同步矩阵

| 信息类型 | 必须更新 | 条件更新 | 不应更新 |
| --- | --- | --- | --- |
| 正式章节全文 | 正文目录、章节工作稿 | 无 | 远期摘要不复制全文 |
| 下一章所需硬状态 | 正文进度最新衔接卡、对应冷归档 | 连续性台账 | 作者偏好 |
| 明确的新时间、地点、资源、物品、关系或知情变化 | 最新衔接卡、连续性台账 | 项目状态、阶段大纲 | 候选推断区 |
| 正文对章纲的实质改写 | 阶段大纲、项目状态、创作日志 | 人物档案、远期摘要 | 不得只留在正文 |
| 明确的人物履历或长期状态变化 | 人物档案、最新衔接卡 | 项目状态、阶段大纲 | 作者长期偏好 |
| 影响远期的主因果或伏笔坐标变化 | 对应区间摘要 | 核心创作纲领 | 普通修辞不进入 |
| AI对性格、动机、伏笔或未来路线的推断 | 候选推断与待确认事项 | 用户确认后再进权威资料 | 不得直接写人物档案 |
| 仅把章纲写细 | 正文、工作稿、最新衔接卡 | 无 | 不重复扩写项目状态和摘要 |

每章定稿后还必须：

- 更新正文总数、上一章路径、当前工作章和工作状态。
- 把完整衔接卡追加到对应区间冷归档。
- 检查摘要正文覆盖范围是否需要更新。
- 只有发生已确认且已落地的变化时才追加创作日志。

## 十二、默认口令

- “准备第X章”：读取资料并建立导演卡，不写正文。
- “开始第X章第X场”：给出口述提示，等待用户口述。
- “整理这一场”：忠实整理并写入工作稿。
- “整合这一章”：合并、检查、保存正式正文并执行资料同步。
- “只合并预览”：形成非正式整章预览，不进入正文目录。
- “这一章定稿”：将此前明确的预览稿转为正式正文。
